## 10 同日追加：厂家无关的多 key 模型层

用户要求：「模型这一步我不想写死厂家，想要适配多种 api key」。

### 10.1 设计决定

| 决定 | 理由 |
| --- | --- |
| 三种协议适配器（openai / anthropic / gemini），`httpx` 直连，**不引入任何厂家 SDK** | 引 SDK 就等于写死厂家。openai 兼容协议一家就覆盖 DeepSeek / Kimi / 智谱 / 通义兼容模式 / 硅基流动 / OpenRouter / Ollama / vLLM |
| `JXL_MODELS` 配置里只写 `api_key_env`（密钥的环境变量名），不写密钥 | 配置可入库、可发队友，密钥留各自 `.env` |
| 多 profile + 按序降级；缺密钥的 profile 自动跳过 | 配 5 家只有 2 把 key 也能跑；某家限流/欠费自动切下一家 |
| prompt / 解析 / 相对日期规范化放在厂家无关的 `core.py` | 换厂家不动这些，也不动契约与前端 |
| 相对日期由后端确定性换算，模型只给原文 | 可单测、可复现，不伪造事实（规则 7）。换算后仍 `unresolved` + `derived` |
| 密钥一律走请求头；Gemini 用 `x-goog-api-key` 而非 URL query | 避免密钥进日志与异常 |
| 图片 mime 由字节头嗅探，兼容 data URL | 不必为 mime 改已冻结的契约 |
| 「输出不合契约」也触发降级 | 某家返回垃圾 JSON 时换下一家，而不是直接失败 |

### 10.3 过程中发现的两个真实缺陷

**① 设计缺陷（由测试暴露）**：`ModelRouter.complete()` 最初只取文本，模型返回垃圾 JSON 时不会降级到下一个厂家。`test_router_all_invalid_output_keeps_invalid_output_kind` 失败暴露了这点。修法：给 router 加可选 `validate(text, profile_name)` 回调，由 `ModelProvider` 传入 `parse_model_output`，使「输出不合契约」成为可降级的失败。补了 `test_router_falls_back_when_model_output_is_invalid`。

**② 环境缺陷（由端到端验证暴露，92 条单测全绿也没抓到）**：本机 `NO_PROXY=localhost,.localhost,127.0.0.1,127.0.0.0/8,[::1],::1`，httpx 0.28 把 NO_PROXY 条目当 URL 模式解析，`[::1]` 被解析成端口 `:1]` → `InvalidURL`。**这台机器上任何默认 `httpx.Client()` 都会崩**。

实测四种组合确认：默认 trust_env → InvalidURL；MockTransport + 默认 → OK（所以单测绕过了它）；trust_env=False → OK。

修法：模型调用一律 `trust_env=False`，代理改由 `JXL_HTTPS_PROXY` 显式配置。回归测试 `test_ambient_no_proxy_does_not_break_real_client` **必须走真实 client 构造**（transport=None，指向本机拒绝连接端口），MockTransport 版本守不住这条。该测试首版断言 `kind == "transport"` 失败——本机端口 1 是丢包而非拒绝连接，落到 `timeout`；两者都证明 InvalidURL 已消失，断言放宽为二者之一。

### 14.2 但一致性检查抓到一个真问题（已修）

跨样本 datetime 序列化不一致：模型产出 `2026-11-13T18:00:00+08:00`（带秒带时区），我们补年份产出 `2026-05-12T16:00`（无秒无时区）。两者都过契约（`Field.value` 是 Any），但前端做字符串比较/排序/展示会踩坑。

真响应复核：两条 deadline 现为 `2026-11-13T18:00:00+08:00` 与 `2026-05-12T16:00:00+08:00`，schema 仍 PASS。HANDOFF 已补「日期值格式约定」告知前端。
