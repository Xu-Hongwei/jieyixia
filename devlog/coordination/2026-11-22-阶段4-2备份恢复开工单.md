# 阶段4-2 备份恢复开工单

日期：2026-11-22。状态：设计完成，待Qoder实施。本文件细化阶段4总开工单，本批只做4-2；冲突处以本文件明确的实施细节为准，不改变业务契约。

前置：4-0格式/校验/映射和4-1真实导出已通过人工验收。最近核实前端456项测试、check/build通过，开工重新记录现场基线。

## 1 本批交付

用户在数据管理选择真实ZIP，先看校验与恢复预览；确认后创建独立恢复空间，原空间保持不变。恢复后的图片、资料、行动、成果和历史能访问，未结束工作可以核对后继续，刷新后还能找到恢复空间。

**只新增前端恢复能力与必要存储/工作区接线。** 不改契约0.4.0、DB v3、后端、guard或部署。不做覆盖/合并/去重导入、云同步、任意旧备份升级、演示重置或计划页面。

已有`remap.js`、`recovery.js`、`validate.js`、适配器优先复用。现有`unpackArchive`使用unzipSync，注释已将受限解码留给本批；它不能原样作为用户文件导入入口。

## 2 用户流程与界面状态

保留`/data`次级页面与现有导出功能，增加“从备份恢复”。不新增主导航，不重新做整站视觉。

```text
选择备份 → 正在检查 → 预览与命名 → 确认恢复 → 正在写入 → 恢复完成
               ↓错误        ↓取消           ↓失败
            列原因、零写入   零写入       明确回滚/查询已提交结果
```

同页同一时间只执行一个导出/导入作业，防止重复耗用内存。切换空间不是取消导入或改变导入目标。

### 选择与检查

- 单次选一个ZIP；accept属性仅作文件选择提示，实际按字节检查，不只信扩展名/MIME。
- 显示正在检查，可取消；取消后的旧解析结果不能重新出现，选第二个文件时递增作业标识。
- 选文件、解压、校验、预览阶段**不写任何业务记录、不创建空空间、不切换全局workspace**。
- 非法包只显示错误与重新选择入口，不能“忽略错误继续”；合法v0缺引用等批准兼容项显示为说明，明确区分阻断错误。

### 预览

显示文件名、原空间名、导出北京时间、格式/契约版本、各类数量、图片大小、未结束工作数量，以及恢复转换提示：新空间/新ID、原数据不覆盖、未结束工作暂停待确认。

新空间名默认使用已实现defaultRestoreName。允许修改，去掉首尾空白，1–80个字符；不把名字当唯一键，重名可以存在，列表用恢复时间辅助区分。不自动修改原空间名。

预览只展示摘要，不能把原图或完整大草稿全部铺开造成页面卡顿。格式/契约与未知kind处理沿用4-0，不能为了导入当前文件放松规则。

### 确认与完成

“恢复到新空间”是唯一写入按钮。确认后冻结文件、名称、目标空间、操作标识、ID映射与准备数据；双击不另签发一次意图。

提交阶段不能显示“取消成功”而后台继续写入：禁止取消/换文件，并对页面内导航提示等待；另一个标签仍可正常工作。意外关页靠事务原子性与恢复回执解释结果。

成功提供“进入恢复空间 / 留在当前空间”。不自动切换；进入时复用既有离开保护，目标路由为`/today`，不携带旧任务/会话详情ID。失败显示对象与原因，不显示空空间成功页。

## 3 有界ZIP解码：先限制，再交给4-0校验

沿用v1限额：压缩100MiB、总展开300MiB、单JSON25MiB、单图25MiB、总条目5000。阈值保持单一来源，不在解码器再写另一组常量。

### 必须做到

1. 读取File前先查File.size，再检查实际读取的压缩字节；拒绝未知/加密/不支持的格式和压缩方法。
2. 解码过程中逐项计数、按**实际输出块**累计条目与总字节；超限立即停止解码并释放作业。不能仅信声明的uncompressedSize，也不能先unzipSync分配全部输出再检查。
3. 检查条目原始路径：绝对路径、..、反斜杠混淆、重复/冲突路径及不允许的目录条目明确拒绝。保留条目序列供校验，不能先归并进对象导致重复路径被后一个覆盖。
4. 本应用导出的ZIP必须支持；合法ZIP不支持的变体给出明确错误，不猜测。ZIP结构/CRC损坏、缺失文件等失败不能产生可确认预览。
5. 路径、压缩方法和字节限制通过后，按最终entries调用4-0 validateBackup，验证manifest、SHA-256、JSON、记录与关系。所有payload须声明，不能忽略多余文件。

可沿用已锁定fflate的流式/异步接口；解析尽量在可终止Worker或分块异步任务中进行，不能让大文件检查长期阻塞取消按钮。原始压缩包、解压字节及预览结果只保留必要副本，结束/取消释放，不用字符串无限复制图片。

SHA-256是损坏检测，不是来源可信认证。包中内容不执行，不请求外部URL，不上传文件，不调用模型或依赖healthz。

## 4 校验结果与准备数据必须是同一份

现有validateBackup返回ok/errors/notes/manifest/summary，并不返回已解析业务数据。本批需要一个解码/验证入口统一提供受限解码后的entries、已解析sources/docs/assets及校验结果。

可以扩展返回结构或增加协调模块，但不能校验一份内容后，又从未校验的对象/文件重新解析另一份用于提交。禁止通过UI可编辑对象把预览和最终提交数据悄悄分叉。

流程：

```text
File字节及指纹
→ 受限解码
→ 原始归档A/B/C校验
→ 固定准备数据
→ 全量ID映射
→ 未结束会话安全转换
→ 目标记录重校验
→ Source恢复为本地Blob
→ 原子提交
```

原始文件哈希在映射前校验。映射后改变了JSON内容，就不再拿旧payload哈希校验新记录；用目标空间的记录级结构/关系校验。不要修改包内manifest再宣称它仍是原始文件。

Source保持备份asset_path形态完成目标记录级校验，再调用sourceFromBackup还原真实Blob并移除asset_path。落库前核对本地Blob类型/字节与已校验资产一致；不能把需要asset_path的归档校验器直接套在本地Blob形态上误判缺图。

## 5 ID映射与恢复转换

### 映射不变量

- 所有活对象ID新建，所有workspace_id统一目标空间；映射在确认本次意图时固定，重试不重新随机。
- 重写Note/Source、Matter归组、Task.note_ids/截止出处/当前行动、Action.task_id、Focus任务/行动/计划、PlanItem任务/最近结束会话及Field.quote.source_id等**当前契约实际定义的引用路径**。
- 当前0.4.0 TimeNode没有quote字段，不能为了映射新增字段；Field.value中的任意同名字符串/对象不按键名猜成引用。原开工单的宽泛嵌套描述以实际契约定义为准。
- deleted/v0缺失历史标识也生成隔离ID，跨记录一致，不创建不存在的实体；与已有库及本次活对象/历史映射不能碰撞。
- 不整段字符串替换JSON。草稿、原文、标题、快照、URL里出现旧ID仍是原文本。
- 正常历史正文、累计、起止、状态、开始快照、计划顺序/分钟不变。目标空间为普通恢复空间，is_demo=false；来自demo也不变成可重置demo。

缺省record_version按v0，Matter.updated_at按4-0批准的本地字段保留，不能复发之前兼容问题。未知kind阻断，不静默漏掉。

### 未结束工作

复用buildRecoveryPlan：

| 记录 | 恢复结果 |
| --- | --- |
| 已结束v1/v0 | 保留结束成果与版本，仅重映射引用 |
| 未结束v1 | running=false、锚点null，保留累计/正文/首次开始；新建过期占位owner协调记录 |
| 未结束v0 | 仅暂停，不补v1字段；仍可显式legacyEnd |

目标runtime只由应用重建，不导入包中运行锁/台账。目标run.session_id为空；占位owner不等于当前页面owner，不自动续租。进入恢复会话必须能走“恢复编辑→核对用时（保持暂停）→显式继续计时”。

原空间或另一标签正在运行的会话及其runtime完全不动。多个恢复空间可各有暂停会话，全库运行唯一规则继续由原事务保证。

## 6 恢复事务与回执

### 新存储入口

增加专用`commitRestore(preparedOperation)`或等效原语，显式目标workspace，不依赖当前全局配置。不得暂切configureWorkspace、循环调用putDoc/putSource/putWorkspace，或分成“先建目录、再写记录、最后补runtime”三个事务。

一次readwrite事务覆盖**workspaces / sources / docs / focus_runtime**。文件读取、解压、哈希、Blob创建、映射和全量准备校验都在事务外完成；事务内不await非IDB工作。

事务中校验目标非personal/demo，目录未占用，全部准备记录/runtime同属目标空间；检查新活ID及隔离历史ID未与库中已有对象碰撞。以add或等效不覆盖方式写入，出现冲突整体abort。不能为“自动修好碰撞”在事务中换一套新ID后继续写。

本次准备数据来自已通过检查的稳定结果；存储入口仍做关键形状/归属/数量/runtime完整性校验，不能接受跨空间混写的任意数组。

### 同一次操作只恢复一份

本次确认绑定：import_operation_id、目标workspaceId、**原ZIP实际字节SHA-256**、backup_id、目标名与固定ID映射。文件名/大小不能作为唯一文件身份。

工作区目录记录内保存最小本地恢复回执（操作ID、源文件哈希、backup_id、提交时间、数量摘要）。这是目录元数据，不进入业务契约或导出用户运行台账。

同意图重试在同一事务中先查询目标回执：绑定完全一致且已提交，返回原恢复空间，不再次写记录；操作/文件/目标不一致则拒绝。以后用户编辑了该空间，也不能因为当前数量变化把重试变成重新导入并覆盖修改。

用户主动“再恢复一份”才创建新意图和新目标。首版不实现跨刷新自动重试任务日志；刷新后已提交空间可在目录找到，未提交零残留。

### 失败与提交结果

任何store写入失败/QuotaExceeded/ID冲突导致整体回滚，不留空目录或局部runtime；原库逐字段与原图字节不变。

若事务已提交但回调迟到或UI报错，先按本次操作回执查实际结果；确认已提交则显示原空间，不能提示用户盲目重复导入。界面离开不等于事务取消，不把原空间当作导入目标。

提交后核对新空间数量、图片、必要引用及未结束协调完整性。核对错误明确显示“已创建空间，但核对异常”，不假装零写入，也不自动回滚已可能被用户编辑的空间。正常提交结果只应用到本次作业；晚到回调不覆盖随后选择的另一文件预览。

## 7 工作区目录与进入恢复空间

WorkspaceSwitcher当前固定两个tab，必须改为读取store.workspaces目录的选择控件，支持多个恢复空间，桌面与手机不横向挤压。显示完整名称，重名时有恢复时间辅助信息，按ID切换。

增加显式刷新目录能力，恢复成功、页面重新聚焦时可刷新；其它页面看不到新空间时提供刷新入口，不能要求重启浏览器。

ensureWorkspace仅负责默认personal/demo初始化；选择不存在的恢复ID应报不存在，不自动创建同ID“个人空间”空壳。当前空间失效时可说明后回到personal，不静默覆盖数据。

进入恢复空间前统一requestWorkLeave；取消保持原URL/空间/输入，成功后切换并回`/today`。App空间watch退出旧详情的规则保留，不能把原taskId/sessionId带到新空间。

DataPage区分“个人空间 / 演示空间 / 恢复空间”，不能把所有非demo都标个人。恢复成功提示明确目标名；留在原空间时，原空间的导出计数/状态不改成新空间的数据。

## 9 验收矩阵

每项使用独立浏览器Context及虚构数据；操作前保存原库全部store快照和图片字节摘要作为独立oracle，不用导入器自检替代原库不变验证。

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| R01 | 同一已含原ID的浏览器选4-1真实ZIP恢复 | 新空间/新ID，原空间及其它空间逐字段/原图哈希不变 |
| R02 | 全新浏览器Context恢复同文件 | 无原库依赖，图文、任务、行动、历史可用 |
| R03 | 选择、检查、预览、取消、换第二文件、旧检查迟到 | 零写入零目录，旧预览不污染新文件 |
| R04 | 无效ZIP、重复路径、路径混淆、CRC/方法/加密异常 | 在解码/预览阶段拒绝，无静默覆盖条目 |
| R05 | 高压缩比、头部大小伪报、实际JSON/图片/总量刚超限、条目超量 | 按真实输出及时停止，不先全部解压；界面可取消、无卡死 |
| R06 | 限额恰好边界、合法空空间、中文名 | 不误拒合法包，空恢复空间可选择与再导出 |
| R07 | 篡改哈希、缺资产、未知kind/版本、非法记录/活引用 | 列清原因、确认不可用、全库无变动 |
| R08 | 全部活引用和已删除/v0缺失历史ID | 新引用闭合，历史隔离不误连；正文中旧ID字符串不变 |
| R09 | 缺省v0、Matter.updated_at、PlanItem互指 | 兼容分支保留，不复发4-0缺陷，不重排计划 |
| R10 | 运行与暂停v1恢复，已有另一空间运行 | 目标暂停可接管核对，显式继续受全局唯一保护；原运行不变 |
| R11 | v0未结束且缺原引用 | 可看草稿并显式归档，不补快照、不自动计时 |
| R12 | 双击、提交结果迟到、同意图失败重试、两个页面提交同意图 | 恰一个目录和完整数据；同回执返回原结果 |
| R13 | 各store写入失败、额度不足、目标或记录ID冲突 | 四store全回滚，零半恢复、原库不变 |
| R14 | 提交前取消、提交中导航、关闭后重开 | 取消结果准确；已提交空间可找，未提交无残留 |
| R15 | 提交期间换工作区/另一页继续工作 | 导入仍只写固定目标，不改当前运行、锁或其它空间 |
| R16 | 成功后留原空间、进入新空间、重名空间、刷新后选择 | 目录可达，名称与身份清楚，详情ID不跨空间带入 |
| R17 | demo备份恢复 | 新空间为普通恢复空间，不属于可重置demo |
| R18 | 原空间记录删除历史与恢复空间查看 | 原Task/Action被删的成果仍可查找，失效引用不可跳转 |
| R19 | 恢复空间再导出再恢复 | 除新ID/新空间/未结束安全转换外，业务事实与图片字节相同 |
| R20 | 已加载应用断网、桌面与360px手机 | 文件检查/预览/恢复可用，不依赖Docker、后端、模型或网络 |
| R21 | 原4-1正常/非法/超限导出、3B保存/离开/接管回归 | 不破坏已验收能力，check/test/build通过 |

R12包含“事务已提交、UI回调失败”反例；不能只测试事务abort后重试。R13至少在第一个和最后一个store的写入位置分别注入失败，验证目录与runtime确实一起回滚。

原图校验比较真实字节；对象校验用旧→新映射解释引用，不因ID不同就跳过其余字段。已结束成果不得以“恢复转换”为名重写正文或快照。
