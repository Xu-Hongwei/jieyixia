# 页面分工与跳转整理方案

日期：2026-11-19。依据：当前 `frontend/src/app/router.js`、App、三个页面及store的只读检查。本文是下一轮实施建议，尚未改产品代码。

## 当前混乱的具体来源

1. 今天页既是跨周截止日历，又承载事项管理、恢复及任务创建；名称「今天」不能解释浏览其他周的主要用途。
2. 收集箱是所有原始资料的列表，核对页又常驻待核对/失败/已确认的完整队列，两者都承担查找资料的职责。
3. 今天页的「待核对」「分析失败」都链接到 `/notes`，没有携带队列条件。核对页还可能按上次选中项进入，目标没有表达入口意图。
4. 核对页普通建任务和手动建任务成功后均 `router.push('/today')`，不携带新任务ID或截止日期；新任务若在未来周或无截止区，用户看不到刚刚操作的结果。
5. 任务详情能跳到出处便签，但没有显式「返回该任务」与恢复原周、原日、列表位置的约定。
6. 日历周偏移、选日、列表模式与收集箱筛选大多是组件内ref，离开页面重建后容易恢复默认状态；返回路径与浏览器后退的体验需要统一。

上述是源码可确认的职责和导航缺口；本轮没有另做完整导航浏览器测试，不能把每种返回丢状态都当作已实测故障。

## 固定三个主入口

| 主入口 | 唯一主要职责 | 允许的次级操作 | 默认不承担 |
| --- | --- | --- | --- |
| 日程 | 按截止日期查看、定位和处理任务 | 新建任务、任务详情、无截止清单 | 完整资料库、全部便签队列、常驻事项管理 |
| 资料库 | 保存、搜索和管理原始资料及关联便签 | 添加资料、AI整理、筛选、查看已核对内容、进入事项管理 | 一份资料的全部逐字段核对表单 |
| 待核对 | 处理待确认和分析失败的资料 | 对照原文、逐字段确认、重试、建立任务 | 默认展示全部已确认资料作为另一个资料库 |

名称建议将「今天」改为「日程」、「收集箱」改为「资料库」、「便签核对」改为「待核对」。文案可统一决定，职责与导航规则先固定。主入口数量维持三个；任务、便签、原文和事项详情均为有明确上下文的次级工作面，不各自增加一个并列导航项。

原始资料、识别便签、行动任务仍是不同数据对象，不合并数据模型。资料库的一条记录可以展示原始资料与关联便签的处理状态，避免用户在两个列表重复找同一份资料。无日期长期任务保留独立清单，不伪造截止日。

## 主流程与回看流程

```mermaid
flowchart LR
    L[资料库：添加原始资料] --> A[AI整理]
    A -->|成功：指定便签| R[待核对工作台]
    A -->|失败：指定失败记录| R
    R -->|确认截止后建任务| T[创建成功：查看任务或继续核对]
    T -->|查看任务| C[日程：定位日期与任务详情]
    T -->|继续核对| R
    C -->|查看出处| D[关联便签与原文]
    D -->|返回任务| C
```

「仅保存资料」保持在资料库；不强制调用AI或进入核对。没有截止的独立任务从日程新建后定位无截止清单。

## 必须统一的跳转规则

| 触发动作 | 目标与结果 | 必须保留的上下文 |
| --- | --- | --- |
| 点击待核对计数 | 打开待核对队列，定位其中一条；没有时显示空状态 | 来源页面与原筛选/选日 |
| 点击分析失败计数 | 打开失败队列，定位失败记录 | 不能被上次选中的已确认便签覆盖 |
| 资料库点击未核对记录 | 对应便签的核对工作台 | 原资料列表查询、筛选、位置 |
| 资料库查看已确认记录 | 对应便签与原文，可显式继续编辑 | 显示已确认状态，不能把它自动当成新待核对记录 |
| AI整理成功 | 打开返回的准确noteId | 所属工作区、来源；失败或暂存不伪装成功 |
| 保存任务成功 | 默认留在核对页显示成功反馈，提供「查看任务」「核对下一条」 | 新任务ID、该便签ID与当前队列 |
| 点击查看任务 | 日程定位该任务截止周/日期，打开详情 | 若无截止则展开无截止清单；不统一跳回本周 |
| 日程任务查看出处 | 打开准确的关联便签/原文 | 返回入口写明「返回任务」，恢复原周/日/视图 |
| 完成任务、改名、归组 | 在当前工作面原位更新 | 不触发无关整页跳转；详情取最新任务，先修前轮P1 |
| 删除当前对象 | 取消不跳转；成功后关闭已删除详情并定位合理下一项/空状态 | 保留当前筛选；撤销入口可达，不跳进已删除ID |
| 切换个人/演示空间 | 清空上一空间的对象选择与详情，加载新空间合法入口 | 不在新空间继续显示旧任务或旧便签ID |

核对规则保持既有契约：截止可独立确认并建任务；「标记已审阅」不自动确认所有字段。「核对下一条」只负责导航，不暗中改变任何字段状态。

## 低成本路由落实建议

继续使用当前hash router，路径可暂时保留兼容：

- 日程仍可用 `/today?date=2026-11-20&view=week&task=<id>`。date表示选中/定位日期，task表示详情对象；显示名称改「日程」不要求立即迁移路径。
- 资料库 `/collect`，将需要恢复的搜索、筛选和排序写入query或工作区内的页面状态。
- 队列入口 `/notes?bucket=pending`、`/notes?bucket=failed`；明细 `/notes/<id>?bucket=...`。显式队列和对象选择优先于上次打开记录。
- 返回目标使用应用内受控的导航上下文，至少包含路由、筛选、日期/视图、对象；滚动位置按工作区和路由保存，不把大量临时状态全塞进URL。
- 对象不存在或不属于当前工作区时显示明确提示，并回到合法列表/队列，不留下空详情或选中另一个无关对象。
- 刷新、浏览器后退和页面内返回都遵守相同的路由与对象选择规则；URL、选中ID与详情只保留一个明确事实来源。

现有createTask/createTaskManual仅返回ok，可在前端store成功结果中补充新任务ID供精确导航；这是前端内部返回值，不新增后端API或契约字段。

事项管理采用统一的次级面板，从资料库/关联事项入口进入；恢复采用共享面板或明确恢复入口。不要把相同管理操作分别复制到多个页面，也不要用自动跨页跳转替代保存反馈。

## 执行顺序与验收

1. 先修《前端视觉整理复审》的旧任务回写和模态焦点问题。
2. 统一三个页面职责、名称、计数口径；待核对计数用便签数，字段数作为该便签内进度，不能同一个角标混用。
3. 先补精确队列和准确对象跳转，再补建任务后的定位及返回上下文；最后整理事项和恢复入口位置。暂不扩大后端功能。
4. 独立浏览器虚构数据验收：从失败计数进入失败记录；创建未来周任务能定位；出处查看可返回原任务；资料库筛选离开再返回仍在；刷新深链接保持同一对象；删除后无悬空页；切换工作区无对象串用；手机有明确返回入口。

交付证据分开保存：职责/路由图、上述导航流程的实际操作记录、桌面手机截图、现有功能回归结果。仅修改链接地址或页面标题不算全部完成。
