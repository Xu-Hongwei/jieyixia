## 1 根因与最小修复

### F1/P2 外部结束后旧草稿失去核对入口

**根因**：`WorkPage.vue` 主协调 watch 的 `ended_at != null` 分支原先**无条件** `router.replace('/work-records/'+sid)`。其它页面持有者结束会话后，旧页即使还有未保存输入也被直接转历史，本地文本不再可见，重进执行页同样被转走 → 失去核对入口（复审 file=WorkPage.vue start=94 end=97）。

**修复**（`WorkPage.vue`）：
- 新增 `endedReview` ref（:41）。ended 分支改为：**仅当本页已装载该会话（`loadedId===sessionId`）且仍有脏/冲突输入且本地文本≠数据库最终成果**时，置 `endedReview=true` + `draft.frozen=true`（停止写入）并 `return`，不转历史（:99-104）。否则维持原正常转历史。
- 只读核对面板（template `v-else`，:640-665）：Badge「已结束」+ 警示卡「核对：本页未保存输入与已结束的最终成果」，两个 `<pre>` **同屏展示**本地未保存文本（`draft.text`）与数据库最终成果（`session.draft_md`）；三个出口按钮——**复制我的输入**（`copyLocalDraft`，:366，`navigator.clipboard.writeText`，失败/不支持降级为提示手动复制）、**舍弃本地输入，查看历史** / **舍弃本地输入，返回任务**（`discardEndedReview`，:376，先 `draft.forget()` 再 `router.replace`）。
- 离开守卫 ended 分支（:415-423）：`endedReview` 且仍脏 → `askLeave('ended')` 明确确认舍弃才离开（确认后 `draft.forget()`+清 `endedReview`）；无脏输入正常放行转历史。对话框新增 `leaveMode==='ended'` 文案与「舍弃本地输入并离开」按钮标签。
- **不覆盖已结束成果、不复活会话、不把旧草稿自动写入新会话**：核对区全程只读 + frozen，出口只有「复制」与「明确舍弃后离开」，无任何写库路径。
- **本页自己成功结束**仍走 `submitEnd` 原路径（`draft.forget()`→`navigatedAway=true`→返回任务），不触发核对面板；**无脏输入的已结束深链接**仍正常转历史（复审要求的两条不回归项，见 §2 F1-B）。

### F2/P2 Escape 关闭后导航仍悬挂

**根因**：离开确认用 reka-ui `DialogRoot v-model:open="leaveOpen"`。Escape/遮罩关闭只把 `leaveOpen` 置 false，**绕过 `chooseLeave`**，`askLeave` 等待的 Promise 永不结算 → 导航悬挂（复审实测 navigation='pending'，file=WorkPage.vue start=359 end=371）。且原 `askLeave` 每次新建 Promise 会**覆盖仍未结算的 resolver**，重复导航可致悬挂/双弹。

**修复**（`WorkPage.vue` :387-411）：
- 抽出 `settleLeave(v)`：取走并清空 `leaveResolve`/`leavePromise`，**恰好 resolve 一次**。
- `askLeave`：已有等待中的确认（`leaveResolve` 非空）→ **复用同一 Promise**，不覆盖未结算 resolver（重复导航不悬挂、不双弹）。
- `chooseLeave(v)`：先 `leaveOpen=false` 再 `settleLeave(v)`。
- **`watch(leaveOpen, v => { if (!v) settleLeave(false) })`**：任何非确认关闭（Escape/遮罩/v-model）统一结算为**取消**；确认按钮已先 `settleLeave`，watch 再触发时 resolver 已空 → 不双重结算。按钮取消、Escape、遮罩**同一语义**。
- 不保留过期批准令牌：沿用既有 `composables/workLeave.js` 的一次性 `approved` + `resetWorkLeaveApproval`（本轮未改该文件）。
