# 默认时区：北京时间（2026-11-18）

状态：用户追加决定，待 Qoder 实施与验收。本次只更新产品与交接规则，前端代码暂不修改。

## 统一口径

- 产品默认时区为中国标准时间，即北京时间 **UTC+08:00**，标识使用 **Asia/Shanghai**。不单独使用有歧义的 CST 缩写。
- 默认不跟随操作系统/浏览器时区；用户设备设为 UTC 或海外时区，默认业务时间仍按北京时间解释。
- 用户手动选择日期和时刻时，默认按北京时间保存；例如 2026-11-20 17:00 保存为 `2026-11-20T17:00:00+08:00`，无需用户手写偏移。
- 原文明确写其他时区/偏移时保留其实际含义，不直接把偏移替换成 +08:00。展示可换算成北京时间，但保留查看原时间的入口。
- 原文未写时区的 datetime，业务比较与逾期计算默认采用 UTC+08:00，并标明“按默认北京时间”。原始模型字段仍可保留 naive value / tz_known=false，原文和引用不改；不能把产品默认解释伪装成原文明示时区。本轮不为此自行新增响应字段。
- 日期型值仍保存 YYYY-MM-DD，不补 23:59 或强加偏移；从北京时间次日 00:00 起算逾期。
- “今天/明天/一周后”、今日分组和规划日期均使用北京时间的日界线。
- captured_at、analyzed_at 等记录时间可继续存储合法 UTC/其他明确偏移的时间戳；计算时正确换算，不能直接改字符串偏移。收集时间仍不等于消息发布时间，默认时区不能用来自动补造相对日期参照。
- datetime 比较先转为实际时间点：有明确偏移的按原偏移，无偏移的按默认 +08:00 解释。date 与 datetime 精度混合仍不补造时刻或任意选最早。

## 空日期输入默认今天（用户追加）

- 新建/编辑时间时，如果没有已有日期，日期输入框默认读取北京时间的今天；每次进入时动态计算，不写死日期，不取设备所在时区的本地日期。
- 已识别出的有效日期、已有记录及用户编辑过的日期优先回填，不因重新渲染、刷新或跨日被今天覆盖。
- 用户需要其他日期或具体时刻时再编辑；默认今天只填日期，不擅自补当前时刻或 23:59。开启具体时刻后由用户选择时间。
- 默认日期属于可编辑的表单初值，点击保存/确认后才持久化；用户主动采用默认今天时，记录为用户输入/选择。模型没有识别到日期时，原始分析字段仍可保持空，不把今天冒充原文中的日期或模型识别事实。
- 暂不设置截止/主动清空仍然可用；用户明确清空后不立刻又自动填回今天。进入时间编辑并启用日期设置时才应用空值默认。
- 用于重新分析的用户参照日期也可默认今天，但须用户看到并采用后才作为 reference_at 发送；不能在后台给所有请求无条件补今天，也不能把今天标为消息原文日期。
- “消息日期”若由用户采用今天保存，其参照来源应标为用户指定；只有原文明示日期才可标 message_date 来源。

## 验收样例

1. 未注明时区的 `2026-11-20T17:00:00` 按北京时间解释，与显式 +08:00 对应同一业务时刻。
2. `2026-11-20T09:00:00Z` 与北京时间 17:00 对应同一时刻；转换显示不改变截止。
3. 日期截止 `2026-11-20` 在 `2026-11-20T15:59:59Z` 未逾期，在 `2026-11-20T16:00:00Z` 起逾期。
4. 切换测试进程/浏览器系统时区后，上述业务结果不变。
5. 原文、确认来源和原始时区信息保留；日期精度、未知参照留空与非法偏移拒绝规则不回退。
6. 在北京时间跨日边界新建空日期表单，读取正确的今天；已有值和用户修改值不被覆盖，清空/暂不设置不会反复回填。自动填充但尚未保存的日期不改变记录或调用模型。
