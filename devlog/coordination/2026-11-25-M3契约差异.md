# M3 契约差异表（schema 0.5.0 → 0.6.0；propose 协议 1.0 → 1.1）

状态：实施依据。开工单：《2026-11-25-M3进展反馈与最小改排开工单》§6。
原则：先差异后实现；frozen 0.4.0 字节不动；IDB 保持 v4；ZIP 容器保持备份 v2；
旧 0.5.0 备份继续可读（草案缺省 mode=create、取消集为空，不产生新授权）；不批量重写旧库。
命名沿用仓库方式；语义/权限边界/验收以开工单为准，本表只列形状与规则增量。

| 类型 | 增量 | 规则 |

## 2. HTTP（contract/assistant_http.py，协议 1.1）

| 项 | 增量 | 规则 |
| --- | --- | --- |
| 协议版本 | 请求/响应 protocol_version: Literal["1.0","1.1"] | 响应版本=被接受请求版本；1.0 的 new_plan/revise_draft/explain_today 原样可用；replan_task 只走 1.1（1.0 携带即 422） |
| `Intent` | += `replan_task` | check_request_semantics 同步放行并加改排守卫 |
| `ReplanPlanSummary`（新） | plan_item_id、date、planned_minutes>0、action_text、state | 待替换/保留摘要共用形状 |
| `ReplanContext`（新） | task_id、progress: ProgressInput、replacements 1..100、kept≤500 | 机器快照放 context，不伪装 user_answer；用户输入沿用 M2 结构化边界 |
| `AssistantProposeRequest` | + replan_context（可空） | replan_task ⇔ replan_context 必填且协议 1.1；其它 intent 不得携带；目标任务必须在 selected_tasks；replacements/kept ID 去重且互斥；replacements 不得出现在 protected_plans；selected_actions 属于目标任务 |
| `PlanningContext` | 形状不变 | replan 时 days.committed_minutes 由前端填**有效占用**（O 减 R）；protected_plans 只列保留/受保护安排 |
| `PROPOSE_RULES` | output 段「替换不支持」改为「替换只能由用户本地选择产生」；新增 replan 段（仅 replan_task 渲染） | 单一来源不变：禁 task create/update、禁改截止、禁取消指令、禁写完成状态、禁跨任务；只能 link 该任务、复用其未完成行动或提新行动（标将新增）；用户已确认分钟数是权威，模型不得覆盖 |
| 模型输出协议标识 | AssistantModelProposal 自身无协议字段（核对事实） | 无需改模型输出形状；协议适配只在 HTTP 信封层 |
| `PROPOSE_ENDPOINT` | errors/attempt_budget 不变，注明 replan_task 自 1.1 | 重试/额度/超时策略不动 |

后端语义守卫（semantics.py）：replan_task 的 proposal 只允许 op=link 且 target_id==replan_context.task_id；
action reuse 仅限该任务未完成行动；work_items 全部指向该任务；出现 create/update/截止候选改值/跨任务引用 → invalid_output。
replacement_ids 永远不由模型响应产生。

## 3. 前端规则与事务（不改契约形状的实现口径）

- `domains/assistant/replan.js`（新，纯函数）：单一资格函数（同空间/目标任务未完成/date∈窗口且≥提交时北京时间今天/state=planned/task_ref_state=active/actual_minutes===null（0 不算未执行）/focus_session_id===null/全部 FocusSession 无引用）；范围校验；快照比对；预览差异；手工清单→建议结构（本地闭环，不依赖模型）。
- `normalize.js` 改排分支：有效占用 = O 排除已验证 R（一条只减一次）；预算/缓冲公式复用；replacement_ids 记录 R 但 schedule 不再扣减；存在目标任务保留安排时要求 replan_scope 确认（替代该任务的 extra_work 口径，其余任务 extra_work 规则不变）。
- `schedule.js`：replacement_ids 校验上限 100/去重/不得出现在 occupancy；容量消费逻辑不变。
- `application.js`：mode 分支；意图签名覆盖 replan_scope/progress_input/replacement_baseline；取消写集由 baseline 重建；replan 新安排为零 → NO_ADOPTABLE_CHANGES（不提供整批清空）。
- `db.js transformAdoptionAtomic`：plan 返回新增 `docCancels`（受限取消）：事务内重读、同空间同任务、预期内容逐项全等、仅 state→cancelled，其余字段保留；任何不符整体 abort。业务新增仍一律 add()。
- `applications.js`：最终事务重建取消集必须与用户选择+信封完全相等；漂移整体拒绝，不跳过单条。
- 备份：restore 只恢复内容；pending/信封/取消授权不重放；已采用只读；被取消保持取消。

## 4. 兼容与门禁

- 旧 0.5.0 草案/信封/回执：新字段全部有缺省（create/空集），读入即合法，不获得取消能力。
- create 路径（M1/M2）全部原有拒绝规则保持；create 信封夹带取消集 → 拒绝（契约+服务双层）。
- 门禁照旧：契约生成/自检、冻结检查、前后端全量、tsc/构建；新增测试只覆盖开工单 §10 风险。
