# 前端页面分工、导航与视觉审查

日期：2026-11-26  
性质：现有产品只读审查，供下一轮前端整理决策使用。尚未实施下面的方案。

## 1. 审查结论

目前最值得做的是一次“页面职责和操作流程整理”，然后再统一视觉。单纯换颜色、加动画或换组件库，解决不了现在的混乱。

现有功能已经覆盖资料、核对、任务、安排、执行和调整，但界面仍能明显看出逐阶段累加的痕迹：任务总览放在日程底部；资料库与助手各有输入和 AI 入口；助手同时展示输入、核对、编辑、排程与采用机制；详情页缺少稳定的导航归属。

本轮发现两项可复现缺陷，应先修：

1. 任务 → 调整后续安排 → 原任务页 → 返回原列表，会丢失原日程日期与列表视图。
2. 390 像素移动端加载助手演示草案后，页面实际宽度达到 531 像素，产生横向溢出。

其余主要是信息架构和交互设计问题，不等同于数据损坏，也不推翻此前功能验收。

## 3. 具体问题与优先级

优先级含义：A＝先解决的操作阻碍；B＝下一轮页面整理重点；C＝随后统一的视觉与文案。

### F1 · A · 改排往返丢失原位置【已复现缺陷】

复现起点：`/tasks/t-smoke?return=%2Ftoday%3Fdate%3D2026-11-27%26view%3Dlist`。

点击“调整后续安排”，再点“原任务页”，任务地址变成 `/tasks/t-smoke`；再点“返回原列表”，落在 `/today`，原来的 11 月 27 日和列表视图丢失。

原因：`TaskDetailPage.vue:774` 只传 `replanTask`；`ReplanPanel.vue:282` 返回时只调用 `taskPath(task.id)`，没有接续原返回上下文。现有 `workNavigation.js` 已有受限返回路径处理，宜扩展复用。

建议：改排入口携带合法来源与任务上下文，原任务页和完成后的查看任务都延续该链路。直接打开助手的情况采用明确默认位置。继续保留返回路径校验，不能为恢复上下文引入任意跳转。

验收：指定日期、周/列表、任务清单筛选及滚动位置的往返尽可能恢复；至少上述日期与视图复现用例必须通过。刷新、直接打开、切换空间分别验证。

### F2 · A · 助手草案移动端横向溢出【已复现缺陷】

在 390×844 视口打开助手，点击“载入演示：跨天周报”，编辑页 `scrollWidth=531`，超过视口 141 像素；截图显示表单延伸到屏幕右侧。干净场景的日程、任务、助手首页、资料库均为 390 像素宽。

证据：[移动端草案](../../output/ui-review-2026-11-26/clean-and-demo/screenshots/mobile-assistant-demo.png)。

建议排查 `AssistantPage.vue:574` 起的网格子项、`SourceReview.vue` 长资料标题，以及日期输入同行布局的最小宽度传播。当前已确认溢出结果，尚未通过逐项禁用样式定位唯一根因，不能直接认定某一个 CSS 属性就是全部原因。应让内容在容器内收缩、换行，不能只用全局隐藏横向滚动掩盖控件截断。

验收：360/390/430 宽度，普通草案、长标题、改排草案、编辑/预览两种状态均不产生页面级横向滚动；按钮和日期可完整操作。

### F3 · B · 任务缺少独立入口，日程承担太多职责【信息架构】

路由有 `/tasks/:id`，没有任务总览路由。全部任务入口位于日程下方的 `TaskListsPanel`，与待安排、过去未完成共用折叠区。用户想找长期任务或无截止任务，必须先进入日程，再到日历下面找。

建议新增“任务”一级入口，复用现有任务清单能力；日程保留今日/本周安排和截止，底部只保留相关的待安排摘要与“查看全部任务”。这首先是界面归属调整，不需要新增任务数据模型。

验收：任意页面能通过主导航找到全部任务；无截止任务同样可找到；从旧日程入口仍能继续访问，避免旧链接失效。

### F4 · B · 详情页没有明确导航归属【导航设计与实现】

浏览器实测任务详情和工作记录页面，四个主导航均未选中；核对详情 `/notes/:id` 也没有对应的当前导航提示。`App.vue:46` 起用各个独立路由链接的 active-class，而路由没有声明页面所属分区。

建议导航选中状态按“所属分区”计算，而非只依赖路径匹配。任务详情属于任务，核对详情属于资料，工作记录可归日程下的二级入口。返回位置与导航归属是两件事：从日程进入任务时，仍应能明确返回原日程。

建议将“返回原列表”改成真实目的地，如“返回日程”“返回任务列表”；显示简短的上下文路径。长页面保留可访问的导航，桌面侧栏可固定在视口内，移动端选一种稳定导航方式。

### F5 · B · 助手按技术模块铺开，没有清晰的下一步【交互设计】

桌面助手首页高 1265 像素；新建输入、七天容量、改排入口、演示入口、历史草案依次排列。新建和改排是两种用户意图，却需要滚动寻找。

加载演示草案后，编辑、保存修改、排程窗口、重新排程、截止确认、预览和采用分散于左右两栏。桌面演示页高 1709 像素；左侧很长，右侧未排程区域留下大片空白。移动端“编辑/预览”虽已有切换，但操作按钮分散，切换控件位于顶部。

建议助手首页先选择“制定新计划 / 调整已有计划”，历史草案单列次级入口，演示弱化为“试用示例”。工作流整理为“提供资料 → 核对任务与工作量 → 预览日程 → 确认加入”，每步给出一个明确主操作和未完成原因。

这里是流程呈现整理，不是删除安全规则：资料核对、截止确认、替换范围确认必须保留；修改后的失效确认、旧预览禁用、采用前再次核查也必须保留。可以在界面统一调度保存和重排，但失败时不能继续采用，也不能替用户自动确认事实。

验收：首次用户不读工程文档也能知道当前在哪一步、还缺什么、下一步做什么；未保存、未重排、需重核对三种状态的处理方向明确。

### F6 · B · 资料库、待核对与助手的关系不易理解【页面职责】

资料库提供“AI 整理”，助手提供“真实生成：资料 → 理解 → 任务建议”，待核对负责逐字段确认，助手草案中又出现“资料核对”。它们背后的能力不同，但用户很难从入口判断“我这张截图应该放哪”。

建议统一对外解释：资料负责保存与核对原始内容；助手负责根据资料和要求形成可执行计划。资料详情提供“用这些资料制定计划”，进入助手时带上明确选择，不隐式发送整个资料库。

待核对建议成为资料内部的队列/筛选状态，保留角标和直达入口；原 `/notes` 深链接继续兼容。查看已确认资料时应使用“资料详情”一类标题，避免所有情况都显示“待核对”。核对可以嵌在助手流程内完成，复用同一事实状态，减少来回跳页。

### F7 · B · 任务详情没有突出当前行动，低频内容占用主视线【页面布局】

任务详情顶部突出“完成任务”和删除，当前行动、行动列表、跨日安排、说明、关联资料、工作记录同时展开。即使只有 2 个行动、5 条安排，移动端页面也高 2333 像素。高度本身不是错误，但“下一步做什么”与低频编辑、历史信息争夺空间。

建议首屏围绕“任务名称 / 总截止 / 当前进展 / 下一步行动”；未选当前行动时明确引导选择，已选时突出开始工作。行动与近期安排为主要内容，说明、历史记录和资料来源按需展开；删除放到更多菜单，保持确认和撤销能力。

不得改变任务完成与行动完成独立的规则，也不要为了减少点击自动替用户选定或完成行动。

### F8 · C · 文案暴露机制，用户需要理解过多概念【内容设计】

实测草案出现 `Task / Action / PlanItem`、`rpt`、`a1`、`w1` 等内部术语/局部键；日程出现“同一展开区 · 搜索与筛选对当前清单生效”；工作记录解释“不用现名称伪造历史”；多处说明较长且常驻。

建议面向用户统一表达：任务＝要完成的目标；行动＝具体步骤；安排＝某天准备投入的工作。源代码和存储名保持不变。引用对象默认展示名称，技术标识放诊断详情；“新建”明确为“新建任务”，“采用计划”可改为“确认加入日程”。

保留会影响决策的说明，例如替换多少旧安排、哪些安排受保护、哪些工作尚未排入。纯实现说明移入帮助或详情。

### F9 · C · 相同卡片层级过多，重点依赖阅读寻找【视觉设计】

暖白、纸张感、棕橙主色与日期字体已经形成统一方向，建议保留。主要问题是大卡片套小卡片、相似圆角边框和过多 12px 辅助文字；重要任务内容和机制说明在视觉上相近。

建议采用“页面标题 → 核心内容 → 辅助信息”三层：主工作区使用稳定底板，内部列表用分隔线和留白，不再每个字段包一层卡片。正文与任务标题优先 14–16px，12px 留给时间等次要信息；关键截止日期不得为了布局被截断。

颜色按语义使用：棕橙＝当前操作/选中；红＝逾期或阻断；黄＝待处理提醒；绿＝完成。截止必须同时有文字/图标，不能只靠颜色。不要为每类信息增加一个新颜色。

同一工作步骤只突出一个主按钮，其他动作降为次级。助手的演示按钮不应与正式生成争夺主操作。

### F10 · C · 异常与恢复信息的常驻方式增加噪声【反馈设计】

正常空状态下，日程仍展示一张“恢复入口”大卡片；第一轮 fixture 分析失败后，原始 `422 unknown_source` 横幅继续出现在日程、任务等页面。这里确认的是反馈的展示与跨页持续，不是认定真实模型会产生同样错误。

建议成功反馈短暂提示，局部失败放回对应资料/步骤，需持续处理的异常保留可追溯入口和数量；全局存储失败、结果未知等高风险情况仍应持续提示。无恢复项时将入口降为次级工具，有待处理项才提高层级。错误正文给出下一步，技术错误码收进详情。

## 4. 推荐的页面分工

这是下一轮设计建议，尚未变更现有产品。

| 主入口 | 用户来这里解决的问题 | 主要内容 | 次级入口 |
|---|---|---|---|
| 日程 | 今天/这周做什么，什么时候截止 | 上方每日工作、下方每日截止；周/列表切换 | 安排工作、工作记录、待安排摘要 |
| 任务 | 我有哪些目标，分别推进到哪 | 全部任务、状态/事项筛选、任务详情 | 行动、跨日安排、资料、进展历史 |
| 资料 | 截图和文字存在哪，哪些待核对 | 资料列表、待核对/失败队列、原文与字段 | 用所选资料制定计划、事项管理 |
| 助手 | 帮我生成或调整可执行计划 | 新计划/调整计划、分步核对与预览 | 历史草案、示例 |

数据管理放工具区；工作执行页、记录详情页作为上下文页面。事项暂作分组能力，不升级为另一套项目系统。

保留用户已经明确要求的统一日程：**上面每日任务安排，下面每日截止**。计划和截止仍是不同事实，不把它们重新混成一种卡片；同一任务可跨多天出现工作安排，并在截止当天展示截止提醒。

建议贯通三条业务主路径（箭头表示业务步骤，不要求每一步切换页面）：

1. 截图/文字 → 资料保存 → 助手理解与拆解 → 核对 → 日程预览 → 确认加入。
2. 日程安排 → 任务/行动上下文 → 开始工作 → 记录结果 → 返回原日程。
3. 任务进展 → 调整后续安排 → 核对替换范围与新计划 → 确认更新 → 返回原任务或指定日程。

这些路径共享已有资料与对象，不另建一套互不相通的数据。

## 5. 建议实施顺序

### 第一轮：修复导航与移动端阻碍

- 修 F1 上下文丢失、F2 横向溢出。
- 确定详情页所属分区、返回标签与默认返回位置。
- 对复现路径补有意义的导航与尺寸检查。

### 第二轮：整理页面职责与助手流程

- 新增任务总览入口，复用现有任务列表与筛选。
- 资料收拢核对队列，保留旧链接兼容和角标提醒。
- 助手拆清新计划与改排，形成分步流程；移动端每一步有稳定的下一步操作。
- 任务详情突出当前行动，低频编辑与历史按需展开。

### 第三轮：统一视觉与文案

- 统一页面标题、工具栏、按钮主次、卡片/分隔线、字级与间距。
- 日程、任务、资料、助手共用一套状态和错误反馈样式。
- 用同一数据集留存桌面/移动端前后截图；再做比赛演示素材。

每轮完成后交回验收。以上优先复用 Vue、Pinia、现有组件及领域逻辑，不需要先更换框架或 UI 库。页面整理默认不变更后端/API/存储契约；若实现中发现必须改变业务语义，应单独列出并评审，不能混进视觉整理。

## 6. 不应在整理中丢失的约束

- 北京时间、默认读取今天、日期精度和秒保留的既有规则。
- 每日工作安排与总截止分离；计划跨天不会偷偷改截止。
- 本地保存、离线可用、个人/演示/恢复空间隔离。
- 删除确认、撤销、关联引用保护与工作执行保护。
- 草案显式采用、并发检查、旧预览阻断、结果未知的核实流程。
- 改排只替换选中的允许替换项，受保护安排保留并继续占用容量。
- 用户未选择的资料不能因为简化入口而自动发送给模型。

## 7. 下一轮验收建议

不只验收“按钮能点”，还应检查：

- 新用户能在主导航直接找到日程、全部任务、资料、助手。
- 日程 → 任务 → 助手 → 任务 → 日程恢复原日期与视图；从资料来源进入时同样能返回。
- 任务与安排的名称、截止和进展在不同页面一致，没有制造第二套数据。
- 普通草案、改排草案、未保存、需要重核对、已加入、结果未知等状态都有清楚的下一步。
- 360/390/430 移动端与桌面检查长标题、多条行动、无截止、逾期、空状态；关键控件不截断、不横溢。
- 主导航选中、键盘焦点、错误对应字段与触控目标可识别；不能只靠色彩解释状态。
- 原有返回、空间切换、离线、删除、采用与备份相关验证仍通过；本轮截图不替代这些回归。

建议先批准页面分工和三条主路径，再画各页草案。这样美化后的页面会同时更容易理解、操作和展示。

## 8. 补充要求：减少跨页跳转，收敛重复入口

用户明确补充：不只是返回路径需要修好，还要减少完成一个功能所需的跳转，以及同一功能在不同页面反复出现的入口。本节是下一轮设计约束，尚未实施。

### 8.1 一个主要入口，少量带上下文的快捷操作

每项功能有一个明确的归属。只有用户在当前位置确实需要操作当前对象时，才保留上下文快捷操作；不在每页放同一组“新建、分析、规划、调整”按钮。

| 功能 | 主要入口 | 有理由保留的快捷操作 | 收敛方式 |
|---|---|---|---|
| 手动新建任务 | 任务页“新建任务” | 日程安排时确实没有对应任务，可就地新建并带回 | 日程取消与“安排工作”并列的常驻“新建任务”按钮；不再跳去另一页创建后手动找回 |
| 创建/编辑每日安排 | 日程日期区域、安排卡片 | 任务详情中对当前任务安排工作 | 共用同一编辑面板；日程顶部与每天格子之间保留适合当前视图的一套入口，避免同屏重复铺开 |
| 上传/保存资料 | 资料页 | 助手当前计划内添加资料 | 复用同一保存能力；助手内上传后继续当前流程，不强制跳去资料库 |
| 核对资料 | 资料页待核对队列 | 助手中查看并核对本轮引用的资料 | 在详情面板或当前步骤完成；移除独立一级“待核对”导航，角标可直达资料的待核对筛选 |
| 智能制定计划 | 助手 | 资料选中后“用所选资料制定计划” | 保留一次有明确目的的交接，自动带入所选资料；避免资料页同时提供两套含义相近的规划操作 |
| 调整已有计划 | 任务详情“调整后续安排” | 助手选择“调整计划”并选定任务 | 共用同一调整流程；有任务上下文时直接带入，不要求再次选择；不再在每张安排卡片都加全任务改排按钮 |
| 开始工作 | 当前行动或安排的操作区 | 日程快速详情中的当前安排 | 直接带入任务/行动/安排上下文进入执行，不强制先绕到完整任务详情 |
| 工作记录 | 日程下的二级“工作记录” | 任务详情中的相关记录 | 只显示当前任务有关的记录及必要的查看全部入口；不增加一级导航 |

表中描述的是目标方案，具体入口显隐应在原型确认后实施，不能误当成已完成修改。

### 8.2 常见操作就地完成

- 日程点击安排：先打开轻量详情面板，在这里改日期、时长、备注或开始工作；需要管理整个任务时再“打开完整任务”。不要每次查看一张卡片都离开日程。
- 任务内编辑标题、截止、行动、分组：行内编辑或一个共用面板，保存后仍留在原任务。
- 资料查看与核对：列表旁详情面板；下一条资料在面板内切换，原筛选和滚动位置不动。
- 助手的输入、核对、预览、确认：同一工作区内部切换步骤。完整保留草案、未保存提示与重新核对规则，不在资料页、核对页和助手页之间往返。
- 桌面可使用侧面板；移动端可使用全屏面板并提供明确关闭/返回。只保留一层活动面板，避免抽屉里再打开抽屉。

面板不是越多越好。完整任务、智能规划、专注执行等持续工作仍有独立页面；轻量查看与修改才适合就地处理。详情深链接和刷新恢复继续支持。

### 8.3 三个目标体验示例

**改明天的安排**：日程 → 点安排 → 面板改日期 → 保存，仍在原日程；零次完整页面切换。

**截图生成计划**：助手内上传 → 核对内容 → 预览排表 → 确认加入；这些都是助手内部步骤。完成后默认留在结果页，由用户选择“查看日程”，不自动连续跳转。

**调整一个任务**：任务详情 → 带任务上下文进入调整流程 → 确认更新 → 查看原任务。整个过程不用再找任务、再选资料，也不需要用户自行推理返回顺序。跨页时仍修复 F1 的返回上下文。

### 8.4 新增验收口径

- 每个核心功能能说清“主要在哪操作”，同屏不出现多个同义主入口。
- 同屏若保留多个相似入口，必须分别服务不同对象或状态；不能只因不同开发阶段都加过按钮就全部保留。
- 查看、改名、改截止、改安排等轻量操作不要求离开当前列表；关闭面板后恢复日期、筛选、滚动位置与键盘焦点。
- 用户从有上下文的入口进入后，不需要重复选择已有对象。
- 返回、关闭、保存、取消含义一致；浏览器后退与应用内返回均验证。少跳转不能以丢失深链接、未保存保护和执行保护为代价。
- 对三条主流程分别记录页面切换次数、重复选择次数、同屏重复入口和完成结果；以消除无意义跳转为目标，不以删除所有快捷操作或减少安全确认次数为指标。

实施优先级调整：第一轮除 F1/F2 外，先列出实际入口清单与去留决定；第二轮将“入口收敛和就地操作”与页面职责一起做，第三轮再统一视觉。
