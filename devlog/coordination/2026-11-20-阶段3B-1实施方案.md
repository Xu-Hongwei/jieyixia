## 2 DB v2→v3 迁移

- `DB_VERSION=3`，`onupgradeneeded` 仅 `createObjectStore('focus_runtime', {keyPath:'id'})`；sources/docs/workspaces 不触碰（v1→v2→v3 链式迁移测试守着）。
- `req.onblocked`：reject 可解释错误（`DB_UPGRADE_BLOCKED`，提示关闭其它标签页），不再无限等待；`db.onversionchange`：关闭本连接并清 dbPromise，下次操作重新 open（旧标签让位升级）。
- focus_runtime 是**运行元数据**，不是用户成果：不进备份导出（阶段4 导入后重建协调状态）；clearWorkspace 同时清该空间 runtime 记录（demo 重置不留运行锁）。

## 3 focus_runtime 记录类型（不入契约 schema）

| id | 形状 | 语义 |
| --- | --- | --- |
| `run:<workspaceId>` | `{id, kind:'running', workspace_id, session_id, updated_at}` | 全局运行位置按空间各一条；**全库 running 唯一**=所有空间 run 记录中至多一条 session_id 非空。开始/继续事务内校验并写入；暂停/结束原子置空。不靠内存 |
| `sess:<sessionId>` | `{id, kind:'session', session_id, workspace_id, owner_id, epoch, lease_expires_at, revision, draft_seq, last_checkpoint_at, recovery: null \| {reason, since, pending_ms}, updated_at}` | 每会话协调记录。owner=标签页实例 id（sessionStorage 持久，刷新换新 owner 走接管）；epoch 单调递增，接管+1；revision 每次提交+1（条件更新用）；draft_seq 草稿序号；recovery 非空=待恢复确认，期间计时操作拒绝 |
| `ops:<workspaceId>` | `{id, kind:'ops', workspace_id, entries: [{request_id, op, session_id, at_ms, result}]}` | 幂等台账：同 requestId 重试返回原结果（含迟到回调后按 requestId 读结果，不重建）。**保留策略**：仅存活重试窗口 `OPS_WINDOW_MS=10分钟`（可注入）；每次事务顺带清理过期条目；超窗旧请求明确拒绝 `STALE_REQUEST`，不无条件重执行。台账只存结果摘要（ok/code/session_id/revision），不存草稿正文 |

类型构造/校验在 runtime.js，先定义类型与测试再接服务。owner/租约/草稿序号**只在此处**，绝不私塞 FocusSession 领域对象。

## 4 协调与状态机设计

### 4.1 共同协调原语（db.js）

`transformFocusAtomic(plan)`：单一读写事务覆盖 `['docs','focus_runtime']`；事务内 getAll 两 store → 按捕获空间过滤 docs、runtime 全量（run 记录需跨空间读）→ plan(latestDocs, runtime, ctx) 返回 `{puts, deletes, runtimePuts, runtimeDeletes, info}` → 提交前世代检查 → 写入。任何抛错 abort 整体回滚。**开始/保存/检查点/暂停/继续/结束/接管/恢复/v0结束/删除保护全部走它**；3A 既有 transformDocsAtomic 保留（S1 修上下文），删除/完成 plan 升级为经 transformFocusAtomic 读会话。

### 4.2 状态机（domains/focus.js 纯函数）

- `beginPlan`：校验任务/行动/空间有效（行动属于任务且未完成、Task 非 done；blocked 需 `confirmBlocked:true` 显式确认）；**事务内**查全量 docs：同空间无未结束会话（v0 未结束→`LEGACY_RECOVERY_REQUIRED`；v1→`ALREADY_ACTIVE` 带已有会话信息，不自动结束/丢成果）、全库无其它 running；冻结 TaskSnapshot/ActionSnapshot（captured_at=wallNow）；record_version=1、两引用 active、plan_item_id=null；todo→doing；写 sess 协调（epoch=1、owner、租约）+ run 位置 + ops 台账。
- `checkpointPlan`：running 且 owner/epoch 有效且无 recovery；**事务内读最新锚点**结算 `delta=wallNow−anchor`，累加一次、锚点移到 wallNow；不动 draft_md；更新 last_checkpoint_at/revision。
- `pausePlan`：结算本段→running=false、anchor=null、释放 run 位置；**保留 owner/租约**（暂停仍独占草稿写入）。
- `resumePlan`：同一暂停会话、关系仍有效（RELATION_INVALID 拒绝）、全库无另一 running；新锚点、running=true；started_at/accumulated 不变。
- `endPlan`：未结束+有效持有者+outcome∈{done,partial,blocked}（blocked 必须 blocker）+最终草稿已提供；结算本段+最终 draft_md+outcome+ended_at 一次提交；done→Action.done=true+清对应 current_action_id（**专用原子路径，不受通用完成保护反阻**）；partial/blocked 不改 Action/Task；任何结束不自动完成 Task/PlanItem；释放 run 位置；sess 记录标记 ended（保留作幂等/只读依据）。结束后正文只读，旧保存拒绝 ALREADY_ENDED。
- `saveDraftPlan`：有效持有者+未结束+`draft_seq` 递增（晚到旧序号拒绝 STALE_REVISION，不覆盖新正文）；只更新该版正文，可合并计时结算（同一 delta 只累加一次）；revision+1。
- 异常检测（结算共用）：`delta<0`（时钟回拨）、`delta>JUMP_THRESHOLD_MS`（默认 5 分钟，明显跳变）、`wallNow−last_checkpoint_at>STALE_GAP_MS`（默认 60 秒，休眠/失联/后台节流）→ 不结算，置 recovery 并返回 `RECOVERY_REQUIRED`（附最后已保存累计/锚点/待核对间隔）。**不用 max(0,delta) 掩盖**。
- `recoverPlan`：用户显式选择 `keep`（保持已保存累计）或 `correct`（修正总累计，非负整数毫秒，`origin:'user'` 显式来源，不伪装系统测得）；建立新锚点、清 recovery；旧时段不二次计入。继续/结束前必须先恢复。
- `takeoverPlan`：租约过期才允许（有效租约下另一页只读/OWNER_CONFLICT）；epoch+1、新 owner、新租约、**进入 recovery**（不自动补计时）；旧 owner 之后一切心跳/保存/暂停/结束因 epoch 失效拒绝。
- `legacyEndPlan`（v0 未结束）：用户确认已保存累计与结束结果后，**只更新 v0 已有字段**（accumulated_ms/outcome/blocker/ended_at/running=false），不补快照/新字段；释放其占用的唯一位置；随后新开创建 v1。旧引用缺失不阻碍查看与结束遗留草稿，但不允许对不存在对象继续运行。

### 4.3 服务层（service.js）

- 每会话 Promise 队列串行（暂停/结束先合并最后草稿；结束后排队的旧保存被 ALREADY_ENDED 拒绝，不复活历史）。
- 操作统一返回 `{ok, code, workspace_id, session_id, request_id, revision, session?, info?}`；错误码：WORKSPACE_CHANGED / ALREADY_ACTIVE / OWNER_CONFLICT / STALE_REVISION / RECOVERY_REQUIRED / ALREADY_ENDED / RELATION_INVALID / SAVE_FAILED / LEGACY_RECOVERY_REQUIRED / STALE_REQUEST / DB_UPGRADE_BLOCKED。
- 同一次点击及重试复用 requestId（台账返回原结果，不重复累计/生成 ID）；用户成功后明确再次开始用新 requestId；**不按文本/内容去重**。
- 检查点调度：运行中每 CHECKPOINT_MS（默认 10s）经队列提交；参数可注入，单测用受控时钟不真实等待；后台节流允许进入恢复确认，不承诺后台定时器精准。
- 写入失败：保留输入与可重试状态；事务已提交但回调迟到→按 requestId 从台账读结果，不重新创建。
- 保存状态按 revision/draft_seq 归属（3B-2 页面用），不用全局 saved 覆盖新输入（沿用 3A R2 教训）。
- 暂停成功前不切空间（服务返回 WORKSPACE_CHANGED 时保留原空间与输入；底层 S1 兜底）。

### 4.4 S1 工作区上下文（先行）

- `configureWorkspace` 递增世代号；每个公共异步入口**调用时**捕获 `{ws, gen}`；过滤/stamp 用捕获 ws；写事务提交前（onsuccess 计划执行处）检查 gen 未变，变了 abort+WORKSPACE_CHANGED 整体回滚。
- 已提交晚到回调：原空间事实成立，结果带固定 `workspace_id`；store 侧只在归属==当前空间时应用，重新进入原空间按 DB 加载。
- 覆盖 putSource/getSource/allSources/putDoc/allDocs/transformDocsAtomic/deleteDoc 与全部新会话操作；allWorkspaces/putWorkspace/getWorkspace 保留全局目录语义，clearWorkspace(id) 用显式 id。
- 验证三窗口：延迟 open 后切空间、排队事务提交前切空间、提交后回调延迟期间切空间；旧读不覆盖新列表、旧写不写新空间、已提交原空间写入不被误报可重复执行。

### 4.5 删除/完成保护与关系补丁（S6）

- 保护谓词（focus.js）：受影响 task/action 集合 × 全量会话，任一 `ended_at==null`（含暂停、含 v0）命中 → 抛明确错误「先处理进行中的专注会话」，事务回滚。覆盖：setActionDone(done=true)、deleteAction、finishTask、deleteTask、cascadeDeleteNotePlan。
- 已结束会话：单删 Action→action_ref_state=deleted（task 引用不动）；删 Task/联删→task_ref_state 与相应 action_ref_state=deleted；正文/累计/快照保留。补丁进 info.runtimePatches。
- 撤销：lastDeleted 携带最小关系补丁（被断引用 id+原状态、被清 current_action_id 原值）；undoDeletePlan 恢复对象后逐条核对——引用对象恢复后仍不存在则保持 deleted；会话在删除后被改过（revision/ended 变化）则拒绝覆盖该补丁；不整体覆盖历史。
- PlanItem：沿 3B-0 §5 已定策略（planned 条目随删除事务移除并计入撤销补丁，历史条目置 deleted）；本批不开发计划 UI、不重算计划，plan_item_id 关联保留。
- Task 改名/说明/截止/归组不重写快照（快照只在 begin 冻结）。
