# 「截下来」下一阶段 MVP 功能计划

## 一、当前 MVP 基线

已经具备：

- 截图/文字收集。
- AI 识别草稿和失败降级。
- 字段级核对、编辑、确认和原文引用。
- 从已确认便签创建任务。
- IndexedDB 本地持久化、刷新恢复、重分析合并。
- 后端契约 0.3.0、北京时间规则、图片校验、模型预算和基础防护。

当前第一条闭环是：

```text
收集资料 → AI 整理 → 人工核对 → 确认事实 → 创建任务
```

## 二、MVP 还缺什么

### P0：必须补齐

1. **F04 收集箱完善**
   - 关键词搜索。
   - 按内容类型、核对状态、日期筛选。
   - 待核对、失败、已确认分组。
   - 删除便签前提示受影响任务。
   - 删除普通便签时解除任务关联，不留下悬空引用。

2. **F05 事项归组 UI**
   - 创建事项。
   - 将便签和任务手动归入事项。
   - 在事项页查看相关资料、任务和截止时间。
   - 删除事项时保留任务，只解除关联。

3. **F08 今天首页**
   - 按北京时间显示今天日期。
   - 展示今天到期、逾期、待核对、失败和可恢复任务。
   - 未确认截止时间不能伪装成已确认事实。
   - 提供“继续核对”“继续专注”“仅保存”的恢复入口。

4. **F10 专注工作区**
   - 从任务或计划条目开始专注。
   - 计时、暂停、恢复、完成。
   - 保存实际用时和当前行动。
   - 刷新或断网后可恢复。
   - 专注完成不自动篡改任务截止时间和确认状态。

5. **F11 基础备份恢复**
   - 导出 JSON/ZIP，包含记录、任务、事项和原图。
   - 写入契约版本、导出时间、工作区 ID 和校验信息。
   - 导入前完整校验，失败不改变当前空间。
   - 默认恢复到新工作区，不覆盖现有数据。

6. **F12 演示数据隔离**
   - 示例数据使用独立 `workspace_id` 和 `is_demo=true`。
   - 页面明确标记“演示数据”。
   - 退出演示空间不污染用户真实数据。
   - 支持一键恢复演示空间初始状态。

7. **F13 轻量日程规划 P0**
   - 批量录入任务：标题、截止日期、预计剩余时长、是否允许拆分。
   - 设置未来 7 天每日可用时长。
   - 使用确定性规则生成按天计划草案，优先安排截止较近的任务。
   - 允许拆分任务，保留每日 15% 缓冲。
   - 显示每日已安排、可用时长、空余和无法安排的缺口 `gap_total`。
   - 用户可以编辑、移到其他日期并确认计划。
   - 计划条目可进入专注工作区。
   - 规划必须离线可用，不依赖模型接口。

### 交付侧 P0

- 前端负责人实际签收并走一遍黄金路径。
- 生成 3 张与 fixture 原文完全一致的通知截图。
- 通过 Qoder Sites 发布可访问地址。
- 准备比赛要求的作品链接、作品介绍、使用过程截图和视频。
- 记录 Qoder 使用过程和每轮修改证据。
- 真实模型若公开部署，必须通过同源网关注入后端 token；不能把 token 放进浏览器代码。

## 三、推荐实施顺序

### 第 1 阶段：先形成可用的任务工作台

顺序：

1. F08 今天首页。
2. F04 搜索、筛选和安全删除。
3. F05 事项归组。
4. F10 专注工作区。

这一阶段完成后，用户可以从一条通知走到任务执行，并且第二天打开仍能继续。

### 第 2 阶段：补数据安全和比赛演示能力

顺序：

1. F11 基础备份恢复。
2. F12 演示空间隔离。
3. Qoder Sites 发布和真实浏览器验收。
4. 统一错误、空状态、断网和刷新恢复体验。

这一阶段解决“现场数据丢失”和“演示数据污染真实数据”两个比赛风险。

### 第 3 阶段：完成规划差异化

顺序：

1. F13 批量任务录入。
2. 每日可用时间设置。
3. 确定性按天排程。
4. 预览、人工调整、确认。
5. 与今天首页、任务和专注联动。

先做规则排程，保证离线、可解释、可测试，再考虑 AI 增强。

## 四、暂时不要做

以下功能先冻结，避免 MVP 失控：

- F06 自动检测同一任务的截止时间变更。
- F05 AI 自动归组。
- F09 AI 自动生成行动建议。
- F13 自然语言批量规划、AI 估时、AI 拆解和逾期自动重排。
- 复杂任务依赖图、效率统计、跨版本合并和冲突解决。
- 新的后端规划接口。

这些能力属于 P1。当前规划、搜索、今天、专注和备份都应优先保持前端本地可用，后端继续只承担识别和健康检查。

## 五、MVP 验收门槛

用户能够：

1. 收集一张通知并在 AI 失败时保留原图。
2. 核对并确认截止时间，再创建任务。
3. 在今天首页找到待处理任务。
4. 将任务加入计划并调整日期。
5. 开始、暂停、恢复一次专注。
6. 刷新页面后继续工作。
7. 导出数据，在新工作区恢复数据。
8. 退出演示空间后看不到演示数据。
9. 断网时继续查看、编辑、规划和专注；只有 AI 识别显示不可用。

达到以上门槛后，再冻结 MVP 做比赛录屏和提交材料。
