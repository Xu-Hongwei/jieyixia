## 2. 备份格式 v1 示例

ZIP 内布局（4-0 用内存归档模型表达，真实打包在 4-1）：

```
manifest.json
data/sources.json      ← Source 备份记录数组
data/docs.json         ← docs 备份记录数组（note/matter/task/action/focus_session/plan_item）
assets/<内部文件ID>.<png|jpg|webp|gif>   ← 原图真实字节
```

文件名：`截下来-<空间名清洗>-<北京YYYYMMDD-HHMMSS>.jxl-backup.zip`，例 `截下来-个人空间-20261122-153000.jxl-backup.zip`。

**manifest.json**（bytes 为示意；manifest 不列自身哈希避免循环；SHA-256 按归档原始字节）：

```json
{
  "format": "jxl-backup",
  "backup_format_version": 1,
  "schema_version": "0.4.0",
  "backup_id": "bk-fictional-0001",
  "exported_at": "2026-11-22T15:30:00+08:00",
  "source_workspace": { "id": "ws-src", "name": "虚构来源空间", "is_demo": false },
  "counts": { "note": 1, "matter": 1, "task": 1, "action": 2, "focus_session": 4, "plan_item": 1 },
  "source_count": 2,
  "image_count": 1,
  "payloads": [
    { "path": "data/sources.json", "bytes": 412, "sha256": "<64hex>" },
    { "path": "data/docs.json", "bytes": 3870, "sha256": "<64hex>" },
    { "path": "assets/src-img.png", "bytes": 70, "sha256": "<64hex>" }
  ]
}
```

**data/sources.json**（image 用 `asset_path` 指向真实字节，**绝不**把 Blob 写成 `{}`、**绝不**写 `blob:` 临时 URL；text 完整保留）：

```json
[
  { "id": "src-img", "workspace_id": "ws-src", "kind": "image", "captured_at": "2026-11-20T09:00:00+08:00", "asset_path": "assets/src-img.png", "name": "通知截图.png", "is_demo": false },
  { "id": "src-txt", "workspace_id": "ws-src", "kind": "text", "captured_at": "2026-11-20T09:05:00+08:00", "text": "请在本周五前提交实验报告，字数不超过2000字。", "is_demo": false }
]
```

**data/docs.json**（保留本地 `kind` 与业务字段；note 的 `warnings/error` 是已保存事实，保留）：

```json
[
  { "id": "note-1", "workspace_id": "ws-src", "kind": "note", "source_id": "src-img", "status": "reviewed", "content_type": "notice", "title": "实验报告提交通知",
    "fields": [ { "key": "deadline", "value": "2026-11-27", "raw": "本周五前", "origin": "model", "status": "confirmed", "derived": false, "quote": { "text": "本周五前提交", "source_id": "src-img" }, "precision": "date", "tz_known": false } ],
    "matter_id": "matter-1", "matter_role": "requirement", "created_at": "2026-11-20T09:10:00+08:00", "updated_at": "2026-11-20T09:20:00+08:00", "reviewed_at": "2026-11-20T09:20:00+08:00", "is_demo": false, "warnings": [] },
  { "id": "task-1", "workspace_id": "ws-src", "kind": "task", "title": "完成实验报告", "matter_id": "matter-1", "note_ids": ["note-1"],
    "deadline": { "value": "2026-11-27", "precision": "date", "source": "note", "from_note_id": "note-1", "confirmed_at": "2026-11-20T09:25:00+08:00" },
    "status": "todo", "current_action_id": "action-1", "created_at": "2026-11-20T09:30:00+08:00", "updated_at": "2026-11-20T09:30:00+08:00", "is_demo": false },
  { "id": "focus-paused", "workspace_id": "ws-src", "kind": "focus_session", "task_id": "task-1", "action_id": "action-2", "plan_item_id": null,
    "started_at": "2026-11-22T09:00:00+08:00", "accumulated_ms": 600000, "running": false, "draft_md": "检查中", "outcome": null, "ended_at": null,
    "record_version": 1, "timer_anchor_at": null, "task_snapshot": { "title": "完成实验报告", "matter_name": "实验报告", "deadline_value": "2026-11-27", "deadline_precision": "date", "captured_at": "2026-11-22T09:00:00+08:00" },
    "action_snapshot": { "text": "检查字数与格式", "minutes": 20, "captured_at": "2026-11-22T09:00:00+08:00" }, "task_ref_state": "active", "action_ref_state": "active", "is_demo": false }
```

限额（v1，按实际字节 enforcement；完整字节流 enforcement 在 4-2 解码器）：ZIP ≤ 100MiB、总解压 ≤ 300MiB、单 JSON ≤ 25MiB、单图 ≤ 25MiB、总条目 ≤ 5000。图片只收 PNG/JPEG/WebP/GIF 栅格（按 magic 识别，拒 SVG/HTML）。路径只允许 `manifest.json` / `data/*.json` / `assets/<ID>.<允许扩展名>`，拒绝对路径/`..`/反斜杠/控制字符/重复。

## 3. 本地字段适配表（4-0 核心交付）

docs 的 `kind` 是**本地持久化元数据**，不在契约域模型内（`additionalProperties:false`）；`workspace_id` 由存储层 stamp，**属契约字段**。校验业务核心前先投影掉本地额外字段，但备份往返**全保留**（不粗暴删非 schema 字段）。

| kind | 契约定义 | 本地额外字段（投影掉再校验，备份保留） |
|---|---|---|
| note | Note | `kind`, `warnings`(分析警告数组), `error`(失败便签错误码) |
| matter | Matter | `kind` |
| task | Task | `kind` |
| action | Action | `kind` |
| focus_session | FocusSession | `kind` |
| plan_item | PlanItem | `kind` |

Source（`kind` 是契约 SourceKind 枚举，**不是**本地元数据）：

| 本地形态 | 备份形态 | 恢复形态 |
|---|---|---|
| image：`{id,kind:'image',captured_at,blob:File/Blob,name}` | 删 `blob`，加 `asset_path:'assets/<id>.<ext>'`；真实字节进 assets | 按 `asset_path` 取字节→`new Blob([bytes],{mime})`；删 `asset_path`；保留 `name` |
| text：`{id,kind:'text',captured_at,text}` | 完整保留 `text`，无 asset | 保留 `text`，无 blob |

- 契约 Source 的 `image_ref` 必填是 **models.py 校验器规则**（schema.json 中 image_ref 可空）；备份以 `asset_path→assets 真实字节` 承接该语义。
- 图片缺本地字节 → 抛 `ASSET_MISSING`；非栅格 → 抛 `ASSET_TYPE_UNSUPPORTED`（**不生成宣称完整的备份**）。
- `asset_path` 是归档文件指针，**豁免 ID 重写**（恢复时新 source.id 与文件名无关）。

## 4. 三层校验（validate.js）

**A 归档/内容完整性**：manifest+必需文件存在且唯一、路径规范、条目/字节限额、声明 vs 实际一致（无未声明载荷、无缺失声明）、按**归档原始字节**核 SHA-256/字节数、JSON 严格 UTF-8 解析、图片按 magic 识别且与扩展名一致、只收 `backup_format_version=1`/`schema_version=0.4.0`。

**B 结构/数据**：对每条记录投影业务核心后 `validateAgainstDef`（**复用权威 schema.json**：类型/枚举/必需/未知字段/if-then），再补 models.py 的 `model_validator` 语义——真实日历/时刻/偏移（`captured_at/started_at/ended_at/timer_anchor_at`、Deadline/TimeNode/snapshot 值）、数值（minutes>0、planned_minutes>0、accumulated_ms≥0）、跨字段（Note reviewed/归组、Field 状态机、Deadline 来源/确认、FocusSession v0/v1 分版本、PlanItem）、**全局 ID 唯一（同 ID 不同对象/类型拒）**、**全部记录属 manifest 单一来源空间**、**计数逐项匹配**、**禁运 owner/租约/epoch/revision/draft_seq/token 等运行时凭据**（递归扫描）。未适配 kind（group/plan_draft/change_proposal/其它）→ **显式列计数并阻断**。

**C 关系闭包**（镜像 generate.py 跨记录不变量）：Note.source_id + 嵌套 fields[].quote.source_id、Matter.note_ids、Note/Task.matter_id、Task.note_ids/deadline.from_note_id/current_action_id（归属=Action.task_id）、Action.task_id、FocusSession.task_id/action_id（归属=同任务）/plan_item_id（同任务）、PlanItem.task_id/focus_session_id（**必须已结束+同任务+反向 plan_item_id 一致**）。活引用必须解析到正确类型/同空间/正确归属；`ref_state=deleted` 历史**不得**解析到包内活对象（假删除拒）；**每来源空间 ≤1 未结束会话**。

所有错误带 `{layer,objectId,path,message}` 一次性列出，**零写入**；严重错误不可一键忽略。v0 旧缺失引用走 **notes 预览说明**（非硬拒），不伪造已删事件。

## 5. ID 映射与引用重写（remap.js）

预生成目标 workspaceId + 全量 ID 映射后再提交（sources/docs 共用 store 按 id 键，只改 workspace_id 会覆盖原空间）。

| 引用路径 | 重写目标 |
|---|---|
| 所有对象 `.id` | 活对象新 ID |
| 所有 `workspace_id` | 目标空间 |
| Note.source_id / fields[].quote.source_id | 新 Source ID |
| Matter.note_ids / Note.matter_id / Task.matter_id / Task.note_ids | 按类型新 ID |
| Task.deadline.from_note_id / current_action_id | 新 Note / Action |
| Action.task_id | 新 Task |
| FocusSession.task_id / action_id / plan_item_id | 活引用→新对象；deleted 历史→独立隔离新标识 |
| PlanItem.task_id / focus_session_id | 新 Task / 已结束 Focus |

- **deleted/缺失历史 ID** → 独立隔离新标识，跨记录一致，**绝不与活 ID 冲突**；不强制造对象。
- **绝不整段 JSON 字符串替换**：只结构化重写定义好的引用字段；草稿/quote 原文/标题/URL 里出现旧 ID 字样**原样保留**（已测）。
- 起始快照/已结束 outcome/时间/accumulated **原值保留**；恢复空间与活记录 `is_demo=false`（manifest 保留来源 demo 标记供预览）。
- **映射后重跑 B+C**（`validateRecords`）通过；字节哈希在 4-2 真正落库前按重序列化重算。

## 6. 未结束会话恢复准备（recovery.js）

- **已结束 v1/v0**：保留历史事实，只在 remap 映射引用，**不重写快照**（本模块不动）。
- **未结束 v1**：`running=false / timer_anchor_at=null / outcome=null / ended_at=null`，保留已存 `accumulated_ms/draft_md/首次 started_at`；**不导入原 focus_runtime**；重建最小协调记录：新 sessionId/目标 ws、**独立恢复占位持有者** `restore-placeholder:<sessionId>`（绝不冒充页面）、**过期租约** `lease_expires_at=nowMs-1`、`epoch=1/revision=1/draft_seq=0`、`recovery=null`、`ended=false`；run 记录 `session_id=null`（**不占全局运行位**）+ ops 台账。
- **未结束 v0**：只 `running=false`，保留旧字段/文本/累计，**不补 v1 锚点/快照/引用状态**；仍走显式 `legacyEndPlan` 归档。
- **不自动计时**：已用 focus 域验证打开恢复空间走 `takeoverPlan`（epoch+1，pending_ms=0）→ `recoverPlan(keep)`（累计不变）→ `resumePlan`（running=true，锚点=当前墙上时间，**离线间隔未计入**），无 OWNER_CONFLICT 死路。
- 多次恢复各自暂停，run 占位均空，不互相占用全局运行位；原空间/其它标签运行会话与锁不受影响。
- runtime+协调记录与业务数据**原子落库在 4-2 恢复事务**（本批只产出记录）。

## 7. v0 / v1 / 计划边界

- **v0（record_version=0）**：沿用 0.3.0，新字段（锚点/快照/引用状态）出现即混版拒；started_at/ended_at 不收紧；缺失引用走预览说明+隔离映射。
- **v1（record_version=1）**：开始即有任务/行动快照、逐引用状态、锚点与运行态一致、ended_at↔outcome 成对、时间真实合法；未结束（含暂停）引用必须 active。
- **plan_item**：只引用 task_id 永不回写 Task；focus_session_id 快捷引用必须指向**已结束**会话且反向关联一致；planned 条目不得指向已删任务。
- **未适配 kind 阻断**：group（加载时已迁移为 matter）、plan_draft/change_proposal（契约有但产品不创建）→ 显式列计数阻断；**兼容适配须复审后才加**（不假设「页面不创建」=「库里没有」）。
- **边界说明（未强制的更强不变量）**：generate.py 对 golden fixture 额外要求「deadline 出处便签的 deadline 字段已确认且值一致」；这是夹具级不变量，非通用数据不变量。备份 C 层只强制 `from_note_id ∈ note_ids` + 解析到同空间 Note，**不强制**该确认/值一致，以免误拒用户合法备份（如手动调整过截止）。如需收紧请复审决定。
