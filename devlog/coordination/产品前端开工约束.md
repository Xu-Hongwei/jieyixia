# 产品前端开工约束

日期：2026-11-18。状态：**建议采用的开工基线，供用户交给 Qoder 与前端负责人执行；前端接收与环境验证待完成。** 本文件没有安装依赖、创建产品工程或修改产品代码。

依据：[产品定案](../../contract/DECISIONS-2026-11-18.md)、[第四次验收](2026-11-18-整改四次验收.md)、[UI 选型建议](2026-11-18-UI选型建议.md)。产品行为及范围以正式决策为准，布局和具体视觉由前端负责人设计。

## 1. 技术栈

| 层 | 开工选择 | 边界 |
| --- | --- | --- |
| 应用 | Vue 3 + Vite，单页应用 | 沿用项目方向，不因技能模板改成 React、Next.js 或 Nuxt |
| 语言 | JavaScript + Vue 单文件组件，Composition API / script setup | 保留既有 JS 协作方式；JSDoc 引用生成契约，开启 checkJs。改 TypeScript 需提出具体收益与迁移范围 |
| 样式 | Tailwind CSS 4 + 统一 CSS 变量/设计令牌 | 颜色、字号、间距与交互状态集中定义，避免页面各设一套 |
| 主组件体系 | shadcn-vue（Reka UI） | 配置 JavaScript 输出；按官方方式核对 components.json、别名、主题和依赖。现有 lab 的手写组件先核对差异，不直接当作完整官方安装 |
| 图标 | lucide-vue-next | 同一套尺寸与线条规则 |
| 路由 | Vue Router | 今天、收集箱/便签、任务、规划、专注等可恢复导航；发布前测试深链接刷新。托管未验证支持 history 回退时使用 hash 模式 |
| 共享状态 | Pinia | 管理工作空间、跨页选择、任务与专注状态；临时输入优先留在组件/composable。Pinia 不是持久化数据库 |
| 持久化 | IndexedDB + 统一 repository/service 入口 | 复用已验收的快照、事务和串行保存原则；读写限制 workspace，禁止页面各自操作数据库 |

Vue Router 和 Pinia 是产品前端拟新增的依赖，不宣称 lab 当前已安装。具体稳定版本按所选 Vue/Vite 及本机 Node 兼容性确定后锁入 lockfile；不直接照搬“latest”，不用全量升级依赖作为开工步骤。

只选一套主组件体系。日期输入、拖拽、编辑器等专项库按实际需要少量增加，先说明解决的需求与维护成本。首版不引入小时级排班日历、完整富文本编辑器、复杂动效框架或微前端。

## 2. 工程边界与目录

已有产品前端仓库/目录时沿用队友约定；如果在本仓库新建，建议用 frontend/，保留 lab/ 作为接口与故障联调台。不要把不断扩大的 lab/App.vue 直接当作全部产品架构。

建议划分：

```text
frontend/src/
  app/                 应用入口、路由、页面布局、主题
  pages/               今天、收集箱、便签、任务、规划、专注页面
  components/ui/       主组件体系部件
  components/domain/   字段核对、节点列表、任务行、资料面板等业务组件
  stores/              Pinia：工作空间与跨页状态
  services/api/        HTTP 请求、错误分类、契约版本处理
  services/storage/    IndexedDB repository、事务、快照、迁移
  domains/             确认、时间规则、任务操作、planner 等纯业务逻辑
  composables/         输入、加载及页面交互逻辑
  styles/              设计令牌及全局样式
```

这只是职责边界，不要求开工第一天建齐所有空目录。页面负责展示与交互，业务模块负责规则，存储入口负责提交；组件不直接调用模型厂家或复制后端提示词。

## 3. 契约与数据必须遵守

1. 接入 contract/schema.json 与 typedefs.d.ts 的 0.3.0 候选基线。生成物只读取，不手改；新增/变更字段先提契约差异，再经源定义生成和验证，不为 UI 自创后端返回格式。
2. HTTP 统一走 services/api；模型密钥不进前端、浏览器存储或打包产物。按错误 code 处理接口降级，本地存储错误与网络错误分开提示。
3. IndexedDB 为持久事实来源。先保存原始资料再调 AI；修改在独立快照上进行，事务完成后才更新界面。失败保留输入和原记录，同一记录变更串行处理。
4. 多条记录的关联更新在同一事务提交。按用户追加决定，删除便签改为先列出关联任务并确认，确认后便签与列明任务同步删除，不再因截止引用直接阻止；解除其他关联、删除、恢复均不能半成功。具体边界见 [时间输入与便签联删](2026-11-18-时间输入与便签联删.md)。
5. 正式与 demo 使用独立 workspace，所有查询和读写均按当前空间限定；不要只靠界面隐藏做隔离。存储键与引用映射一致，逻辑 ID 不因刷新或重试改变。
6. 不清空 lab 或用户历史数据库来迁就新结构。复用存储时定义兼容读取/显式迁移，失败可恢复；产品前端换 origin 后 IndexedDB 不会自动共享，需按正式备份/迁移规则处理。
7. mock 与真实接口实现相同消费接口。固定示例在产品上标明“演示数据”，不冒充实时识别；真实上传仍走真实分析。

## 4. 关键业务与交互约束

- reviewed 只表示整张便签已审阅，不能替代关键字段 confirmed。
- 确认模型推算值保留 origin=model、derived=true 与原文；用户实际改值才标 origin=user。null 不可确认为有效截止。
- time_nodes 是结构化数组；活动开始、结束、旧日期等按语义展示。无可靠参照不补年/换算；活动开始不自动成为任务截止。
- 用户可以手动输入或选择一个节点作为任务截止，必须有明确确认和来源；任务允许没有截止。
- date 精度保留日期，按北京时间次日起判逾期；产品默认 UTC+08:00（Asia/Shanghai），不跟随设备时区。明确偏移的 datetime 按实际时间点比较，无偏移按默认北京时间解释并明示采用默认，保留原文时区未知信息。详见 [默认北京时间规则](2026-11-18-默认北京时间规则.md)。
- 时间输入提供日历与按需开启的时间选择，日期/消息日期/参照日期不要求手写格式；已识别值回填，保留精度与时区，不将内部枚举当作普通用户的必填表单。
- 保存中、保存失败、待确认、空状态、分析失败、离线均有清晰表现和下一步动作。分析成功但落库失败提供仅重试保存入口，不重新请求模型。
- Pinia 与当前页面不是唯一事实源；刷新/重开恢复依赖实际存储，不仅是组件状态看起来正常。
- 页面用中文产品语言表达状态，不把 role、basis、reference_source、schema_version 等内部枚举当作普通用户文案；原始引用能在需要时展开查看。
- 三个主要区域为“今天、收集箱、专注”；第一轮只交付“收集 → 核对 → 建任务 → 刷新恢复”。F13、备份恢复及示例隔离仍是后续既定 P0，新增 AI 增强保持暂停。

## 5. UI 与技能使用

- 开工先交两种有实质差异的布局草案、一套紧凑设计令牌和关键状态说明，选定后实现。真实使用路径优先于静态展示效果。
- 桌面可用资料列表、字段工作区、原图上下文布局；小屏可用抽屉/展开面板，确保主要操作无需横向滚动。
- 控件使用主组件体系的键盘/焦点能力，保留可见焦点；状态不能仅靠颜色区分，动效尊重减少动态效果设置。
- 设计阶段选择一个视觉指导技能，如 UI UX Pro Max；组件实现使用 shadcn-vue 官方技能；实际触发和安装路径在 Qoder 中验证。不同时堆叠多个风格指导技能。
- 每阶段保存指令、方案取舍、真实运行截图和验证结果到 devlog。参赛材料如实区分计划、已实现、已验证与尚未签收。

## 6. 首轮验收门槛

- 构建与 JavaScript 静态检查能实际运行；定义对应脚本，不把空脚本当作通过。
- 在约 360 / 768 / 1440 宽度检查收集、核对与任务主要路径，不要求像素级统一截图。
- 保存截图或文字，展示草稿与原文，编辑一项要求、确认一个时间、创建任务，刷新后资料及状态一致。
- 注入保存失败，输入与原记录保留；恢复后只重试保存；连续确认两个字段不丢修改。
- 模型不可用时能仅保存和使用已有内容；固定示例、真实分析及正式数据边界清楚。
- 为时间、确认、planner 和关联事务编写必要的规则测试；不为每个装饰组件补镜像实现的测试。
- 真实浏览器完成主要路径、键盘操作及故障恢复，保存实际结果。此前 API 完整测试的环境停滞尚未定位，不沿用 Qoder 报告代替独立验证。
- 产品前端负责人实际签收契约；Qoder Sites 部署后的访客访问和深链接刷新另做发布验收。
