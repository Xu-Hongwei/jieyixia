## 1. 改了什么

**契约（单一来源）**
- contract/assistant_models.py：新增 ClarificationTurnRecord / UserAuthoredInput / render_user_authored_text / CLARIFY_* 常量；
  ThreadMessage.user_input 可选字段（role=user 守卫）；登记 ASSISTANT_PERSISTENT_MODELS（自动再导出）。
- contract/assistant_http.py：AssistantProposeRequest.user_input 可选字段 + 一致性 validator
  （render(user_input) 必须等于 user_message：模型读到的 = 被核验的）。
- 提案 models.py 再导入 + 登记；正式/提案 schema.json、typedefs.d.ts 重新生成（129/92 定义）。

**后端**
- semantics.py：请求带 user_input 时用户段 = [original_user_request] + 各 user_answer（trim 非空），
  摘录接地只读结构化字段，不解析文本；格式常量改从契约导入；旧请求保留标记解析 fallback（既有负向用例不放宽）。

**前端**
- clarification.js：renderUserInputText / userInputSegments（契约镜像）；旧解析函数降级为旧归档 fallback。
- requests.js：composeClarificationMessage 先建结构化记录再渲染，返回 { text, userInput }。
- stores/assistant.js：runRound 归档消息与请求携带 user_input（首轮 clarifications=[]）；
  continueClarification/retryGeneration 透传；restoreClarification 优先读 user_input.clarifications（旧归档 fallback）。
- drafts.js：appendMessage 透传 user_input（仅提供时写入，旧消息幂等 digest 不变）。
- application.js：manual 出处接地优先读归档消息 user_input 结构化字段。

**为什么这样能堵住注入**：模型问题无论含什么内容（包括换行 +「答：2026-11-30」）都永远留在
assistant_question 字段；核验只读 original_user_request 与 user_answer，文本解析退出新写入路径。
负对照机器校验：同一注入文本走旧解析会误判为用户段（测试断言 true），结构化路径拒绝（prepared=false / 502）。
