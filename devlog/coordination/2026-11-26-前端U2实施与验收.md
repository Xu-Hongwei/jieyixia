# 前端 U2 实施与验收

日期：2026-11-26（北京时间）  
状态：U2 已实施并通过本地自动化验收，交回人工体验；未进入 U3。  
依据：[前端体验整理实施方案](2026-11-26-前端体验整理实施方案.md)。

## 1. 本轮结果

日程、任务总览、任务详情复用一个安排侧边面板。查看、编辑、改期、确认进度在当前页面完成；桌面保留背景日程，窄屏面板占满可视宽度。日期、筛选和既有深链接继续使用原有路由规则。

- 日程撤掉普通“新建任务”和完整任务筛选区。周视图从每日“＋安排”开始，列表视图另有“安排工作”；底部仅保留待安排、过去未完成和全部任务入口。恢复工具无待处理项时降为小入口。
- 安排中可以“新建任务并继续”。日期、时长和工作说明保留，创建成功后自动选中该任务，继续原表单。任务与安排仍是两次独立保存；创建任务后放弃安排，保留任务，并有明确提示。
- 任务详情默认展示当前行动与最多三项近期未结束安排；全部安排仍可展开。工作记录、说明/完成标准、关联资料改为按需展开。
- 关闭按钮、Escape、遮罩、路由返回共用已有未保存保护；放弃后才关闭，取消则保留输入。同一页面仅查询参数变化时，也清理已放弃的旧面板。
- 任务详情加入工作区切换保护，未保存的说明可以取消切换。已有开始资格检查、取消确认、部分完成、历史只读和存储重试仍走原有服务。
- 删除安排详情的重复规则说明、周表操作解说和编辑器回车机制提示；保留字段、重要影响范围及失败信息。手机安排日期字段加宽，显示完整日期。

浏览器使用隔离 Chromium、虚构数据和真实 IndexedDB；独立 fixture 后端，不调用付费模型。检查了 360/390/430/768/1440 宽度。实际读取存储确认了编辑、改期、新任务关联、取消后保留任务、部分完成、开始会话绑定，以及断网下模拟写入失败后的同请求重试。

保存失败注入的是“明确失败”分支，不能把它记为“提交结果未知”分支的浏览器验证；后者仍由现有单元回归覆盖。手机检查为浏览器视口模拟，未验证实体设备软键盘、Safari 或系统安全区。没有进行线上部署验收。构建仍有约 1095 kB 主包告警，按原计划留到 U5 处理。

验收中保留的早期失败证据不删除：主检查 r1/r2 的返回断言使用了脚本直接更改 hash 的历史记录，r3 改为真实主导航后验证取消返回保留地址与输入；补充检查曾分别误把明确失败预期为待核实、误把返回来源参数预期为执行安排参数，均依据实际既有规则修正断言。最终以表中路径为准。

复核命令（仓库根目录）：

```powershell
npm --prefix frontend run check
npm --prefix frontend test
npm --prefix frontend run build
node output/frontend-u2-2026-11-26/accept.mjs
node output/frontend-u2-2026-11-26/extra.mjs
node output/frontend-u2-2026-11-26/u1-regression.mjs
node output/frontend-u2-2026-11-26/u0-regression.mjs
```

浏览器脚本各自启动独立服务，用完关闭自己的进程。按顺序执行，不占用用户的 8000/8020 服务。再次运行会覆盖脚本当前输出子目录；需要保留本次证据时先更换脚本中的 `RUN` 名称。

## 5. 人工体验与下一阶段

建议体验：日程点击安排 → 编辑或改期 → 保存 → 关闭回到原位置；安排工作 → 新建任务并继续 → 确认原输入保留；任务详情查看全部安排与折叠内容。未保存时关闭或返回，应先确认。

下一阶段 U3：将资料列表与待核对整理为连续的列表/详情操作，收拢重复入口，保留旧核对链接、出处、失败重试、联删/撤销及明确选择资料后交给助手的边界。
