## 2. 设计定案

### 2.1 选择“稳定页面＋就地面板”

两种结构的取舍：

| 方案 | 结构 | 取舍 |
|---|---|---|
| A，采用 | 四个稳定主页面；轻量查看/编辑用行内区域或侧面板 | 能复用现有路由、组件、深链接，改动范围较小，桌面和手机职责一致 |
| B，暂不采用 | 一个工作台里常驻资料、任务、计划多栏 | 桌面可减少导航，但窄屏退化复杂，容易同时展示过多内容，需要更大范围重做 |

视觉方向：暖白纸面、深色清晰文字、棕橙强调操作，安静、紧凑、内容优先。保留日期字体特征；不添加产品介绍大横幅，不另做展示型首页。

内容层级：页面标题与一个主操作 → 工作列表/日程 → 当前对象的上下文；辅助机制与历史信息按需展开。

交互方向：面板开合、选中行反馈、步骤切换采用短而一致的过渡；尊重减少动态效果设置，不引入新的动效框架。

### 2.2 四个主入口

| 页面 | 回答的问题 | 主操作 | 次级内容 |
|---|---|---|---|
| 日程 | 今天和这周做什么、什么时候截止 | 安排工作 | 工作记录、待安排摘要、必要的恢复提示 |
| 任务 | 有哪些目标、每个推进到哪里 | 新建任务 | 行动、跨日安排、说明、来源与历史 |
| 资料 | 截图和文字存在哪里、哪些需要核对 | 添加资料 | 待核对/失败筛选、事项管理 |
| 助手 | 如何根据需求生成或调整计划 | 当前步骤的继续/生成/确认 | 历史草案、示例 |

数据管理保留在工具区。待核对归资料状态筛选，U3 起移除重复的二级核对导航；工作记录归日程二级页面。一级入口的减少不能隐藏失败与待核对数量。

桌面保留左侧导航，长页面仍可访问；手机采用四项底部导航，上方保留当前标题及空间入口。为底栏和固定操作区预留空间，键盘打开、系统安全区、长页面均需检查。

### 2.3 就地操作与完整页面的边界

日程点击安排先展示详情面板，编辑、改期、确认进度通过现有命令完成；管理整个任务才打开任务页。任务标题、截止、分组、行动在当前任务内修改。资料列表打开右侧核对区，手机使用全屏详情面板。

每次只保留一个活动业务面板；从详情转编辑复用同一宿主，不堆叠多个抽屉。删除、替换等确认对话框仍可覆盖当前面板，关闭后正确恢复焦点。

任务详情、助手、专注执行、工作记录详情保留独立路由，支持刷新和直接打开。减少跳转不等于把所有页面塞进弹窗。

## 3. 入口去留清单

| 当前入口/能力 | 处理 |
|---|---|
| 日程工具栏“新建” | 移到任务页作为“新建任务”；安排编辑器内保留“创建任务并继续”，就地完成 |
| 日程工具栏与每日格子的安排入口 | 桌面周视图以日期格入口为主，空白日和列表视图保留清晰创建动作；不在同一上下文重复突出多个同义主按钮 |
| 日程底部全部任务大区 | 迁至任务页；日程留下相关摘要与查看任务入口 |
| 主导航“待核对” | 并入资料内筛选，保留数量提示和旧链接兼容 |
| 资料 AI 整理 | 表达为提取/核对资料事实，不伪装成完整规划；规划由“用所选资料制定计划”交接到助手 |
| 助手上传资料 | 保留，复用资料保存服务，完成上传后留在助手 |
| 任务“调整后续安排” | 保留当前任务快捷入口，自动带入上下文；助手也支持主动选择任务进行调整 |
| 每张安排卡片上的全任务改排 | 不新增；安排卡片负责当前安排操作 |
| 完成后查看任务/查看日程 | 一个结果区域提供目的地，不出现两份重复成功横幅，不自动连续跳页 |
| 日程恢复入口 | 无待处理项时降为工具入口，有异常/撤销可用时显示明确提醒；不删除恢复能力 |

## 4. 路由、面板和状态规则

保留现有 `/today`、`/collect`、`/assistant`、`/tasks/:id`、工作与数据路由，新增 `/tasks` 任务总览。暂不为了文案改名而重命名全部 URL。

- 路由声明页面所属分区，导航依据分区高亮；“返回哪里”由来源上下文决定，不能与分区混为一谈。
- `/notes`、`/notes/:id` 作为兼容入口保留并使用资料分区。实现时优先渲染共用核对面板，不先强制重定向，以免丢失 `bucket/from/return` 等旧参数。
- 旧 `/today?undated=1` 与 `create=1` 仍有明确落点。先保留兼容适配；任务页与新建面板完成后再替换旧内部调用，不能提前删除。
- 新 `/tasks` 的清单类型、搜索、状态、无截止及事项筛选采用受限参数；加入返回路径白名单。对象 ID 仍按当前空间验证。
- 日程既有 `date/view/plan` 继续有效。改排返回保留任务上下文和原日程条件，不无限嵌套 `return`，不接受任意外部地址。
- 资料向助手交接的是明确选择的资料 ID 与来源空间，接收方再次检查当前空间、存活情况和数量限制；不在 URL 放原文、图片或整份草案，也不自动开始模型调用。
- 已保存草案重新打开时从持久内容恢复，再重新计算可用步骤；步骤导航不是已确认、已重排或可采用的凭证。
- 短期视图与滚动状态可按空间存入 sessionStorage；正式任务/草案仍走现有存储入口，不为导航偏好升级备份契约。
- 面板打开可形成可返回的地址；面板内目标/视图切换避免堆积历史。关闭时只清除相关参数，保留原筛选。浏览器前进后退必须与界面关闭一致，不能只靠不受控的 `router.back()`。
- 离开、切换对象、切换空间、关闭面板、浏览器后退都走未保存保护；保存中、待核实不能被新的面板替换。组件重组保留 `PlanEditor.guardLeave` 等已有机制。

## 5. 实施阶段与验收

### U0：基线保护与两个已知缺陷

先保存 frontend 源码、相关配置与锁文件的限定范围副本及哈希清单，不包含密钥、`.env`、用户数据库、node_modules 或构建产物。保留当前工作树，不自动提交或清理 Qoder 的成果。

修复：改排往返丢失日期/视图；助手草案在手机横向溢出。修改前复现，定位真实溢出元素，不用全局 `overflow-x:hidden` 遮住问题。

涉及：`TaskDetailPage.vue`、`AssistantPage.vue`、`ReplanPanel.vue`、`workNavigation.js`，以及定位到的具体布局组件。

验收：指定日期列表 → 任务 → 改排 → 原任务 → 日程恢复日期/视图；360/390/430 的普通与改排草案可完整操作。补必要的导航与布局回归。

### U1：导航和任务入口

新增任务总览；抽出可复用的任务清单主体，将筛选与路由宿主分离，避免直接复制日程耦合的 `TaskListsPanel`。加入导航分区、返回目的地标签和移动导航。

先用日程、任务两页确定标题、工具栏、列表与面板的统一布局，再扩展到其他页面。此阶段先不撤掉尚未被新入口承接的旧能力。

涉及：`App.vue`、`app/router.js`、新增任务页、`TaskListsPanel.vue`、`workNavigation.js`、任务筛选相关模块。

验收：全部任务、无截止任务、待安排、过去未完成都可找到；搜索/筛选/滚动返回恢复；详情导航高亮；旧深链接可用；切换空间不沿用前空间对象。

### U2：日程与任务的就地操作

将既有安排详情/编辑放进统一面板宿主，保留日程背景与选日。新增任务表单从日程页提取为复用内容；安排时缺少任务，可以先创建任务，再回到同一安排表单，保留日期与输入。

“创建任务并继续”是两次已有业务保存：任务保存成功不代表安排已创建。若用户取消安排，保留已创建的任务并明确告知；不自动删除任务，也不假装两步是一个原子事务。

任务详情首屏显示目标、总截止、当前行动和执行入口；近期安排为主要内容，历史、说明和来源按需展开。保留日程上方每日工作、下方每日截止。

涉及：`TodayPage.vue`、`TaskDetailPage.vue`、`PlanDetail.vue`、`PlanEditor.vue`、`WeekView.vue`、新增共用面板宿主与任务创建表单。命名以实际职责为准，不预建空层级。

验收：查看/改期不离开日程；开始工作复用现有资格检查；关闭和取消不丢输入；保存失败保持输入；删除、撤销、部分执行、历史只读等既有规则不变。

### U3：资料和核对合并体验

资料页以列表与详情为核心，待核对、失败、已确认成为筛选状态。抽出核对内容供资料面板和旧 `/notes` 路由共用，移除一级待核对导航。资料选中后可将明确选定的内容带入助手。

涉及：`CollectPage.vue`、`NotesPage.vue`、已有字段/原文组件、资料选择交接与导航。

验收：资料上传保存、下一条核对、带出处建任务、失败重试、联删与撤销均可完成；列表位置保持；旧核对链接可用；未选资料不会被发送；仅保存仍可离线使用。

### U4：助手改为分步工作区

首页提供“制定新计划 / 调整已有计划”，示例与历史降低层级。新计划流程：

1. 提供资料与需求，设置可用时间；七天默认值先显示摘要，需要时展开逐日编辑。
2. 核对资料、任务、工作量与截止；只展示与当前建议有关的问题。
3. 预览每日安排、未排工作与限制；回改会使旧预览和相关确认失效。
4. 明确确认加入，展示一个结果区域；不自动跳离。

改排复用相同框架，但前置展示替换范围、保留安排和进展输入。用户仍明确确认替换；不因“下一步”按钮合并了界面就自动确认事实。

步骤完成条件读既有业务状态，不能只靠 UI 步数。保存 → 重排可以由明确的“保存并预览”顺序调度：任何一步失败停止、保留输入、禁止采用。如果重排又产生待核对问题，直接在当前步骤列出，而不是要求用户在多个页面找按钮。

采用结果未知、旧草案、不支持操作、已采用只读、恢复空间等状态仍有各自落点，不强行进入普通四步流程。资料核对更新和正式采用保持现有语义。

涉及：`AssistantPage.vue`、`PlanInput.vue`、`SourceReview.vue`、`ReplanPanel.vue`；按步骤抽取展示组件及少量交互 composable。复用 `stores/assistant` 与现有服务，不复制 normalize/schedule/adopt 规则。

验收：同一助手页跑通新建和改排；前进、回改、刷新、重新打开草案不会绕过确认；未保存输入阻断、约束保存、并发变化、重复采用及结果核实相关回归通过。

### U5：视觉统一、性能检查与交回

统一暖白底板、字级、间距、列表分隔、按钮主次、状态与错误反馈。正文/主要操作优先 14–16px，12px 只用于辅助信息；主按钮集中在当前步骤，内部 key 和实现术语移出普通操作面。

重要截止有文字/图标与颜色，正常空状态安静；故障、未排工作和高风险状态仍醒目。移动端面板、底栏、软键盘与固定操作区一起检查。视觉阶段不再调整业务定义。

评估路由懒加载以降低入口包体积；使用前后构建与实际加载证据判断，验证离线降级和缓存场景，不作未经测量的速度承诺。

交回：源码改动清单、当前回归结果、桌面/手机前后截图、三条主路径录屏或步骤记录、已知限制与可恢复基线。开发者和工具使用过程如实记录。

## 6. 工程与协作边界

- 沿用 Vue 3、Vite、Pinia、Vue Router、Tailwind 和 Reka UI，不迁移框架、不全量升级依赖。弹层优先使用现有组件能力，缺口再小范围补齐。
- 不改后端/API/数据契约、规划算法、任务/行动/安排的关系、默认北京时间和日期精度规则。
- 不移除显式采用、并发检查、事实新鲜度、旧预览阻断、改排保护、删除确认与撤销。
- 不触碰用户浏览器 IndexedDB、个人资料或真实密钥。浏览器验收使用隔离上下文与虚构数据，默认 fixture/模拟模型；不自动部署或进行付费调用。
- 后续各阶段由当前前端执行方推进；为避免覆盖，应避免另一执行者同时编辑相同前端文件。若工作树出现新修改，先核对归属再继续，不覆盖外部改动。
- 不用 Git reset、clean 或整目录替换处理已有成果。回滚只恢复本轮明确修改的文件，核对是否有后续外部更新。

## 7. 验收节奏与完成标准

每阶段实施后运行相关检查并保存结果，出现回归先解决再进入依赖阶段；方案制定时未修改源码，实际实施状态由各阶段交回记录证明，不以计划内容视为已完成。

前端阶段交回应保持 check、相关测试和 build 通过；涉及领域交互的阶段运行完整前端回归。阶段内不因样式微调反复运行全部测试；集中验收时再执行一轮完整基线及相关真实浏览器流程。后端未改时不为 UI 调整反复跑后端全量。

最终至少覆盖：

| 场景 | 通过条件 |
|---|---|
| 查找任意任务 | 从主导航可直接进入任务总览，不依赖日历位置 |
| 日程查看/改期 | 不离开日程页，关闭面板恢复日期、视图、焦点与滚动 |
| 截图到计划 | 助手内部完成输入、核对、预览、加入，过程中不强制跳去资料/核对页 |
| 任务改排 | 自动带入任务，返回原任务和原日程上下文，不重复选择 |
| 草案变更与并发 | 修改后旧预览不能采用，确认失效规则有效，重复点击不重复写入 |
| 异常与恢复 | 失败保留输入，离线可用，恢复与结果未知入口明确 |
| 旧链接与空间 | 原深链接能打开，空间切换不会加载或提交其他空间对象 |
| 手机与桌面 | 360/390/430/768/1440 宽度关键页面无横溢，操作区不遮挡内容，键盘可操作 |

用页面切换次数、重复选择次数和同屏重复主入口评估体验，另外记录必要的确认次数；不把删除安全确认当成优化成果。

## 8. 补充约束：减少无关说明文字

用户补充要求：减少页面上无关、重复和解释实现机制的文字。此要求贯穿 U1–U5，随页面整理同步完成，不等到最后才统一删文案。U1 已精简任务列表、返回入口与存储提示，其余页面随后续阶段整理。

### 保留什么

- 用户内容：任务、行动、资料、日期、工作量与进展。
- 操作必需信息：字段名称、当前状态、下一步动作、无法继续的具体原因。
- 决策相关信息：删除/替换影响范围、未保存内容、未排工作、模型发送范围、离线与保存失败、结果待核实。

上述信息放在对应字段、步骤或确认操作旁；阻断、数据丢失风险与重要影响范围直接可见，不能只放悬浮提示里。

### 删除或移到次级位置

- 删除描述页面自身布局的文字，如“同一展开区 · 搜索与筛选对当前清单生效”。
- 删除同屏重复的标题解释、成功提示、默认值解释与操作指南。
- 内部对象名、局部 key、错误码、事务/缓存等实现说明移入诊断详情，普通界面使用任务名称和可执行的提示。
- 次要规则放按需展开的帮助；不影响本次操作的后台机制不常驻展示。
- 按钮和字段标签已能说明的内容不再补一句解释；字段标签保持可见，不以 placeholder 代替。
- 默认不添加页面宣传语、欢迎段落、教程横幅；空状态给出一个明确动作即可。

### 文案改写示例

| 原呈现 | 目标呈现 |
|---|---|
| 本地规划助手 · 真实模型理解 + 本地规则排程…… | 删除常驻机制横幅；生成与确认步骤各自显示必要提示 |
| 一次保存为正式 Task / Action / PlanItem；重复点击不会重复写入 | 按钮“确认加入日程”；有结果摘要时显示具体任务与安排数量 |
| 同一展开区 · 搜索与筛选对当前清单生效 | 删除 |
| 七日可用时间（北京时间；起始默认今天，每次生成重新读取） | “可用时间”；日期控件显示当前起始日期，时区在工作区统一标明 |
| 尚未选择当前行动。请在下方行动列表中显式选择下一步，不会自动替你指定 | “选择下一步行动” |
| 原始错误码 + 长段机制解释 | “分析失败，资料已保存”并提供“重试 / 手动整理”；错误码可展开查看 |

示例必须按真实状态使用：保存成功才显示“已保存”；采用结果未知时不能显示成功；时区和默认值影响理解时仍须可见，不为了短而失真。

### 验收标准

- 首屏优先展示任务内容与主要操作，不被说明段落占据。
- 每段常驻说明都能回答“它是否帮助用户在这里作决定或完成操作”；不能回答则删除或移入帮助。
- 同一状态在同屏只提示一次，提醒就近出现；常态、空状态和错误状态分别检查。
- 精简文字后，用户仍能知道对象是什么、下一步做什么、操作会影响什么。
- 不设机械删字比例；不靠删字段名称、缩成歧义词或隐藏风险提示达成精简。
