## 必修 F1 / P1：任务详情持有过期对象，连续操作覆盖已保存状态

位置：`frontend/src/components/domain/WeekView.vue:45`、`:55`、`:263`；相关写入：`frontend/src/stores/app.js:461`、`:536`。

复现（独立浏览器种子任务 t0）：

1. 今天周表点击任务，打开详情。
2. 点击「完成」；IndexedDB 里的状态变为 `done`，但详情仍显示「待办」和「完成」按钮。
3. 不关闭详情，点击「重命名任务」，保存新标题。
4. IndexedDB 中标题已变，但任务状态被写回 `todo`；详情仍显示旧标题。

原理：`selectedTask` 保存被点击时的对象。store 的 `upsertDoc` 替换 `docs` 数组里的对象，详情引用没有随之更新；现有 watch 只判断 ID 是否还存在。TaskRow 收到旧对象，再由 `renameTask` 整体复制、持久化，覆盖已经完成的状态。这不是只影响显示的缓存问题。

修改建议：只保存选中任务 ID，使用 computed 从当前 store 解析任务；删除时清空 ID。写入层按任务 ID 读取最新记录，只更新本次变更字段，避免旧组件对象整份覆盖新状态。无需修改后端或契约。

复验必须覆盖：

- 详情内完成后立即显示已完成，完成按钮消失；重命名后标题立即同步。
- 完成 → 重命名，刷新后仍已完成且保留新标题。
- 归组 → 重命名、重命名 → 完成，彼此不覆盖；详情与周表同步。
- 删除后详情关闭，撤销恢复正确；保存失败时不伪装成功。

证据：`output/playwright/frontend-review-2026-11-19/interaction.json` 的 `finish_in_detail`、`rename_after_finish`；截图 `issue-finish-detail.png`、`issue-rename-detail.png`。

## 必修 F2 / P2：详情浮层缺少完整模态焦点和嵌套关闭规则

位置：`frontend/src/components/domain/WeekView.vue:52`、`:59`、`:232`。

复现：

- 打开详情，聚焦关闭按钮，按 Shift+Tab；焦点进入背景「无截止任务」按钮，`focusInside=false`。设置 `aria-modal=true` 没有实际隔离背景或约束焦点。
- 在详情内打开「删除任务」确认框，按一次 Escape；删除确认和任务详情同时关闭。任务仍存在，没有误删；但本应取消当前确认的操作丢失了父详情上下文。

修改建议：使用已有 reka-ui 的 Dialog 与现有 AlertDialog 统一管理焦点、遮罩和 dismissable layer；键盘只关闭最上层，取消删除返回详情，关闭详情后焦点返回原任务卡。不要用 window 全局 Escape 直接清空父详情。

复验：Tab / Shift+Tab 不进入背景；删除确认 Escape 只关闭确认，父详情仍打开；取消零写入；关闭详情后焦点返回触发卡片；手机仍可使用关闭按钮与遮罩。

证据：`interaction.json` 的 `dialog_focus` 与 `escape_nested_delete`。
