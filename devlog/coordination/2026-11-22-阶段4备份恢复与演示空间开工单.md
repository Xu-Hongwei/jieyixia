# 阶段4 备份恢复与演示空间开工单

日期：2026-11-22。状态：产品与实施设计，待Qoder执行，不是完成报告。

前置：阶段3闭环及3B-3整改通过，最近核实前端356项测试、check/build通过。每批开工重新核实实际基线，不把历史数字当本轮结果。

## 1 交付目标与已定决策

用户能把当前空间的原始资料、便签、任务、行动和工作成果导出为一个文件，在同一或另一浏览器中恢复为独立的新空间；原空间始终不被覆盖。完整演示与个人数据隔离，便于比赛展示。

| 问题 | 本轮决定 |
| --- | --- |
| 备份范围 | 一次一个当前工作区；包含本空间全部已持久保存的业务数据与本地原图/原文 |
| 文件格式 | ZIP，包含manifest、JSON数据及真实图片字节；备份格式版本与业务契约版本分开 |
| 恢复方式 | **只恢复到新工作区**；首版不覆盖、不合并、不去重原空间 |
| ID策略 | 所有活对象新ID，所有关联同步改写；已删除历史标识也隔离重映射 |
| 专注会话 | 已结束原样保留历史事实；未结束恢复为待确认暂停，不复制运行锁、不自动计时 |
| 重试 | 同一次恢复复用目标空间与操作标识，提交结果不明先查原结果，不能再导入一份 |
| 演示 | 显式体验、显式重置；仅影响demo，个人与恢复空间不动 |
| 实施方式 | 四个小批次逐批交回，先做4-0，不一次跨完所有批次 |

本批不新增后端API、不改模型/鉴权/部署、不开发计划页面、统计图或云同步。业务契约保持0.4.0，DB保持v3；备份文件格式不是业务契约升版。必要新增前端ZIP依赖要确认维护与浏览器适配、锁版本、打入本地产物，不依赖在线CDN。

## 2 产品入口与操作流程

### 数据管理

新增次级路由`/data`，桌面侧栏底部、手机工作区区域提供“数据管理”入口，不增加第四个主导航。显示当前工作区名称、是否演示、各类已保存记录数、图片数与图片字节量。

主要操作：`导出当前空间`、`从备份恢复`、`体验示例`；仅当前为demo时显示`重置演示空间`。不提供清空个人空间、删除恢复空间或覆盖导入。

工作区切换器目前只有personal/demo两个固定选项，必须改为从工作区目录读取，并能选择所有恢复空间。保持桌面/手机一致；这是恢复可用性的必需部分，不扩成账户管理。

### 导出

确认当前范围 → 提取一致快照 → 检查可导出性 → 打包 → 校验产物 → 提供下载。

文案：“备份包含当前空间已保存的资料和成果。尚未保存的输入不在其中；恢复时运行中的工作会暂停并等待确认。”离开执行页前仍走既有保存/暂停保护；另一标签仍运行时可导出最近成功保存事实，不强制结束它。

保存成功提示要准确：浏览器已生成文件并触发下载可称“备份已生成，请在下载中确认”；没有文件系统确认能力时，不宣称已写入用户磁盘。失败不更新成功时间。

### 恢复

选文件 → 本地解析与校验 → 只读预览 → 填新空间名 → 明确确认 → 原子提交 → 成功后提供“进入恢复空间 / 留在当前空间”。

预览显示原空间名、导出时间（北京时间展示）、格式/契约版本、记录与图片数量、未结束会话数量、预计字节量，以及允许的旧记录说明。选择文件和预览不写库，也不创建空工作区。

默认空间名为“恢复 · 原空间名 · 北京日期时间”，重名可加后缀；名字不是唯一身份。恢复成功不自动切走当前工作；用户选择进入时，仍先处理当前页的离开保护。

## 3 备份格式 v1

建议结构：

```text
manifest.json
data/sources.json
data/docs.json
assets/<内部文件ID>.<允许的扩展名>
```

文件名如`截下来-空间名-20261122-153000.jxl-backup.zip`，去除不适合文件名的字符。ZIP内路径由应用生成，不直接使用原始文件名；原始显示名放元数据中。

manifest至少包含：固定format标识、backup_format_version=1、schema_version=0.4.0、随机backup_id、带明确偏移的exported_at、原工作区ID/名称/演示标记、各kind数量、Source数量、图片数量、全部载荷文件的path/字节数/SHA-256。

清单列JSON与图片的**实际字节**；manifest自身不列自身哈希，避免循环。按归档中原始字节校验，不能parse后重序列化再假定哈希相同。SHA-256用于发现损坏，不宣传为可信签名或防篡改认证。

sources.json保留原始资料元数据：本地图片用明确asset_path指向assets文件，文本内容保留完整；blob由序列化适配器提取真实字节。不得把Blob变成`{}`，不得把blob:临时URL写入包冒充原图。

docs.json保留本地持久化记录的kind及其业务字段。Action在本地有kind/workspace_id等持久化元数据，不能未经适配就用纯业务Action schema校验后误报，也不能粗暴删除所有“非schema字段”。4-0先明确每种本地记录的格式适配表。

### 包含与排除

| 包含 | 不包含 |
| --- | --- |
| Source原文、本地图片字节、已有来源说明与时间 | API密钥、token、环境配置、后端地址及运行日志 |
| Note字段、确认状态、raw/quote、时间节点、归组 | focus_runtime中的owner、epoch、租约、草稿序号、台账 |
| Matter、Task、Action完整已保存事实 | 页内未提交输入、悬挂请求、当前选中项和滚动位置 |
| FocusSession正文、累计、结果、版本、快照、引用状态 | localStorage整包、失败请求重试缓存、撤销lastDeleted |
| 已存在PlanItem及其会话关联；不生成新计划 | 其它工作区的记录、只因同浏览器存在就顺带打包的数据 |

首版支持的实际docs kind至少为note/matter/task/action/focus_session/plan_item。扫描到plan_draft、change_proposal、遗留group或其它尚无适配的kind时，明确列出数量并阻止静默遗漏；4-0可增加有完整引用映射的兼容适配，经审查后再纳入。不得用“目前页面不创建”假设库里不存在。

备份只包含实际已存内容；不联网下载外链图片。所需本地图片缺失时明确报错，不能生成宣称“完整”的备份。已知v0历史的遗留缺引用与正常数据损坏分开处理，不补造过去事实。

## 4 导出快照与一致性

新增底层`readWorkspaceSnapshot(workspaceId)`或等效方法：在覆盖sources/docs/workspaces的**同一readonly事务**内读取并固定目标空间，不串行调用当前allSources/allDocs来假设它们是同一时点。

事务完成后在内存进行序列化、哈希、压缩；不要在IndexedDB事务里await压缩、哈希或文件读取，避免事务提前结束。

其它标签随后改动，不影响本次固定快照；不强制全站停止写入。开始导出时捕获空间，期间切换空间不能把新空间混进去；结果明确标注实际导出的原空间，不替新空间更新成功状态。

包含未结束会话时，只导出已保存accumulated_ms、draft_md等事实，不把now-anchor间隔临时计算进去。捕获后页面继续工作是新变化，不宣称备份包含捕获后的内容。

空工作区也可生成合法空备份；若图片读取/序列化/空间不足/压缩失败，展示具体错误并允许重新开始，不产生半份可下载“成功文件”。

## 5 恢复前的三层校验

首版只接受backup_format_version=1、schema_version=0.4.0；FocusSession record_version=0/缺省旧记录依其已批准兼容规则处理。这与“支持所有旧备份格式”不同。未来或不支持版本明确拒绝，不自动猜测转换。

### A. 归档与内容完整性

- manifest与必需文件存在且只出现一次，路径唯一、文件名规范；拒绝绝对路径、..、反斜杠混淆、重复路径、加密或不支持的压缩形式。
- manifest声明与实际文件一致，无未声明载荷；实际解压字节数、SHA-256、JSON编码与图片类型/声明相符。
- v1初始限制：ZIP≤100MiB、总解压≤300MiB、单个JSON≤25MiB、单张图片≤25MiB、总条目≤5000；解压流中按实际字节限额，不能仅信ZIP头。过大明确说明拆分/缩减后重试，不截断内容。
- 解析器不执行包内脚本或HTML；图片限制当前支持的PNG/JPEG/WebP/GIF等栅格类型，不以SVG/HTML承载任意内容。无法展示的已有图片需明确适配或报错，不悄悄丢失。

### B. 结构与数据约束

校验本地格式适配后的每种业务记录：必需字段、类型、枚举、合法时间与精度、累计/估时等数值约束、记录版本和未知字段规则；不能只检查kind与id。

包内对象ID唯一；同ID不同kind冲突拒绝。所有记录属于manifest声明的单一源空间。数量与manifest逐项一致。禁止payload夹带owner/token等运行配置或把未知字段当可执行设置恢复。

校验在浏览器离线完成，不能依赖后端、AI或上传文件。可引入本地schema校验器，但须显式处理kind/本地字段/Source Blob适配，不能用一套宽松“任意对象”校验代替契约。

### C. 关系闭合

检查Source→Note、Matter与Note归组、Task.note_ids/截止出处/当前行动、Action.task_id、Focus的活引用及从属关系、PlanItem任务与会话双向关联。包含嵌套Quote.source_id及time_nodes.quote等位置，按定义的引用路径递归遍历，不能只替换顶层字段。

active引用必须解析到正确类型、同空间、正确所属关系；deleted历史标识不强制创建实体，也不得指向同包现存活对象。v0仅按已批准旧数据规则允许遗留缺引用并在预览列说明，不自动伪造成deleted事件。

每个源空间最多一份未结束会话；多个未结束、非法current_action、PlanItem关系等错误明确拒绝，不自动选第一条或静默丢记录。

所有错误在预览前/预览中列出对象与原因，零写入；严重错误不能用一个“忽略继续”按钮跳过。

## 6 ID重建规则

当前sources/docs分别以id为主键，所有工作区共用store；只改workspace_id会覆盖原数据。因此预先生成目标workspaceId及完整ID映射，再提交。

| 引用位置 | 改写规则 |
| --- | --- |
| Source、Note、Matter、Task、Action、Focus、PlanItem.id | 全部生成新ID，源ID仅存在本次内存映射 |
| 所有workspace_id | 统一新目标空间，包括嵌套业务对象 |
| Note.source_id、嵌套Quote.source_id | 改为新Source ID |
| Matter.note_ids、Note.matter_id、Task.matter_id/note_ids | 按对应类型映射，保留归组与资料角色 |
| Task.deadline.from_note_id、current_action_id | 分别映射Note/Action；保留合法精度、确认来源与时间 |
| Action.task_id | 映射Task，不能跨任务接错 |
| Focus.task_id/action_id/plan_item_id | 活引用映射实际对象；已删历史ID按独立历史映射处理 |
| PlanItem.task_id/focus_session_id | 映射Task/已结束Focus，完整保留顺序/状态/计划分钟 |
| 新支持的嵌套计划/提案字段 | 必须先补全路径表与关系校验，再允许该kind导入 |

已删除历史ID生成新的、无实体的隔离标识；同一历史对象在多份记录中的标识保持一致，不得意外与任何活对象ID重合。v0遗留缺引用同样隔离映射，仍不补造被删实体。

不得对整段JSON做字符串替换：草稿正文、引用原文、标题、URL即使恰好包含旧ID也不是引用，不能修改。开始快照、已结束成果、时间、累计等事实保持原值。

完成映射后再次做完整结构与关系校验。目标普通恢复空间及活记录统一is_demo=false；manifest保留来源是否demo供预览，不把恢复空间当成可被“重置演示”清掉的空间。

## 7 未结束专注会话的恢复

已结束v1/v0保持历史正文、开始/结束、累计、结果和原有版本。只对明确的ID引用作映射，不追改快照。

未结束v1恢复为`running=false、timer_anchor_at=null、outcome=null、ended_at=null`，保留已保存累计、正文与首次started_at。它不是“已结束”或“已自动恢复计时”。

不导入原focus_runtime。为目标空间的未结束v1**重新构造**最小协调记录：新sessionId/新workspaceId、独立不可冒充页面的恢复占位owner、已过期租约、初始epoch/revision/draft_seq；无运行占位。初始recovery留空，打开后由现有takeover建立恢复核对。占位owner绝不复用当前页owner。

这样用户打开恢复会话时会进入既有“恢复编辑→核对用时（保持暂停）→显式继续计时”流程；runtime和协调记录随业务数据在恢复事务内原子创建。不能只恢复Focus而漏runtime导致OWNER_CONFLICT死路。

未结束v0只将running置false，保留旧字段与正文/累计，不补v1锚点、快照或引用状态；仍通过显式legacyEnd归档，不能恢复对遗失对象的运行。

恢复多个空间时每次目标均暂停，不占全库运行位；原空间/另一标签正在运行的会话和锁保持不变。数据管理不应为了导入而接管或结束其它空间工作。

## 8 原子提交、重复点击与失败

新增专用恢复原语，**显式传目标空间与准备好的记录**。不能暂时configureWorkspace到新空间，再循环调用putSource/putDoc；不能借用依赖当前空间的transformFocusAtomic假装完成跨目录导入。

一次readwrite事务覆盖workspaces、sources、docs及本次重建的focus_runtime。准备好的文件字节、JSON、ID映射与校验结果均在事务外完成；事务内检查目标空间与ID不存在，用add或等效不覆盖写入，遇冲突整体abort。

一次预览确认生成并保留唯一import_operation_id及目标workspaceId；按选中文件指纹/backup_id绑定。按钮双击、迟到回调与同一次失败重试复用这份意图，不再分配空间ID。

工作区元数据可持有最小恢复操作标识以识别已提交结果，不是新业务契约字段；重试先查询本次目标，若操作与文件绑定一致且已完整提交，返回原空间，不再写第二份。只有用户明确“再恢复一份”才是新意图；首版不在刷新后自动重放导入。

解析/预览可取消，零写入；提交阶段禁用取消与重复确认，等待明确完成/回滚。页面导航不以组件卸载终止事务后就宣称取消；保留操作控制器并报告实际提交的目标空间。

事务失败、额度不足、目标ID冲突或页面异常中断：无空目录、无半份资料、无残留runtime；原空间、演示及其它恢复空间逐项不变。已提交但UI回调失败与“未提交”分开，不能提示用户盲目重试。

提交后读取新空间核实数量/关系并更新目录；校验若发现异常须明确报告，不能悄悄用原空间快照覆盖回去。进入恢复空间前清掉原详情深链接，正常切换、刷新后仍可从切换器找到。

## 9 首次体验与演示重置

没有个人/恢复空间数据且用户未关闭引导时，可显示一次“开始使用 / 体验示例”。已有真实数据不反复弹出；后端不可达不算新用户。数据管理始终有再次体验入口。

示例固定且全部虚构：一张有出处的待核对便签、一份已确认要求和本地图片/原文、一个任务含多条行动、一份待恢复暂停会话、一份已结束成果。尚未实现计划UI，本轮不加入假计划演示。

示例使用新ID写入demo，保证不与个人或恢复空间的全局ID碰撞。示例会话按现有恢复规则构造协调数据，不伪装成用户正在运行。固定日期随示例明确标注为演示日期，不改造成真实用户今天的承诺。

重置演示只针对明确的demo ID，确认列出将清除的示例资料/任务/历史数量。若demo有未结束工作，先引导显式结束并保存，再重新确认重置；不能在另一页工作时静默清锁。

“删除demo现有内容 + 写入新示例”在同一事务完成，失败保留原demo；不要先clearWorkspace成功后再另起事务种子，失败留空。提交时重查未结束会话，避免确认期间另一页开始造成竞态。演示重置不作用于is_demo=false的恢复空间，即便它源自demo备份。
