结论：**暂不通过本轮完整验收。已有 209 项后端测试通过，但独立反例发现两项核心目标未满足，另有时间偏移与配置校验缺口。** 保留已通过部分，不要求回退；修复下列问题后复验。本次未修改产品源码、调用真实模型、操作真实用户数据库或发布。

## 1. 需要修复的问题

### R5-01 / P1：统一总时限仍不能约束单次持续返回的请求

位置：backend/app/model/adapters.py:46–54；backend/app/model/registry.py:144–156。

当前实现只在尝试之间检查 deadline，将剩余时间作为 HTTPX 各阶段 timeout 传入。HTTPX read timeout 约束等待下一块数据的时间，不是整次响应的总时长；连接、写入、读取也可能分别消耗预算。成功返回和解析后没有再检查 deadline。

独立实测：本地 HTTP 假厂家每隔 0.06 秒发送一小段正常 JSON，设置 budget_s=0.3；首次实测 **1.156 秒后仍成功**，留档复跑 **1.140 秒后仍成功**。没有调用任何真实厂家。这不是 MockTransport 人为忽略 timeout 的反例，而是实际本机 HTTP 连接。

影响：持续小块返回可长时间占用请求；README 中“单个厂家调用最长不超过剩余预算”的承诺不成立。

修改要求：对实际网络请求与响应读取落实绝对 deadline，预算耗尽时释放连接并返回现有 503；覆盖成功响应、错误响应和降级路径。只在返回后判超时不能缩短实际等待，只在超时后让后台线程继续跑也不能作为资源已释放的证明。无需新业务接口或消息队列，可以按最小必要范围调整模型 I/O。补真实本地 HTTP 的慢分段、无数据停顿及首选失败/备用成功测试，并设合理时间容差。

参考：[HTTPX 官方超时说明](https://www.python-httpx.org/advanced/timeouts/)，明确区分 connect/read/write/pool timeout。

### R5-02 / P1：图片校验只读文件头，损坏内容仍进入模型

位置：backend/app/validation.py:64–69、133–160；backend/app/providers.py:104–105。

独立构造仅 **24 字节** 的 PNG 签名、IHDR 标记及 1×1 尺寸，缺少完整 IHDR、CRC、IDAT 与 IEND。inspect_image 返回 image/png，进一步走实际 ModelProvider 和计数 MockTransport 后，**模型调用次数为 1，返回成功**。这未满足“损坏图片在调用模型前拒绝”。

另：`data:image/png;base64` 缺少逗号时直接触发 IndexError，不是规范的 ApiFault；真实 API 会进入通用内部错误路径。

修改要求：使用可靠图片解析/解码验证，在字节与像素上限保护下拒绝截断/损坏 PNG、JPEG、WebP；不能只依靠尺寸头。data URL 先验证结构，非法输入统一 422 invalid_request。补三个格式的正常图、截断图、只有文件头、损坏数据块和畸形 data URL，并通过计数假厂家证明非法输入零模型调用。不要为保持“纯 Python”手写不完整的解码器；新增运行依赖需同步声明。

### R5-03 / P2：日历解析没有拒绝非法时区分钟

位置：backend/app/validation.py:48–52；backend/app/model/core.py 的时间值日历校验与节点规范化。

独立实测 `2026-11-18T12:00:00+08:75`：请求时间检查放行，时间节点也保留原字符串。仅调用 fromisoformat 不足以执行既定偏移格式规则。

修改要求：在真实日历检查外显式验证偏移各分量，至少拒绝分钟 >=60，统一请求、模型节点和截止路径的口径。保留合法偏移、毫秒、闰日和跨年；不能通过静默归一化非法偏移来掩盖输入错误。

### R5-04 / P2：部分非法配置仍通过或被静默替换

位置：backend/app/config.py:37–49、73；backend/app/model/registry.py:34–62、91。

独立实测：

- JXL_ANALYZE_BUDGET_S=NaN 被接受，导致 deadline/remaining 的比较失去可靠性。
- JXL_MAX_BODY_BYTES=-1 被接受，会把正常请求判为超限；abc 被静默替换为默认值，没有明确报错。
- profile 的 base_url=123 仍被 load_profiles 接受，后续使用时才会因类型错误失败。

修改要求：浮点数先检查有限性；请求体上限也使用严格正整数校验；base_url/base_url_env 等配置验证类型和非空语义，错误在启动/装载期按现有机制明确报告。补 NaN、Infinity、负数、非数字及错误类型反例。

## 3. 测试停滞的准确归因

本次已清除子进程的 JXL_* 环境配置并明确设为 fixture，受限执行仍在首个 API 用例停滞。50 秒边界后终止；另一次带堆栈的诊断在 25 秒后终止。堆栈停在 socket.socketpair / asyncio ProactorEventLoop 初始化，尚未进入模型调用。

允许本机回环连接后，同一代码与同一隔离设置下的 209 项测试完成。因而：本次独立验收的停滞来自执行环境对本机连接的限制，不能将此前全部停滞一概认定为 ambient JXL_PROVIDER=model。强制 fixture 的隔离修补仍然正确，它解决了另一个真实风险。请在 README/devlog 中分别记录已证明的机制与本次环境事实，不覆盖历史记录。
