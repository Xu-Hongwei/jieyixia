# 阶段3B专注执行计划与规则

日期：2026-11-20。状态：产品与实施设计，未实现。依据：原MVP阶段3、已完成定向整改的阶段3A、Qoder《阶段3B历史保留契约提案》。本文细化并修订提案，不表示其原字段方案已通过或已升版。

## 1 范围与出口

交付一条可恢复的工作流程：任务详情选择行动 → 开始执行 → 查看关联资料并编写草稿 → 暂停/继续 → 结束并记录成果 → 回任务查看历史。

核心价值是成果与上下文能延续。计时配套提供；不新增AI建议、计划生成、统计排行榜、系统通知或富文本文件系统。不新增专注后端API。阶段4备份、阶段5计划UI、阶段6部署继续保持独立批次。

完成条件：真实IndexedDB、刷新、离线、异常关闭、重复点击、多标签和删除撤销下，会话不重复、成果不丢、计时不乱加、任务状态不误改。未保存成功不得宣称结束成功。

## 2 对现有历史契约提案的审查结论

接受方向：历史快照、显式断开活引用、删除与撤销原子处理、先解决数据规则再接会话。

原提案不能原样实施：

| 原提案问题 | 本设计规则 |
| --- | --- |
| 单一refs_detached，理由是删除总为任务级联 | 3A已有单独删除Action；task与action引用需分别标识，仍存在的Task应可访问 |
| 只检查running阻止删除 | 暂停但未结束也有草稿；所有ended_at为空的会话都先处理 |
| running不得有快照，结束才生成 | 新会话开始时立即冻结当时目标，后续改名不追改历史；结束冻结成果与用时 |
| 新字段可选，同时所有旧ended会话强制有快照 | 新旧记录分版本校验；旧记录可读，不补造过去快照 |
| 暂停/继续复用started_at但未明确时间语义 | started_at保留首次开始时间，新增明确的计时锚点，避免把恢复时间当首次开始 |
| PlanItem仅加快照，未声明任务删除后的引用状态 | 计划记录也需显式区分活引用与历史标识；本批只做兼容设计，不开发计划功能 |

建议契约目标版本0.4.0，先提交完整差异、生成物、迁移与兼容测试。新校验会改变有效记录集合，不能笼统宣称「新增可选字段所以完全兼容」。不在本设计轮改models/schema或后端代码。

## 3 页面与交互

### 入口

- 任务详情的当前行动显示「开始执行」；没有当前行动时先选择或填写，不自动取第一条，不生成无action_id会话。
- 当前工作区已有未结束会话，入口变为「继续上次工作」。尝试开始另一行动时选择继续旧会话、结束旧会话后再开始、取消；不能隐藏旧会话再开一份。
- 同一任务多个行动逐段执行；每次已结束后的再次开始生成新会话。

### 执行页

路径建议`/work/:sessionId`，为次级工作面，不增加第四个主导航。

```text
返回任务        当前行动             保存状态
任务名称 · 预计30分钟 · 实际用时
                          [暂停/继续] [结束]

工作内容                       关联资料
普通文本/轻量Markdown           要求便签
自动保存                       原始资料
                               参考内容
```

正文可提供「本次目标 / 工作内容 / 下次继续位置」提示，但不要求用户每次填写长表单。原文只读，工作草稿可编辑，二者不要共享编辑绑定。

手机默认草稿，资料在标签/抽屉中切换；操作区紧凑可达，不以巨大计时器占据首屏。选中文字、输入和资料切换不被动画打断。

有未结束会话时，当前工作区的日程/任务页有紧凑继续条：任务、行动、运行或暂停状态、继续入口；没有会话时隐藏。切换资料再返回仍回同一会话。

### 结束

| 选择 | 必填 | 保存结果 |
| --- | --- | --- |
| 行动完成 | 结果选项 | Focus outcome=done，同时明确完成该Action |
| 部分完成 | 结果选项 | outcome=partial，Action保持原状态 |
| 被阻塞 | 具体卡点 | outcome=blocked，Action保持原状态，卡点保留 |

成果与下一步建议填写，不全部强制必填。结束后回任务详情并显示记录，提供再次执行/返回日程。新会话可以显式复制上次草稿作为起点，不能隐式改旧历史。

## 4 会话与任务状态

会话展示状态从持久化字段派生，不增加多个可互相矛盾的status字段：

| 状态 | 条件 | 可操作 |
| --- | --- | --- |
| 运行 | running=true、ended_at为空 | 保存、暂停、结束 |
| 暂停 | running=false、ended_at为空 | 编辑并保存、继续、结束 |
| 已结束 | ended_at和outcome均存在、running=false | 只读、再次开始新会话 |
| 待恢复确认 | 页面重开或计时持有者失联，无法确认离线时长 | 核对用时后继续/结束，不自动累计离线间隔 |

待恢复确认是恢复流程状态，不等同一个自动结束结果。已结束成果首版只读，避免后续编辑让旧记录与快照相互矛盾。

开始时用户的todo任务转doing；blocked需明确确认恢复，done需重新打开。会话结束不自动完成或阻塞Task，不修改截止或通知字段。行动完成是用户在结束表单的显式选择；完成当前行动时同事务清空current_action_id，不自动选择下一项。

运行或暂停期间直接完成/删除当前Action或Task，应先引导处理本会话，不能让执行页继续绑定已完成/已删对象。修改标题/说明不会重写已冻结快照；执行页目标以会话开始时内容为准，可标示当前对象已修改并允许查看。

关闭结束表单表示继续当前会话；「取消删除」不等于取消会话。不引入模糊的cancelled结果。确需丢弃一份空会话时，只有草稿为空且累计为0才允许单独确认删除；已有成果或时间时通过部分完成结束保留记录。

## 5 计时与异常恢复

### 时间事实

- started_at：首次成功开始时刻，之后不改变。
- accumulated_ms：最近成功提交的有效累计毫秒。
- timer_anchor_at（建议新增，可空）：运行中本段尚未计入accumulated_ms的起点。
- 显示值：运行时`accumulated_ms + max(0, now - timer_anchor_at)`；暂停/结束只用accumulated_ms。
- 暂停/结束/检查点：在同一事务累加本段并更新锚点；暂停与结束锚点置空。继续设置新锚点，不清零累计。

预计时长不是倒计时强制终止；超过预计仍可继续。视觉刷新频率不参与累计事实。

### 检查点

运行中约每10秒保存检查点，草稿保存、暂停、结束时也可合并提交，避免每秒写库。写入串行或带版本校验；旧的定时保存不能覆盖更新的正文、暂停或结束状态。重复暂停/结束幂等，不重复累加。

### 重开与时间变动

刷新/浏览器重启、休眠唤醒或持有者丢失后，不把整个间隔自动记作工作。展示最后保存累计、未确认间隔和最后保存时刻；用户可保留已保存累计或修正总用时，再继续/结束。修正必须是明确用户操作，不能显示为系统精确测得。

正常运行页面可使用单调时钟检测明显的墙钟跳变；负数、异常大跳变进入核对流程，不默默纠正。单调时钟不能跨重启恢复，恢复仍以持久化检查点与用户确认处理。

## 6 自动保存及异步规则

- 输入停止约1秒保存，离开/暂停/结束前再次保存；状态为未保存、正在保存、已保存、失败可重试。
- 保存时捕获工作区、sessionId、草稿修订号。回调只影响同一对象同一版输入，不能清空后续输入或修改新页面保存状态。
- 失败保留输入和重试入口；额度/本地写入失败不能通过「结束」按钮绕过保存。不能只依赖beforeunload完成异步落库。
- 结束操作把最后草稿、累计、outcome、blocker、ended_at及显式Action完成变更一次提交；任何失败都不半结束。
- 运行中离开任务/日程/资料/空间前，提供「保存并暂停后离开 / 留在这里」。只有成功保存暂停后才导航。
- 切工作区必须先解决运行会话；原空间可保留暂停会话，新空间只显示自己的继续入口。

## 7 唯一会话与多标签

每个工作区最多一份未结束会话（含暂停）；同一浏览器数据库全局最多一份运行会话。不同空间可各有一份暂停记录，不允许同时计时。

开始和继续必须在IndexedDB事务内校验最新数据，不能先内存判断后普通put。刷新到同一会话不新建；重复点击/Enter沿用同一请求结果。

运行写入需要标签持有者与递增世代号的协调记录，作为明确的本地运行元数据，不私塞未定义FocusSession业务字段，不随备份恢复运行锁。只有当前有效持有者能提交计时与会话修改；检查、接管和写入在事务内验证。跨标签消息仅负责通知刷新，不能代替持久化互斥。

另一页打开时可只读或跳到已有会话，不能两边编辑。崩溃或失联后接管先进入恢复确认；旧页复活不得继续写。锁到期与跨页接管要有可测试的规则，不能用「按钮禁用」声称解决多标签。

存储辅助函数必须捕获调用时workspace_id，异步提交中不根据切换后的全局变量决定归属；跨空间写入拒绝。当前transformDocsAtomic依赖可变全局工作区，接入会话前需核查并补充这项保护。

## 8 建议的契约差异

以下由Qoder在3B-0提交完整代码差异与兼容测试后审查；本文件不是已修改schema。

### FocusSession

保留现有ID、工作区、task_id/action_id/plan_item_id、started_at、accumulated_ms、running、draft_md、outcome、blocker、ended_at。

新增方向：

| 字段 | 语义 |
| --- | --- |
| record_version | 旧记录默认0，新会话明确1；分别校验，不用新约束拒绝旧合法记录 |
| timer_anchor_at | 明确运行计时边界；旧记录缺失时进入恢复，不推断为可靠累计 |
| task_snapshot | 开始时冻结的任务标题、事项名称、截止值及精度、捕获时刻 |
| action_snapshot | 开始时冻结的行动文本、预计分钟、捕获时刻 |
| task_ref_state | active或deleted，单独表达任务活引用能否使用 |
| action_ref_state | active或deleted，单独表达行动活引用能否使用 |

保留task_id/action_id字符串；状态deleted后这些值只是历史标识，禁止当活链接使用。active必须在同一工作区解析到正确类型/所属关系。删除Action但Task仍在时，只断action引用，Task仍可跳转。新建活记录必须两引用active；暂停/运行记录不能断开。

新版本会话开始就有快照，快照不随后续活对象修改而重写。ended_at与outcome成对存在；ended后running=false且锚点为空。快照不是原始资料备份，不复制原图进每份会话。

### 旧记录

旧记录可读且原样保留，不从今天的任务内容补造过去快照。历史无快照时标明「旧记录未保存当时信息」；如展示当前对象名称，明确是当前名称。旧引用缺失时按遗留缺失展示，不自动伪造deleted事件。旧未结束会话进入恢复流程，由用户确认后处理；本批不重写已结束旧记录为新版本。

### PlanItem兼容边界

3B不实现规划UI，也不假定旧plan_items不存在。提案需覆盖Task删除后的计划活引用策略：旧历史可保留并明确断开；未执行计划不得继续指向已删任务。若该策略需加快照、引用状态或版本标记，应与契约差异同时说明，不只加snapshot就宣称引用闭合。

focus_session_id单值仅作为最近一次**已结束**会话的快捷引用（需在字段说明中明确），全部会话以FocusSession.plan_item_id反查；不保存第二份会话ID数组。本批默认从任务行动开始，plan_item_id为空；已有计划记录不随意重算，阶段5正式接入后再定义全部汇总更新。

## 9 删除与撤销

沿用已定便签联删、任务删行动、原始资料默认保留；不把历史删除混入普通任务删除。

### 删除前

受影响对象存在任何未结束会话，包括暂停：提示「取消删除 / 先结束本次工作」。完成结束表单后重新展示删除影响，再由用户确认；不能因之前点过删除就在异步结束后自动删。失败或取消保持记录不变。

### 删除事务

- 删除单个Action：同步清current_action_id；关联已结束历史action_ref_state变deleted，task_ref_state保持实际状态。
- 删除Task或便签联删：删除对应任务/行动，结束历史逐引用断开，草稿、成果、用时、快照保留。
- 快照在开始时已有，删除事务不临时伪造当年信息；旧记录按遗留策略兼容。
- 历史页显示「原任务/行动已删除」，不提供失效跳转；任务仍存在时仍可返回任务。
- 含未执行/历史计划数据时按批准的PlanItem策略同步处理，不能留下新悬空活引用。

### 撤销

只逆转本次删除：恢复任务/行动及本次被断开的引用；不改写会话成果、累计、快照或新产生记录。恢复事务逐条检查ID、类型、归属、版本与关系；记录被其他操作改过时明确拒绝冲突，不能把整份历史快照覆盖回去。

删除记录需包含本次关系变更的最小补丁及提交后版本/状态，供冲突感知撤销。连续删除的单步lastDeleted仍沿用当前边界，不在本批增加通用历史撤销栈。

## 10 历史展示

任务详情展示本任务相关的已结束记录摘要：行动、开始/结束、实际用时、结果、卡点；展开看草稿。页面内只读回看，首版不做统计图。

删除任务后，日程辅助入口「工作记录」可访问独立历史列表，保证保留内容真的可找到；按日期及任务标题搜索即可，不新增并列主导航。关联仍有效时提供返回任务，断开时保留快照标签。

历史时间与页面分组按北京时间；累计毫秒为事实，分钟只是展示换算。不得每段先四舍五入再求和造成累计误差。

## 12 验收矩阵

1. 从指定当前行动开始，只创建一份会话；没有行动不能绕过创建无关联会话。
2. 运行→暂停→继续→结束，按受控时钟验证累计，无重复加时；started_at保持首次开始。
3. 草稿自动保存，刷新恢复；旧保存回调不覆盖新输入或另一会话。
4. 保存失败保留草稿，结束失败不半结束；恢复后重试恰一份结果。
5. 双击、连续Enter、重复暂停/结束都幂等，成功后新的明确开始仍可创建下一段。
6. 同空间两页并行开始只成功一份；失联接管后旧页不能继续写；恢复不自动计入失联间隔。
7. 个人/演示空间分别读写；切空间先成功暂停；旧异步请求不写入新空间。
8. 异常关闭、休眠、时钟前后跳变展示恢复确认，用时修正是用户显式操作。
9. 行动完成清当前引用，任务不自动完成；部分/阻塞不篡改行动或Task状态；阻塞缺卡点拒绝。
10. 开始后改任务标题，旧会话仍展示开始时快照；结束后成果只读。
11. 单删Action、删Task、便签联删各验证历史保留、逐引用状态、影响确认和原子性。
12. 暂停会话同样阻止直接删除并引导先结束；取消删除/结束不丢草稿。
13. 撤销恢复本次关系；期间历史有新版本则拒绝覆盖；新的工作记录不被回滚。
14. 删除后从工作记录入口找到成果；不存在对象链接不跳到空页。
15. 旧无快照历史可读、不会被新校验整体拒绝；旧未结束恢复不补造过去事实。
