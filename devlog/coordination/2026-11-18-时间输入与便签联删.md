# 时间输入与便签联删：Qoder 修改任务

日期：2026-11-18。状态：用户已明确提出并纳入产品规则，代码待 Qoder 实施与验收。本次只修改决策与交接文档，不代表界面已修好。

## 1. 当前问题

- frontend/src/components/domain/FieldCard.vue 的截止、时间节点与参照编辑使用普通 Input，用户要输入日期/ISO 字符串并理解多项内部属性。

- frontend/src/stores/app.js 的 deleteNote 遇 deadline.from_note_id 引用就返回失败；这是原有产品规则，不是缺少删除接口。
- 当前便签与任务保存在浏览器 IndexedDB；本轮修改主要在产品前端、领域逻辑和存储事务，不需要增加后端任务删除 API。

## 2. 时间输入修改要求

做一个共用时间输入组件，供手动截止、便签截止编辑、时间节点编辑复用；参照日期和消息日期采用仅日期选择。

用户追加：没有已有日期的输入默认动态读取北京时间的今天，用户可再改日期和时刻；已有值优先。默认值在用户保存/确认后才生效，主动清空不反复回填，原始模型缺失日期不被自动改写成今天。来源与参照语义详见 [默认北京时间规则](2026-11-18-默认北京时间规则.md)。

| 场景 | 用户操作 | 保存规则 |
| --- | --- | --- |
| 只有日期 | 点日历选日期 | 保存 date，不额外补时刻 |
| 有具体时刻 | 开启“设置具体时间”，选择日期和时分 | 用户手动输入默认按北京时间 +08:00 保存，已有明确其他时区按实际含义处理；详见默认北京时间规则 |
| 无截止/不确定 | 清空，或选择“暂不设置” | 不保存空字符串作为有效截止；任务允许无截止 |
| 已识别到时间 | 自动回填，用户直接确认或修改 | 未改值的确认保留模型来源；实际改值记录用户来源 |
| 参照与消息日期 | 点日历选择，可清空 | 真实日历校验，不自动用收集日填参照 |

- 提供“今天、明天、一周后”快捷按钮，按北京时间当前日期计算，只有用户点击才填入。
- 普通界面不要求手写 ISO、UTC 偏移或选择 explicit/relative/inferred；以“日期来源”“用于提交截止”等中文表达，必要的技术属性放进详情。
- 已有明确偏移或秒的时间，打开后未编辑再保存不能丢失偏移、秒数或改变实际时刻；原文未知时区信息保留，业务采用默认北京时间并明示，不伪装成原文已有时区。详见 [默认北京时间规则](2026-11-18-默认北京时间规则.md)。
- 不使用 toISOString().slice(0, 16) 直接回填本地时间控件；避免 UTC 转换造成日期或时刻偏移。
- 时间改动后旧确认失效，重新确认后才作为任务依据；取消编辑保持原值。清空时同步调整确认状态和元数据，不能留下 confirmed + 空值。
- 保存失败保留表单输入，不关闭编辑器；组件提交值仍经领域函数校验，不只依赖浏览器控件。
- 优先复用现有组件体系；本轮无需为选择日期增加大型 UI 库或自然语言时间解析服务。

## 3. 便签与关联任务同步删除

替代原“任务截止引用便签就禁止删除”规则，适用于待核对及已审阅便签。

### 确认流程

1. 点击删除，读取当前工作空间最新便签和任务，生成影响清单。
2. 关联任务定义：note_ids 包含便签 ID，或 deadline.from_note_id 等于该 ID；按任务 ID 去重，不按标题或 source_id 猜测。
3. 弹窗列出任务数量与标题；共享多个便签的任务额外标明“还关联其他便签，本次会删除整个任务”。列表较长可以滚动，不能隐瞒数量。
4. 按钮为“取消”及“删除便签及 X 个任务”；无关联时按钮为“删除便签”。默认焦点落在取消，支持键盘与关闭弹窗。
5. 提交时重新验证关联清单；若其他页面/异步操作导致影响范围变化，刷新清单让用户重新确认，不能静默扩大删除范围。
6. 同一 IndexedDB 事务删除便签、已确认范围内的任务，并清理当前已实现的关联。事务成功后再更新队列、今天列表、选中项和提示。

示例文案：

> 删除“课程作业通知”？这会同时删除 2 个关联任务：课程报告、课堂展示。原始资料保留。此操作不可撤销。

事务失败时显示“删除失败，便签和关联任务均已保留”；取消或失败不能减少列表数量。提交中禁止重复点击。

### 删除范围

- 仅当前工作空间、当前便签及确认框列出的关联任务；任务已完成与否不改变是否纳入影响清单。
- 保留原始截图/文字、其他便签和事项。共享任务的其他便签保留，不向外递归删除。
- 当前前端尚未落地完整行动/计划/专注数据流，本次不为未实现功能预建新结构。后续接入时，任务删除必须同步清理活动关联并保留专注历史；如存在历史外键，采用兼容的归档/历史引用方案并先同步契约，不能硬删父记录后留下悬空引用，更不能默默扩大删除到历史内容。
- 删除与同便签编辑、建任务、重新分析/待保存重试协调；已删除便签不能被旧异步结果或排队的编辑重新写回。取消本次操作不影响正常分析。
- 本次只落实当前用户点击的确认流程，不批量清理现有资料，也不清空用户数据库。
