## 2. 解码器支持范围（decodeArchiveBounded）

- 支持：deflate(method 8) 与 stored(method 0)；本应用导出 ZIP 全支持。
- 拒绝（显式 code，不猜测）：加密(flag bit0)→ZIP_UNSUPPORTED；数据描述符(bit3)→ZIP_UNSUPPORTED；未知压缩方法→ZIP_UNSUPPORTED；ZIP64 哨兵/versionNeeded≥45→ZIP_UNSUPPORTED；坏 CRC32/声明尺寸不符/偏移越界/截断→ZIP_CORRUPT；重复路径→ZIP_DUP_PATH（保序拒绝不静默覆盖）；绝对/`..`/反斜杠/目录项→ZIP_BAD_PATH；找不到 EOCD→ZIP_CORRUPT。
- 限额按**实际输出字节**边解压边计（不信声明 uncompressedSize、不全量分配后检查）：单文件/总量/条目数超上限立即停止并释放作业；File.size 预检 + 实际压缩字节复检。
- 流式 fflate `Inflate` 分块喂入限制单块输出；可在 Worker/分块异步中终止；AbortSignal 传导取消。
- SHA-256 仅作损坏检测与文件身份（非可信签名）；包内容不执行、不访问外网 URL、不上传、不调模型/healthz。

## 3. 取消与资源释放

- 每个检查作业一个 AbortController；`selectBackupFile` 递增 jobId，旧解析晚到结果按 jobId 丢弃（绝不复现）；第二文件取消旧解析。
- `cancelInspection` 仅检查阶段可用→abort+释放→idle，零写入零目录。
- `releaseInspected` 清空 assets Map、`releasePrepared` 置空准备数据；完成/取消/重置均释放大字节。预览仅摘要，不渲染全图/巨草稿、不创建图片临时 URL。
- **写入阶段（committing）禁止取消/换文件/重置**；离开本页弹提示等待（作业不绑定组件，离开不中断写入）。

## 4. 四 store 单事务结构（commitRestore）

一个 `readwrite` 事务覆盖 `['workspaces','sources','docs','focus_runtime']`：
1. 事务内读目标目录 + 全量 sources/docs/runtime（不依赖全局 configureWorkspace，无临时切空间）。
2. 守卫：目标非 personal/demo；目录未被其它意图占用；全部 prepared 记录/runtime 归属目标；新活 ID + 隔离历史 ID 与现有全库对象无碰撞。
3. 幂等：目标已有回执且绑定（op_id + 源文件实际字节 SHA-256 + backup_id + 目标名 + 冻结 ID 映射签名）完全一致→返回原空间不重写；绑定不符→RESTORE_INTENT_MISMATCH；它意图占用→RESTORE_TARGET_OCCUPIED。
4. 写入用 `add`（非覆盖）；任一 store 失败/QuotaExceeded/ID 冲突→**整体 abort 回滚**（含已写 store），无空目录/半份 runtime；`settled` 标志保证单次结算。
5. 文件读取/解压/哈希/Blob 创建/remap/准备复检**全部在事务外**；事务内不 await 非 IDB 工作。
6. tx 已提交但回调晚到/UI 失败→`findRestoreByOperation` 先查回执返原空间，不盲目提示重导。
7. 提交后 `verifyCommittedRestore` 按显式目标读回核对计数/图片字节与类型/必要引用/未结束协调；异常只报「已创建空间，但核对异常」，不假装零写入、不自动回滚可能已被用户编辑的空间。

## 5. 目录回执字段（workspaces.restore_receipt，目录元数据）

`operation_id`、`source_file_hash`(源 ZIP 实际字节 SHA-256)、`backup_id`、`target_name`、`id_map_signature`(活+历史映射排序规范化 JSON)、`committed_at`(ISO)、`counts`(逐 kind)、`source_count`、`image_count`。
**非业务契约、不进备份导出、非用户运行台账**。文件名/大小不作文件身份。

## 7. 真实故障 vs 模拟故障（明确区分）
