### 4.2 错误码（稳定 code + 可读 message）

领域（事务内抛错→整体回滚）：
`INVALID_DATE`（拒 2026-02-30，不滚动修正）、`INVALID_MINUTES`（拒 0/负/小数/NaN/Infinity/非数值）、`INVALID_FIELD`（说明空/缺预固定 ID/编辑无变更）、`RELATION_INVALID`（任务不存在/跨空间/ID 已存在）、`TASK_DONE`（R4 后四个变更命令统一先重查 Task，已完成即拒，先于日期/快照检查；旧成功信封仍可 replay）、`PLAN_NOT_EXECUTABLE`（断引用历史只读）、`PLAN_TERMINAL`（终态不可编辑/改期/取消/再确认）、`UNFINISHED_FOCUS`（附 sessionIds，含暂停/旧版未结束）、`PLAN_HAS_HISTORY`（附 sessionIds，已结束挡原地改写）、`STALE_PLAN`（快照缺失/必需字段不全/与事务内最新不符；R3 后空对象、数组、逐字段缺失均拒）、`DUPLICATE_PLAN` / `DUPLICATE_SCOPE_CHANGED`（零写入提醒，附 matchingIds）、`AFTER_DEADLINE_UNCONFIRMED`（附 risk 事实）、`DEADLINE_CHANGED`（确认依据变化）、`HISTORY_UNRESOLVED`（R5：存在影响权威结果的异常时拒绝写入摘要，保留原值，historyConfirm 也不能绕过）、`HISTORY_UNCONFIRMED` / `HISTORY_CHANGED`（历史摘要须完整回传且一致）、`CONFIRM_REQUIRED`（取消/进度须显式确认）、`ACTION_DONE`（执行资格）。
汇总诊断（非抛错，读取返回）：`CONFLICTING_SESSION`（同 ID 冲突数据，**全部副本整体剔除**，正反序结果一致，已有回归锁定）、`INVALID_DURATION`（负时长）、`INVALID_ENDED_AT`（非法结束时刻；R1 后契约合法的小数秒时刻不再误判）。读取结果新增 `authoritative`（problems 为空才 true；false 时 actualMinutes/latestEndedSessionId 为 null，不把「全部解析失败」当「没有历史」）与 `cacheMismatch`（仅权威可用时报告缓存 actual_minutes/focus_session_id 与重算值的差异；只读不自动修库，用户核对确认后才修正）。
服务：`STALE_REQUEST`（同 requestId 换输入/目标/空间/超窗 10min）、`REQUEST_ENVELOPE_REQUIRED`（裸 requestId 无本地签发也无台账凭据）、`SAVE_FAILED`（落库失败探测，原信封可重试）。
删除保护（matter.js）：`PLAN_PROGRESS_REQUIRED`（附 planItemIds，拒整个删除）、`UNFINISHED_FOCUS`、`SCOPE_CHANGED`（删除范围变化拒旧确认；R2 后范围含计划影响快照 planItemIds+planFacts——ID 集合与每条的 state/task_ref_state/处置方式，事务内重算比对，便签联删与直接删 Task 两路径一致）。

### 4.3 状态转移

- create → `planned`（actual_minutes=null、focus_session_id=null、task_ref_state=active、order=目标日最大有效 order+1）。
- edit/move：仅 `active+planned+无任何关联 Focus`；move 保留 ID 改 date+目标日 order，同日改期无操作；总截止不变。
- cancel：`active+planned/partial+无未结束 Focus+显式 confirm` → `cancelled`（保留记录；有已结束会话时同事务按本单口径重算摘要，须 historyConfirm）。
- confirmProgress：`active+planned/partial+无未结束 Focus+显式选 partial/done` → `partial/done`；不完成 Action/Task；无会话也可确认（actual_minutes 仍 null=未记录）。
- arrangeAnotherDay：新建另一条 planned（新 ID），不迁移原会话、不相减历史用时。
- `done/cancelled/moved` 终态：不支持恢复 planned 或覆盖编辑；相同命令有效重试 replay 原成功结果，不因已终态误报第二次失败。
- 删除：planned 无会话随 Task 删（撤销快照保留）；planned+已结束会话拒整个删除；partial/done/cancelled/moved 保留 PlanItem 置 task_ref_state=deleted（会话成果闭合）；撤销只恢复本次移除/断开对象，已有新修改拒绝覆盖。

### 4.4 事务边界

- 全部业务校验与写入在 `db.transformFocusAtomic` 回调内**同步**完成（不在 IDB 回调里等网络/任意异步）；回调内 `env.ws` 被 ctx.ws 覆盖，排队期间切空间→事务内按新空间事实拒绝，两空间零残留。
- 回执（plan_ops 命名空间，`plan_ops:${ws}`）与业务变更**同事务**提交（runtimePuts），不存在先保存再补回执；回执只存 `{request_id, op, workspace_id, plan_item_id, input_sig, at_ms, issued_at_ms, result摘要}`，不含成果正文/原图，不进业务备份。
- 任一步抛错→IDB 事务整体 abort（docs+focus_runtime 一起回滚）；失败不清草稿、不改 Task、不留半条计划/半份回执；重试用原信封，修改输入用新信封。
- 幂等不依赖有限台账：信封绑定（op/ws/targetId/input_sig/issuedAtMs）+ 台账 replay 前校验绑定；墓碑淘汰后超窗旧请求明确 `STALE_REQUEST`，不当新请求重执行。
