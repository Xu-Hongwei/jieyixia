# 「截下来」下一阶段 MVP 执行计划

> 交给 Qoder 的执行基线。目标是完成可离线使用、可恢复、可演示、可提交的 MVP。  
> 先完成本文 P0，再做任何 P1。本文没有授权修改产品范围或擅自升级契约。

## 1. 项目目标

当前产品已经完成第一条闭环：

```text
收集截图/文字 → AI 生成草稿 → 人工核对 → 确认事实 → 创建任务 → 刷新恢复
```

下一阶段要把它变成一个能真正帮助用户执行任务的本地优先工作台：

```text
收集 → 核对 → 归组 → 建任务 → 今天查看 → 制定计划 → 专注执行 → 备份恢复
```

MVP 的成功标准不是 AI 功能数量，而是用户在断网、刷新、模型失败和浏览器数据恢复后，仍然不会丢失原始资料、确认事实、任务和执行记录。

## 2. 当前基线与不可回退约束

### 已有能力

- FastAPI 后端契约 `0.3.0`，`GET /api/healthz` 和 `POST /api/analyze`。
- fixture 模式和真实模型模式，模型失败保留本地资料并提供降级。
- 严格日历、时区和图片完整性校验，产品业务默认北京时间 UTC+08:00。
- 分析总预算、上游响应字节上限、Bearer 鉴权、IP 限流、并发闸、每日厂家额度和 request_id。
- 前端 Vue3 + Vite + Pinia + IndexedDB + hash 路由。
- 已完成收集、AI 分析、字段核对、手动编辑、确认、创建任务、失败保留、刷新恢复和便签删除联动。
- `contract/models.py` 已包含 `Source`、`Note`、`Matter`、`Task`、`Action`、`FocusSession`、`PlanItem`、`PlanDraft` 等本地领域模型。

### 必须保持

1. 原图/原文必须先保存到 IndexedDB，再调用 AI。
2. AI 失败、网络断开、模型超时、保存失败都不能丢原始资料。
3. AI 输出永远不能直接变成 confirmed；用户确认推算值时保留 `derived` 和原始来源。
4. 用户实际修改值才将来源改为 `user`。
5. 缺失日期不由后端静默补今天；表单初值可以按北京时间显示今天，用户保存后才成为用户事实。
6. naive 时间业务计算按北京时间解释；不能使用设备时区或服务器时区替代产品规则。
7. 任务截止来源、便签引用、计划条目和专注记录必须可追溯，禁止留下悬空 ID。
8. 不新增规划、搜索、今天或专注后端接口；这些功能优先离线在前端完成。
9. 不为了赶进度修改契约字段语义。确需改契约时，必须同步 `models.py`、schema、typedefs、fixtures、测试和交接资料，并升版本。

## 3. 总体实施顺序

### 阶段 0：冻结基线与验收工具

先不要改功能，完成以下工作：

- 运行后端 lock 环境全量测试，目标 354 项通过。
- 运行前端单元测试、类型检查和生产构建。
- 记录当前 git 状态、契约版本、fixture 数量和现有浏览器验收结果。
- 建立一份 MVP 验收清单，每完成一个阶段只勾选有证据的项目。
- 保留 fixture 模式作为无密钥演示后备方案。

阶段出口：任何人从干净环境可以启动前后端，打开页面并完成现有黄金路径。

### 阶段 1：本地数据层、工作区和时间输入基础

#### 1.1 工作区

当前记录已有 `workspace_id` 和 `is_demo` 字段。先复用现有字段，不新增后端表：

- `personal`：真实用户工作区。
- `demo`：公开演示工作区。
- 所有读取、写入、删除和统计都必须经过当前工作区过滤。
- 演示数据初始化必须幂等，不能重复生成。
- 切换工作区后重新加载 sources/docs，不复用上一个空间的选择状态。

如果需要保存工作区目录，再将 IndexedDB 版本从 1 升到 2，并写迁移测试；不能清空已有 `jxl-product` 数据。

#### 1.2 时间输入

- 日期输入使用日历控件，不要求普通用户手写 ISO 字符串。
- 空日期表单默认显示北京时间的今天。
- 允许“今天、明天、7 天后”等快捷操作，但必须是用户主动点击。
- 已有值原样回填；用户保存或确认后才写入记录。
- 清空表示暂不设置，不得自动恢复成今天。
- 节点编辑器只展示用户需要的角色、日期、时间和参照来源，不直接暴露内部枚举。

#### 阶段出口

- 新建、编辑、清空日期的测试通过。
- 系统时区改成其他时区时，今天、逾期和日期分组仍按北京时间。
- 刷新和重新打开工作区后日期值不漂移。

### 阶段 2：F08 今天首页、F04 收集箱、F05 事项归组

#### 2.1 今天首页

页面必须提供：

- 北京时间今天的日期标题。
- 今日到期、已逾期、待核对、分析失败、今日计划和可恢复专注入口。
- 任务状态筛选：待办、进行中、已完成。
- 每个任务显示截止来源：便签、手动或无截止。
- 未确认字段不能进入“已确认截止”列表。
- 失败任务保留“重试 AI”和“手动整理”入口。

不要根据字符串排序判断逾期；统一调用 `domains/time.js` 的北京时间规则。

#### 2.2 收集箱

- 关键词搜索标题、原文摘要和来源名称。
- 按内容类型、分析状态、核对状态、日期范围筛选。
- 明确显示待核对、待确认、失败和已归档状态。
- 删除便签前列出影响任务。
- 依据用户追加定案，提供“取消”与“删除便签及关联任务”：任务集合由 note_ids 或 deadline.from_note_id 引用计算并去重，确认前列明共享任务将整体删除，原始资料默认保留。不再执行“截止被引用就禁止删除”的旧规则。
- 删除操作必须事务化，失败时界面和 IndexedDB 都保持原状。

#### 2.3 事项归组

- 创建、重命名和删除事项。
- 将便签、任务手动归入事项。
- 事项页展示相关资料、任务、截止时间和当前状态。
- 删除事项只解除关联，默认保留便签和任务。
- 同一便签默认只属于一个主要事项；不要擅自改成多对多模型。

#### 阶段出口

用户可以从一张便签进入事项，再进入任务，并从今天首页找到该任务；删除便签、删除事项、解除关联均有明确提示和回滚测试。

### 阶段 3：F09 下一步行动与 F10 专注工作区

#### 3.1 行动

先做人工行动，不做 AI 建议：

- 为任务添加多个行动。
- 行动包含文本、预计分钟数、完成状态和来源 `user`。
- 任务可以设置当前行动。
- 完成行动不自动完成任务。
- 允许重新打开已完成行动。

#### 3.2 专注会话

复用 `FocusSession`：

- 从任务或计划条目开始。
- 开始、暂停、恢复、结束。
- 使用 `started_at + accumulated_ms + running` 计算实际时间，不用 `setInterval` 累加作为唯一事实。
- 刷新页面后恢复正在进行的会话。
- 结束时选择完成、部分完成、被阻塞，并要求阻塞时填写卡点。
- 保存草稿内容和实际用时。
- 专注完成不自动修改任务截止时间、确认状态或计划目标。

#### 阶段出口

关闭页面、刷新、断网后重新打开，正在进行或已结束的专注数据仍然完整；行动完成、计划完成和任务完成三者状态不互相误改。

### 阶段 4：F11 备份恢复与 F12 演示隔离

#### 4.1 备份导出

导出 ZIP，至少包含：

- manifest：备份版本、契约版本、导出时间、workspace_id、记录数量和校验信息。
- sources 元数据和原图/文字。
- notes、matters、tasks、actions、focus_sessions、plan_drafts、plan_items。
- 不包含 API token、模型密钥和运行日志。

#### 4.2 恢复

- 选择文件后先完整校验 manifest、版本、JSON 结构、图片和引用关系。
- 恢复到新 workspace，默认不覆盖当前空间。
- 任意一步失败都不提交半份数据。
- 恢复后检查 source、note、matter、task、action、focus、plan 的引用闭合。
- 老版本不静默当新版本，必须显式提示迁移或不支持。

#### 4.3 演示空间

- 首次进入公开页面显示“进入演示”或“开始自己的空间”。
- 演示数据带 `is_demo=true` 和 `workspace_id=demo`。
- 演示数据和真实数据分栏展示。
- 提供恢复演示初始数据按钮。
- 清理演示空间不能触碰 personal 空间。

#### 阶段出口

清空浏览器数据前可以导出；在新浏览器空间导入后，原图、确认状态、任务引用、专注记录和计划都能恢复。

### 阶段 5：F13 离线规则规划

先完成 P0 规则版，不做 AI 排程。

#### 5.1 批量录入

支持至少 5 项任务：

- 标题必填。
- 截止日期/时间可空。
- 预计剩余分钟数可空；为空时进入“待估计/未排程”。
- 已完成分钟数可选。
- 是否允许拆分，默认允许。
- 最早开始日期可选。
- 可选择已有任务，避免重复创建。

#### 5.2 规则排程

- 规划范围固定为未来 7 天。
- 用户设置每天可用分钟数。
- 默认保留 15% 缓冲，可由用户关闭。
- 截止更近的任务优先，使用确定性 EDD 规则。
- 允许拆分的任务按天分配；不允许拆分的任务只能整体放入足够容量的日期。
- 无截止任务可以保留未排程，不强行猜日期。
- 不能安排的工作必须进入 `unscheduled`，写明 `gap_minutes` 和原因。
- `gap_total` 必须准确，不能返回看似完整的假计划。

#### 5.3 预览、编辑和确认

- 草案与已确认计划分开保存。
- 用户可以调整日期、顺序、计划分钟数和行动说明。
- 调整时实时显示每日已安排、可用容量、缓冲和缺口。
- 确认后生成/更新 `PlanItem`，不回写任务 deadline 或 status。
- 计划条目完成不自动完成任务。
- 当天未完成只提供“移到其他日期、保留待安排、重新规划”等明确操作，不静默挪动。

#### 阶段出口

刷新、断网和重新进入页面后，已确认计划仍然可读、可编辑、可执行；计划和实际专注用时分开保存。

### 阶段 6：公开演示和比赛提交

- fixture 模式作为无密钥演示后备。
- 真实模型模式必须放在服务端，密钥不能进入浏览器构建产物。
- 当前前端 API 客户端没有发送 `Authorization`；不能简单把 `JXL_API_TOKEN` 放进 Vite 环境变量。真实模型公开时使用同源网关/反向代理服务端注入 token，或保持真实模型后端私有。
- Qoder Sites 负责可访问前端入口；部署前验证后端是否能由 Sites 直接托管，不能假设 FastAPI 可以直接运行在静态 Sites 上。
- 公开前检查 CORS、token、限流、并发和每日额度。
- 准备真实截图、过程截图、使用说明、作品介绍和 Qoder 操作记录。
- 录制一条完整视频：收集 → 核对 → 建任务 → 今天 → 规划 → 专注 → 刷新恢复 → 备份恢复。

## 4. 本轮不做的功能

在上述 P0 完成前，禁止插入以下 P1：

- 跨便签截止时间自动变更检测。
- AI 自动归组。
- AI 自动生成行动建议。
- 自然语言批量规划、AI 估时、AI 拆解和逾期自动重排。
- 应用内图片裁剪和 OCR 坐标高亮。
- 跨版本合并、去重和冲突解决。
- 效率统计、复杂依赖图和课程表级排程。
- 新的后端规划接口。

## 5. 每阶段必须交付的证据

每个阶段结束时，Qoder 必须提供：

1. 改动文件清单。
2. 新增或更新的单元测试。
3. 前端生产构建结果。
4. 关键浏览器路径的截图或录屏。
5. 失败、断网、刷新和重复操作的结果。
6. 数据模型或契约是否变化；没有变化也要明确写出。
7. 当前未完成项和下一阶段入口。

不得只写“已完成”；必须给出可复核的路径、测试命令和结果。

## 6. 最终 MVP 验收路径

1. 进入 demo 空间或创建 personal 空间。
2. 上传一张通知，确认原图先保存。
3. 调用 fixture/模型，展示 AI 草稿和不确定性。
4. 使用北京时间今天默认值编辑一个缺失日期，并明确确认。
5. 将便签归入事项，创建任务和下一步行动。
6. 在今天首页看到任务和状态。
7. 放入未来 7 天计划，查看缺口并手动调整。
8. 开始、暂停、恢复一次专注，保存实际用时。
9. 刷新页面，确认所有状态仍在。
10. 导出数据，在新空间恢复并验证原图与引用。
11. 退出 demo 空间，确认 personal 数据不被污染。
12. 断网后继续浏览、编辑、规划和专注；只有 AI 入口进入降级态。

通过这条路径后冻结 MVP，停止新增功能，转入比赛截图、视频、作品帖和发布审查。

## 7. 给 Qoder 的执行规则

- 按阶段逐项实施，每阶段完成后暂停并交回验证。
- 不擅自修改产品范围、删除字段或新增后端接口。
- 不把 P1 AI 功能插入 P0。
- 不以 fixture 通过代替真实本地存储、刷新、断网和恢复验证。
- 不把历史验收数字当作当前改动的证据，必须重跑对应检查。
- 发现契约冲突、删除语义冲突、工作区数据风险或公开 token 风险时，先停在当前阶段并报告具体差异。
