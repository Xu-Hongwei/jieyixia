# 截下来 · 前端布局改版计划

评审基于当前正式前端和上一轮桌面、手机实测画面。本文记录设计提案，供原型评审和后续实施。

## 当前界面与设计决定

- **外框。** 桌面左侧导航、顶部页名和正文大标题重复提示位置，深绿侧栏在内容少时尤其抢眼。一级页保留一个正文标题，主操作与标题同排；子页顶部保留返回位置。品牌字标保留深绿，导航底色改浅，当前项用底色和字重识别。中文正文和工具标签用系统黑体，特色字形集中在品牌和日程日期。
- **日程。** 七列重复“为这天安排工作”，日程下面又分两个待跟进队列。将加号整合到日期列头，键盘聚焦和触屏均可直接触达。保留“上方每日工作、下方每日截止”；工作条优先显示行动与预计分钟，截止行显示任务与截止时间。临近、逾期分别配文字标签。宽屏且有待处理任务时试用右侧窄栏，宽度不足时移到周表下方，队列为空时收起。详情抽屉继续覆盖页面，不把七列挤窄。
- **任务。** 现有四个筛选控件占一整栏，即便仅有一两项任务。将搜索和“筛选”并入清单工具栏，已启用的条件保留在外。任务名称占弹性主列，状态和截止日期纵向对齐；已有多项行动时可显示简短进度。待安排任务保留直接安排入口。首次使用显示建任务入口，筛选无结果显示清除条件，两个状态使用不同文案。
- **资料。** “事项管理”收起时仍预留右栏，截图资料在列表里又主要靠文件名辨认。默认让资料列表占满宽度，截图用小图、文字用首句。选中资料才展开预览，事项管理由工具栏按需打开。空资料库沿用已上线到本地的直接录入；演示空间继续使用内置案例。
- **助手。** 表单里上传、已有资料、关联任务、可用时间和生成几乎同权。输入态优先呈现“这次用哪些资料”和“你想怎么安排”，已有任务和每日预算按需展开。进入预览后，按天列出行动和时长，未排工作在同页给出选日入口；主按钮标明将加入几项安排。没有可采用内容时给出与原因匹配的下一步。

## 实施顺序与验收

1. **先做日程样板。** 使用同一组虚构课程任务，同时出 1440px 桌面和 390px 手机稿。覆盖空周、轻量周和繁忙周。轻量周用同一个任务在周二、周四安排两次工作，周五只显示总截止；繁忙周加入长标题、同日多项和逾期。用这三张状态稿决定侧栏、字号和行高。
2. **样板确认后落地外框和日程。** 沿用现有 Vue 组件、工作区、路由和保存逻辑。从任意一天新建任务并安排仍只提交一次。检查改期、查看截止、返回选中日期、键盘新增和手机触达。
3. **再迁移任务和资料。** 对照空库、少量数据、几十项数据和筛选无结果四种状态；验证任务搜索、归组、添加截图、返回原筛选与滚动位置。
4. **最后处理助手并串联验收。** 用内置、虚构的通知走通“选资料 → 核对计划 → 采用 → 日程 → 开始行动”。单独验证未排工作、空方案、离线和待确认状态。并排对照改前改后截图，复跑现有前端测试与构建，再决定是否发布比赛站。

首轮评审的三个判断标准：能否一眼说出今天做什么和哪天截止；是否需要重复选择已选好的任务或行动；桌面是否有一整栏只显示折叠标题或零计数。手机同时检查 320px 宽度、长标题和键盘焦点。

## 二级页面复核与优先级修订

在独立浏览器里，用虚构的「课程报告」走过新建任务并安排、安排详情、任务详情、添加行动、开始工作、暂停和结束弹窗。另查了文字资料详情、千问连接窗口和内置演示的三天安排。安排与任务详情分别在 1360px 桌面和 390px 手机上查看。正式助手的未排工作、改排、历史详情和备份恢复按现有实现复核，未在本轮重新发起模型调用或执行恢复。

### 各二级页面的取舍

| 页面与状态 | 当前表现 | 设计方案 |
| --- | --- | --- |
| 新建任务并安排 | 已经一次提交，但表单标题偏泛，创建后立刻出现新的详情面板 | 保留合并表单。标题随入口显示“为周五安排工作”，所属任务和当天行动相邻，区分任务总截止与安排日期。普通保存后回到原日程并高亮新项；需要开始时直接点新项。若用户连续排多项，以实测决定是否需要“保存并继续”。 |
| 安排详情 | 390px 手机全屏面板里套一张卡，未开始就并列显示“开始这项安排”“确认进度”，同时列“实际未记录” | 工作内容做标题，下一行“周五 · 30 分钟 · 课程报告”。主动作随状态显示开始、回到工作或查看记录。改期和编辑放次级，取消放更多菜单。保留手动确认进度的能力。有记录才展示实际用时，有截止才显示截止。手机底部固定当前主动作。 |
| 选择行动与开始确认 | 已明确关联且条件满足时，现有逻辑可以点击即开始；零行动时却能先点“开始”，再看到无法确认的弹窗 | 保留可直达的路径。零行动时直接提供“添加行动”，可预填安排文字，由用户确认；多个候选时在原面板选一次。提前执行、任务受阻、跨工作区会话冲突只展示当前适用的事实，并保留现有校验。普通开始目标为一次点击，不按相似标题猜绑定。 |
| 任务详情 | 空任务的“当前行动”和“行动列表”都让用户添加行动；右侧仅有两个折叠标题也占一栏 | 合并为一个行动清单，当前行附“当前”标识。没有行动时只显示一行录入；已有近期安排时紧接清单展示。桌面右侧有资料或完成标准才展开辅助区；手机将次要内容置于安排之后。删除任务移到更多菜单，确认时列出实际影响。 |
| 工作中、暂停、结束 | 工作页同时展示本段投入、历史累计和解释；实测结束弹窗 448 × 684px，同时问行动结果和安排进度 | 工作页首屏只突出行动、当前计时、暂停及结束，写成果占主体；历史累计按需展开。结束时先问“这次行动做到了哪一步？”，再用一行明确选择“这天的安排还要继续 / 已完成”。若受阻再询问原因。行动、安排、任务三种完成事实继续独立，提交前预览实际会保存的结果。 |
| 资料详情与字段核对 | 一句文字和一个提取按钮也打开 672px 宽的整高侧栏；有分析结果时还要比对字段与原始资料 | 短文字原位展开，长文或图片打开阅读面板。核对时桌面左边原文、右边待确认字段，手机可在“原文 / 待核对”间切换并保留字段位置。核对完回到原列表的筛选、选中项和滚动位置。 |
| 助手预览、未排、调整后续 | 内置演示第三步把每日行动和总截止放得很清楚。正式流程另有未排原因、手动选日、容量确认与替换旧安排 | 正式预览沿用演示的日期、行动、时长三列。未排工作就在行内展开已有的“自行安排时间”；超预算时显示可用、已用和本次新增。调整时并列显示保留与替换的安排；没有变更可采用时，主动作带回需要改的字段。 |
| 工作记录、连接千问、备份恢复 | 三者使用时长和操作后果差别大 | 工作记录以只读正文、实际用时和来源链接为主；缺失原任务时仍可阅读。连接千问维持短弹窗，错误贴在输入处。备份恢复保持独立页面，文件、恢复目标和影响核对后再提交，下载与恢复操作分开。 |

### 下一份样板与验收

把首轮样板扩大为一条连续路径：周表 → 安排详情 → 开始工作 → 结束回写。先用同一份内容出桌面、手机两套连续画面，再统一外框。任务详情与资料核对为第二批，助手预览、记录和数据管理为第三批。

- **普通路径**：已知任务、当日、行动明确，从安排详情点一次开始。结束后回原日程，能看出哪一项完成、哪一项仍要继续。
- **例外路径**：零行动、多候选、提前执行、已有暂停会话、超预算和未保存离开各走一次；每次只出现与当前情况有关的处理动作。
- **布局与返回**：390px 下主按钮可触达，320px 下不横向滚动；键盘可打开“更多”并退出。关闭后回到触发按钮或更新后的安排，保留周次、筛选和草稿。
