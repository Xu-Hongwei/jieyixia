## 2. 持久化策略（开工单 §3 要求先说明）

- **Action 存于现有 docs store，`kind:'action'` 只是持久化元数据**，与 note/task/matter 同一识别方式；不属于契约域模型（schema `additionalProperties:false`），验证按契约 Action 字段校验：`id / workspace_id / task_id / text / minutes / basis:'user' / done / created_at`。
- **不私塞未定义字段**：契约 Action 没有 `updated_at`，编辑直接替换记录；`workspace_id` 由存储层 stamp 注入。
- **无新增 store、无 DB 版本升级**（v2 不变）：docs store 本就按 kind 区分记录类型，新增 kind 值对现有读写、迁移、备份导出是非破坏性的。
- **备份/迁移/恢复可识别**：migratePlan 与删除计划均按 kind 处理，action / focus_session / plan_item 记录原样保留（单测 action.test.js「记录原样保留，绝不删除历史」直接以这三类记录断言）。未来备份导出 docs 全量即覆盖行动。
- **当前行动有效性**（validCurrentAction）：必须属于当前任务、当前工作区（store 按 workspace 过滤）且未完成；无效引用一律不展示为有效当前行动，完成/删除当前项时清空并提示用户选下一项，不自动指定。
- **关联变更基于事务内最新数据**：transformDocsAtomic 读最新 → 纯 plan → 先删后写，跨所需 store 单事务；plan 抛错整体回滚，UI 只在提交成功后 applyChanges。无旧组件快照整体覆盖。
- **撤销**：undoDeletePlan 事务内读最新，只逆转本次删除；任一待恢复记录已有新版本 → 明确拒绝（横幅「未恢复：…」），不覆盖、不制造悬空记录；恢复任务时一并恢复行动与有效当前行动关系。

## 3. 功能变化对照开工单 §2

1. **统一详情**：日程周表/列表、事项内任务、核对页建任务结果、独立新建结果全部进 `/tasks/:id`；旧 `/today?task=` 兼容转入同一详情。返回保留来源、日期、视图、筛选与列表位置（return 链路校验 + CONTEXT_KEYS 传递）。无效/跨空间对象：明确警告横幅「任务已不存在或不属于当前空间，已回到原列表」并回原列表。
2. **信息展示**：标题、状态、截止及来源（便签出处/人工调整）、所属事项（可改归组）、说明、完成标准、当前行动卡片、行动列表、关联便签链接；标题与截止不重复堆叠。
3. **编辑**：标题重命名、description、completion_criteria 独立草稿独立保存；截止可手动调整或清空 → `source:'manual'` + `confirmed_at`，保留 note_ids 与 deadline.from_note_id 关联，不改写便签通知字段；**未改值零写入、不伪造来源变化**（A6 以 IDB put 日志实证仅 1 次写入）。
4. **手动行动**：新增/编辑，内容非空、minutes 正整数、basis=user；30 分钟为可修改输入默认值，保存后才成为用户选择。
5. **行动完成/重开/删除**：完成当前项清空 current_action_id 并提示选下一项；任务不自动完成；重开行动不自动指定当前。
6. **任务显式完成/重开**：有未完成行动时提示数量 + 确认「整体完成」，不批量改 Action.done；重开回 todo，不擅自重开已完成行动，有效当前选择保留。
7. **删除与联删**：删任务同批删行动；便签联删任务同批删行动；删单个行动更新 current_action_id。沿用确认框（列出影响）、原子事务、失败保持原状、撤销（含冲突拒绝）。

## 7. 已知边界（如实说明）

1. **撤销入口为会话内存态**（lastDeleted）：整页刷新或切换空间后入口消失，数据无损，只是不提供跨会话撤销。阶段 2 已声明的边界，本轮沿用；冲突拒绝后入口保留（仅成功才清）。
2. **空间切换静默回列表**：既定行为；跨空间对象深链接打开则有明确警告（A11 双路径验证）。
3. **截止选日保留时间尾巴**：阶段 2 allow-time 定案（保留秒与偏移），手动改日不降精度；A6 断言按此口径。
4. **周 date 参数仅非本周写入**：本周锚点不写 query（goDate 语义），A14 用下周日期验证参数恢复。
