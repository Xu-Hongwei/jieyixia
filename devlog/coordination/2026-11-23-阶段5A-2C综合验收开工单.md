# 阶段5A-2C：真实执行数据的综合验收开工单

日期：2026-11-23。状态：待执行设计，尚未验收。

前置：[5A-2B最终人工验收](./2026-11-23-阶段5A-2B最终人工验收.md)通过，R1–R4已闭合。承接[5A-2总开工单](./2026-11-23-阶段5A-2安排与专注执行联动开工单.md)的删除、恢复、旧数据和综合验收范围；本单是2C的具体执行依据。

**本次只执行5A-2C。允许修复验收证实的范围内缺陷；完成后暂停交回人工验收，不自行进入4-3、5B或部署。**

## 1 本批目标

让已经能走通的“安排→行动→工作→成果→日程”在删除、撤销、备份、恢复、断网、跨日和换空间之后仍然可靠。

必须回答三个产品问题：

1. 删除任务或行动后，已投入时间和成果是否保留，误删能否按既有规则撤销？
2. 用户把实际使用过的工作区导出，再恢复到新空间后，安排、记录、图片和引用是否仍然完整，能否继续使用？
3. 断网、刷新、异常恢复、换空间时，页面是否如实说明当前状态，避免丢成果、重复计时或更新错对象？

本批主要交付验收证据、必要的小范围修复和5A功能完成对照，不新增一套功能。完成2C并经人工验收后才收口5A；4-3仍负责演示与整体产品体验，5B仍是后续规划规则，部署仍单独推进。

不改业务后端/API、契约0.4.0或DB v3；不新增登录同步、自动排程、通知、任务多截止、回收站、永久撤销记录、离线应用安装或刷新后表单恢复功能。

## 3 验收环境与数据分支

### 3.1 隔离要求

- 使用独立浏览器Context、真实IndexedDB及虚构资料；不清空用户个人、演示或恢复空间，不改变用户后端进程。
- 使用独立前端服务。AI路径不属于本批：拦截模型请求，采用既有fixture或手动功能；健康检查与模型调用分别记录，不能把后台请求混称为纯离线。
- 双页面并发必须处于同一个测试浏览器Context与同一应用origin，才能共享数据库。不同隔离Context只能证明隔离，不能证明共享空间互斥。
- 每条有破坏性的路径使用独立数据分支，或通过已验证的ZIP恢复建立新的测试空间。不能依靠前一用例留下的随机状态。
- 先导出一份正常基准ZIP；“删除后导出”“未结束会话导出”“遗留数据”“异常文件”分开保存，注明来源和用途。

### 3.2 主要数据必须由页面生成

基准日期用执行当时北京时间D；任务总截止设D+4（日期精度），另外准备精确到时分秒的截止和无截止任务作为对照，不硬编码11月23日。

| 数据 | 构造方式与用途 |
| --- | --- |
| 任务T：完成报告 | 真实页面创建；至少两个不同ID的行动A1/A2，至少一项同名行动对照身份选择 |
| 安排P1：D整理材料 | 页面创建；通过开始/结束产生两段工作，首次安排partial，第二段可确认安排done，行动仍partial；证明两种结果独立 |
| 安排P2：D+1写初稿 | 从P1的继续工作路径或已有“另安排一天”创建；新ID、空摘要，提前执行时明确确认；至少一段blocked+partial并保存卡点 |
| 安排P3：未执行的后续工作 | planned且无任何会话引用，用于验证随Task删除及撤销 |
| 其它历史安排 | 通过正常取消/改期操作形成cancelled/moved，对照新安排和旧历史，不能直接伪造正常链路的最终结果 |
| 资料与图片 | 至少一份虚构文本资料、一张小测试图片及真实关联；资料初始化可用已验证fixture，须披露，主要执行记录不能全部靠种子制造 |
| 无截止任务U与独立工作 | 默认北京时间今天的新安排、无plan关联会话，验证旧流程不被计划联动污染 |
| 运行/暂停分支 | 单独分支制造；遵守每空间最多一份未结束工作、全局最多一份运行工作，不能为了测试方便造两份正常运行记录 |

至少一条多段累计链使用真实等待，例如两段各运行不少于40秒。断言以真实持久化accumulated_ms求和为准，不能因计时误差强行断言恰好80秒。精确40秒+40秒→1分钟、午夜等边界另用受控时钟验证，标明模拟。长等待期间分段检查并报告进度，不等待整夜。

历史v0、旧planned+已有结束记录、异常引用、受损ZIP等允许用独立fixture构造，但须明确是兼容/异常样本，不声称为正常页面生成。

## 4 删除与撤销规则

### 4.1 未结束工作保护

对运行和暂停分别测试：删除Task、删除其实际Action、完成Task/正在执行Action以及便签联删等会影响该会话的入口，应按既有规则阻止并给出返回工作入口。暂停不等于结束。

打开确认时允许、提交前另一页面开始工作或新增删除范围时，事务内仍须拒绝旧确认，重新提示范围；只禁用按钮不算通过。取消删除不产生业务写入。

### 4.2 已结束历史保留

| 操作 | 应有结果 |
| --- | --- |
| 删除有真实成果的Task | Task及按既有规则随删的Action移除；已结束会话和有历史的安排保留；引用状态按规则标为deleted，成果正文、历史快照、投入与原安排状态不丢 |
| planned且从未被Focus引用的安排随Task删除 | 可随删，进入本次撤销快照；不残留活引用到已删Task |
| 旧planned已有结束历史 | 整个删除先拒绝，要求核对安排进度；不能因state=planned就把已投入历史删掉 |
| 删除Action | 不删除PlanItem和已投入记录；会话行动快照可读，不重新绑定同名Action |
| 删除便签并同步删除关联Task | 预览真实影响范围，明确确认后执行；引用闭合和历史保留与直接删Task一致，引用拒绝按现有规则处理 |

删除后不只看列表消失，还要从工作记录、安排详情和日程历史打开成果；历史不能伪装成仍可开始的活任务。

### 4.3 撤销不能覆盖后来修改

- 同一有效撤销窗口内：任务/行动及本次随删的安排按原ID恢复，历史引用仅在满足既有回补条件时恢复，不重算或清空历史成果。
- 删除后另一页面重建同ID或修改受影响记录：按现有冲突策略拒绝整个恢复或跳过明确不满足条件的引用回补，真实提示结果，不覆盖新内容。交回需区分“整次拒绝”和“部分引用回补被拒”，不能统称全部恢复。
- 撤销取消/失败/双击时不产生重复对象；切空间后不把上一空间的撤销作用于当前空间。
- 不要求刷新后恢复不存在的lastDeleted记录；这一边界必须如实说明。

## 5 备份与恢复：走真实文件和真实页面

### 5.1 正常往返

从数据管理页触发ZIP下载，记录实际文件字节与SHA-256；通过文件选择控件上传同一ZIP，经过检查预览、输入恢复空间名、确认恢复和进入新空间。不能只拷贝JSON或直接调用prepareRestore代替整条链。

预览、取消、换文件阶段不创建空间、不写业务记录、不自动切空间。恢复提交阶段沿用既有作业规则，不增加“可中断一半写入”的按钮。

恢复后核对：

| 对象/事实 | 比较规则 |
| --- | --- |
| 空间与记录ID | 新空间、新ID；不能只换workspace_id导致覆盖原记录。建立源ID→目标ID对照，包含图片来源、资料、任务、行动、安排和会话 |
| Task截止 | value、precision及已有来源关系正确保留/映射；无截止仍无截止，不补23:59 |
| PlanItem↔FocusSession | 每段plan_item_id指向目标安排；安排focus_session_id指向目标空间最近已结束会话，且该会话反向指回安排 |
| 多段累计 | 独立按会话明细求和后floor一次；不得重复累计；无历史null与不足一分钟0仍可区分 |
| 成果与历史 | 正文、卡点、结果、起止时刻、历史task/action快照保持原事实，不用当前任务字段覆盖 |
| 已删对象历史 | deleted引用保留语义，不偷偷创建已删Task/Action补齐引用，不因名称相同绑定其他活对象 |
| 图片等资产 | 解压资产/恢复后的Blob字节或哈希一致，页面能打开；不能只比记录数量 |
| 非业务状态 | 不导入旧owner/租约、focus请求台账、plan_ops或页面草稿/待重试表单；恢复时只重建现有协议规定的最小协调记录 |

ID对照和摘要验证应使用独立断言，不能只调用被测remap/summarize函数再把它的返回值当唯一答案。可同时调用生产校验作为额外检查。

在没有运行定时写入的正常分支，比较恢复前后源空间完整快照和资产哈希，证明原空间不变；再在恢复空间修改安排、写一段成果，证明源空间不随之变化。

### 5.2 未结束工作恢复

运行中导出应通过第二页面的数据管理入口获得一致快照，不绕过第一页面的运行中离开保护。暂停导出另测。备份只含已持久化内容，不承诺抓到页面未保存输入或之后产生的检查点。

- 未结束v1恢复为running=false、timer_anchor_at=null，保留已存正文、累计和首次started_at；outcome/ended_at仍为空。
- 新空间运行位为空，恢复占位持有者不能等同于当前页面，租约过期；打开恢复空间不自动计时。
- 按现有takeover→recover→显式继续路径恢复操作；备份到恢复之间的空档不计入投入。未结束记录不能假装成已结束摘要。
- 源空间若仍在另一页运行，恢复操作不得修改其会话或运行位；尝试在恢复空间继续时仍遵守全局运行互斥。为进入新空间而执行的用户明确暂停要单独记录。
- 运行源空间的自然检查点会更新累计与runtime，不能机械以所有字节不变作为断言。此分支区分合法计时写入与恢复造成的越权变更；源空间严格逐字段不变另在静止分支证明。

### 5.3 失败与重试

- 明确事务中止：至少在末端写入或配额不足处注入失败，验证目标目录、sources、docs和runtime没有半套残留，源空间不变。
- 已提交但成功反馈/后续读取失败：先核实原恢复作业，同一次operationId重试只返回同一个空间，不重复写入。
- 用户明确“再恢复一份”是新意图，应创建新的独立空间；不能把同一ZIP文件全局永久去重。重复同一作业与重新恢复同一文件必须分开测。
- 文件受损/资产哈希不符/非法跨记录引用：准确拒绝，不写库、不建空空间、不悄悄丢弃坏记录后宣称完整恢复。
- 保持现有校验限额和兼容范围，不能为让测试通过放宽导入器。

## 6 离线、北京时间与多空间

### 6.1 离线承诺

验收口径是**应用已加载后的断网使用**。真实设置浏览器网络离线后执行手动安排→选行动→开始→写成果→暂停/继续→结束→返回日程→本地ZIP导出/恢复，检查本地路径不依赖模型或业务后端。记录意外发起的请求与本地成功结果，不把健康检查失败当成本地功能失败。

首次离线打开页面、关闭浏览器后离线重启不在当前承诺内，不能用缓存偶然命中宣传已具备完整PWA离线能力。断网后恢复网络，再验证不会自动补发旧begin/end、重复会话或重新累计。

### 6.2 日期和时间

- 默认日期读取操作发生时北京时间今天，操作跨午夜则重新核对，不固定为页面初次加载日期。
- 明确区分安排日、任务总截止、真实执行起止时间：修改或另建安排不改总截止；提前/延后执行不迁移原安排日。
- 受控时钟覆盖北京23:59→次日00:00，另选至少一个非中国浏览器时区做日期显示对照，防依赖宿主本地日期。
- 已打开开始确认跨午夜需要重新核对。已有计时仍按真实经过时间/既有恢复规则结算，不能在午夜自动完成或自动移到新安排。
- 模拟时间跳变和午夜显示测试分开：冻结/跳钟导致RECOVERY_REQUIRED时按既有规则核对，不绕过它制造通过。

### 6.3 空间和页面切换

- 用虚构个人、演示和恢复空间验证隔离；不得把同名Task/Action或类似标题当相同对象。
- 页面A提交后延迟返回，页面B或当前页切到另一对象/空间：旧结果不能跳走新页面、清理新草稿或显示错误空间的成功；原空间保存事实仍可重新读取。
- 离开正在工作页沿用保存/暂停/取消保护。切空间、前进后退、同组件换sessionId都要覆盖，不能只测路由卸载。
- 接管、恢复、成功重放只执行用户确认的操作；不会因为进入恢复空间或点击“回到工作”自动续计时。

## 7 旧数据和异常路径

这些分支采用独立fixture，不污染正常ZIP基准：

| 样本 | 必须验证 |
| --- | --- |
| 已结束v0/v1 | 只读历史、备份恢复保留原事实，不补造缺失快照，不批量升级 |
| 无安排的未结束v0 | 沿用显式遗留结束，释放占用，不新增自动Action完成 |
| 有有效活安排的未结束v0 | 显式选择安排进度，legacyEnd同事务保存摘要，仍不升级版本或套用v1行动完成承诺 |
| v0失效关联/安排终态 | 沿既有例外可显式结束释放占用；提示无法更新安排，不修造关联 |
| 正常v1关联损坏 | 保留正文和错误，不能降级legacyEnd或拆成两次保存 |
| 旧planned有结束历史 | 开始和删除均要求核对进度；处理后才继续，不自动改partial |
| 异常累计/结束时间/引用 | 明确待核对或拒绝，不能当零分钟，不自动修历史 |

只有当前导入兼容规则允许的旧数据才要求ZIP成功恢复。对于协议外脏样本，正确拒绝也是通过条件；不能把“应用内遗留释放占用例外”误解为“所有非法ZIP都必须导入”。

## 8 验收矩阵和证据标准

下列每项要给结果、复现入口、证据和未覆盖分支，不能仅汇总“全部通过”。

| 编号 | 重点链路 | 最小证据 |
| --- | --- | --- |
| C01 | 页面生成多天多段基准 | 真实UI路径、对象ID清单、真实计时明细、独立累计断言 |
| C02 | 行动/安排结果独立与六种组合 | 复用2B证据并核对适用版本；至少真实多段链验证Task不自动done |
| C03 | 运行/暂停时删除与完成保护 | 两种状态、相关入口、拒绝原因与零破坏写入 |
| C04 | Task/Action删除后的历史 | 页面可读、引用状态、正文/快照/累计保持 |
| C05 | 便签联删与取消 | 影响预览、确认与取消、引用闭合；无自动跳过关联Task |
| C06 | 正常撤销与冲突撤销 | 原ID恢复、拒绝覆盖后来修改、作用域与现有撤销边界 |
| C07 | 删除确认期间范围或会话变化 | 双页共享库复现；事务重查拒绝旧确认 |
| C08 | 真实ZIP正常往返 | 下载文件及哈希、页面上传恢复、映射关系、资产、原空间对照 |
| C09 | 删除后历史ZIP往返 | deleted关系不复活、成果可读、无活引用悬空 |
