## 1. 问题陈述（现状冲突）

- 已定删除规则：便签联删任务、**保留专注历史**；阶段 3A 已把 Action 纳入同批删除/撤销。
- 契约 `FocusSession.task_id / action_id` 为**必填活引用**，且历史**没有标题快照**。任务/行动被物理删除后，已结束会话的引用不可解析，违背引用闭合要求。
- `PlanItem.task_id` 同为必填活引用；`PlanItem.focus_session_id` 是单值快捷引用，多次执行时不能把最后一条当全部历史（设计文档第 114 行已指出）。
- 结论：**不先定历史引用契约，就不能接入正式执行历史**（不能先上线会话再补删除语义）。

## 2. 提案核心规则

1. **历史不可变快照**：FocusSession 增加结束时刻冻结的展示快照；删除活对象后历史仍可读。
2. **活引用显式断开**：对象删除后，已结束历史的活引用置为「已断开」状态而非悬空字符串；原始 id 如保留必须明确标注为历史标识，不当作有效活引用。
3. **未结束会话先行处理**：删除任务/行动/便签联删时若存在 running 会话，先提示结束/取消，再执行原确认删除流程；不静默把联删改成「删除不了」。
4. **事务同步**：删除、联删、撤销在事务内同步处理 Action、current_action_id 与历史引用断开/恢复；撤销不覆盖删除后新产生的记录（沿用 3A 冲突感知规则）。

## 3. 最小契约变更建议（字段级）

### 3.1 FocusSession（新增 3 个可选字段，全部有默认值，向后兼容）

```
task_snapshot:   TaskSnapshot | None = None     # 结束时冻结；running 时必为 None
action_snapshot: ActionSnapshot | None = None   # 同上
refs_detached:   bool = False                   # 活对象已删除、引用显式断开
```

其中快照为**不可变值对象**（新模型，非活引用）：

```
TaskSnapshot:   { title: str, matter_title: str | None, deadline_value: str | None, captured_at: str }
ActionSnapshot: { text: str, minutes: int, captured_at: str }
```

校验规则建议：
- `running=True` 时两个 snapshot 必为 None、refs_detached 必为 False（进行中必须持活引用）。
- `ended_at != None` 时 snapshot 必填（结束即冻结，杜绝事后伪造）。
- `refs_detached=True` 时 snapshot 必填（断开后靠快照可读）。
- task_id/action_id 保持必填字符串不变：断开后仍存原 id 作为**历史标识**，由 refs_detached 声明其不再可解析；UI/校验不得再按活引用跳转。

### 3.2 PlanItem（1 个可选字段）

```
task_snapshot: TaskSnapshot | None = None   # 条目创建时冻结标题；任务删除后计划历史仍可读
```

`focus_session_id` 单值语义**明确为「最近一次会话的快捷引用」**，全部历史以 `FocusSession.plan_item_id` 反查集合为准；不新增数组字段（避免双份事实来源）。

### 3.3 Task / Action / 删除语义

- Task、Action 字段**不变**。
- 删除计划（deleteTaskPlan / cascadeDeleteNotePlan / deleteActionPlan）扩展：同事务内把关联已结束会话置 refs_detached=True（快照已在结束时冻结，无需删除时补写）；running 会话存在时 plan 抛错 → UI 先引导结束/取消。
- 撤销（undoDeletePlan）扩展：恢复活对象时把对应会话 refs_detached 复位 False；期间新产生的会话不动；冲突拒绝规则不变。
