## 1 产品目标与范围

交付：从已有任务安排某天做什么 → 一张周表看到每日工作与截止 → 开始执行 → 记录实际投入 → 确认当日安排结果 → 未完成时再安排另一日。

上半区来自PlanItem.date，回答“这天准备做什么”；下半区来自Task.deadline，回答“这天最晚要交什么”。两者关联同一Task，不能互相推导或自动改写。

首版手动按天安排，不排小时槽，不做拖拽、周期任务、自动滚动到明天、AI生成或七天规则规划；不新增多个交付里程碑契约。若某任务有多个真实交付节点，不能用多条工作安排假冒多个截止；该能力另行设计。

无业务后端新API，优先沿用0.4.0的PlanItem、FocusSession.plan_item_id，DB仍v3。允许必要前端领域/事务/执行表单/备份联动修复；不得私塞未定义业务字段。确需改契约先交明确差异与迁移提案，不能以“前端功能”为由绕过契约闸门。

## 2 数据与关系

```text
Task（总目标、总截止）
 ├─ Action（可执行步骤）
 └─ PlanItem × 多条（某一天的工作安排）
       └─ FocusSession × 多段（本次实际选择了哪个Action、投入与成果）
```

| 对象 | 权威事实 |
| --- | --- |
| Task | 总标题、状态、总截止、归组；无截止也可安排 |
| Action | 实际步骤身份与完成状态；同一行动可以多天继续做 |
| PlanItem | 日期、工作说明、预计分钟、安排进度、稳定顺序；只属于一个任务 |
| FocusSession | 实际执行行动、计划关联、已保存用时与成果；全部会话由plan_item_id反查 |

PlanItem没有action_id：action_text是**这一天的工作说明**，不是Action身份。选择已有行动可复制文本和估时作为初值，但改名不建立隐含ID绑定；不得靠同名文本匹配行动。

沿用字段：id/workspace_id/task_id/date/planned_minutes/action_text/state/actual_minutes/focus_session_id/order/task_ref_state。新建默认planned、active、actual_minutes=null、focus_session_id=null。日期须真实日历日期，预计分钟为正整数。

不新增计划ID数组或第二份会话清单；不把计划字段塞进Task。任务安排改变不改Task.deadline、字段确认事实或原始便签。

## 3 统一日程布局

```text
11.23—11.29       上周 / 本周 / 下周       ＋安排工作

              周一         周二          周三       ……
每日任务      查资料       写报告初稿     整理图表
              实验报告     实验报告       实验报告
              预计30分     预计60分       预计30分

──────────────────────────────────────────────
每日截止                   提交申请                    报告截止
                           18:00                      当日截止

待安排 / 以前未完成 / 全部任务（紧凑入口）
```

### 桌面

- 同一日期表头、同一组7列、上下两条区域，水平对齐；不再分成两张独立周表。
- 每日任务占主要高度；每日截止是清楚但紧凑的底带，不能被上方空白挤出首屏。
- 上方工作卡首行工作说明，下行任务名，再显示预计/实际投入与安排状态；有总截止时显示简短“总截止11/27”标签。
- 本日任务密集时最多默认3条并有“还有N项”；展开列内限高滚动。底部截止仍能访问，不能随展开无限向下漂移。
- 无安排显示“未安排工作”；无截止显示“暂无截止”，不能用一句“今天没事”混淆。
- 已完成/取消安排默认折叠为数量入口，可展开回看；Task已完成的截止淡化并标记完成，不删除历史。

### 手机

保留七日日期条，选一天后**上下同时呈现“每日任务”和“每日截止”**，不做两个互斥Tab。今天/选中日样式区分；长标题换行，按钮不挤压正文成竖排。

主导航继续日程/资料库/待核对。当前“周 / 列表”可保留作为布局选择：列表模式也按天显示两区；旧view=list链接仍可打开。不能重新引入“截止 / 我的计划”的含义切换。

### URL与返回

date仍定位北京周/选日，跨周、后退、刷新和任务详情返回恢复一致位置。可增加plan参数定位某条安排，但必须验证其工作区/所属任务；无效或跨空间说明后回合法列表，不自动创建。

旧undated链接可定位到待安排/无截止任务区域，不能丢弃入口。进入任务、执行、历史后返回同周同日，切空间后清旧详情和计划ID。

## 4 新建安排与任务入口

入口：任务详情“安排工作”、日程“＋安排工作”、某日列“＋安排到这天”。均打开同一轻量表单。

| 字段 | 规则 |
| --- | --- |
| 所属任务 | 必选已有未完成Task；任务详情入口锁定该任务，日程入口可搜索 |
| 日期 | 日期列入口默认该日；其它入口默认实时读取的北京时间今天，允许修改 |
| 工作说明 | 必填；可从该任务已有行动带入，或手工填写 |
| 预计分钟 | 正整数；带入行动估时或30分钟初值，用户确认后才落库 |
| 总截止 | 只读展示来源Task；修改截止回任务详情，不在安排表单静默回写 |

本轮不把创建Task/Action与创建安排混成一个复合表单。找不到任务给“先创建任务”入口，保留返回上下文；不能保存无task_id的安排。

同一任务允许跨天、多条安排，也允许同日多项不同说明。完全相同的任务/日期/说明已有未取消安排时给重复提示；用户明确仍要添加可新增，不能按内容永久去重。双击同一次保存必须只一条。

新建写事务读取最新Task及空间，任务已删除/已完成则拒绝；blocked任务可安排但标记受阻，执行仍按既有显式恢复确认。成功后定位目标日与新增卡，失败保留表单输入。

## 5 截止与安排的联动提示

| 情况 | 行为 |
| --- | --- |
| 无截止Task | 可以正常安排；下区不伪造截止 |
| 安排日早于截止北京日期 | 正常展示，不宣称估时一定可行 |
| 安排日与截止同日且截止含钟点 | 提示“当日XX:XX截止，请确认安排来得及”；按天计划不承诺小时可行 |
| 安排日晚于截止北京日期 | 明确提示超出截止，用户可改日期或显式确认保留 |
| 截止已逾期 | 保留真实日期，提示核对；不自动延期或制造已满足过去截止的假状态 |
| 总截止改变 | 重新计算各卡风险，原安排日期不变，不自动批量重排 |
| 没有安排/只有过去安排/已有未来安排 | 分别标“尚未安排 / 待续安排 / 已有后续安排”，不能只要无本周卡就说尚未安排 |

今日强调用品牌色；临近/同日风险用橙色，晚于截止/逾期用红色并带文字。日期型截止只显示当日截止，不补23:59；实际日期时间按北京换算后落列。

下区总截止来自唯一Task.deadline，每任务最多一张总截止卡；不能按PlanItem条数重复生成截止。点击总截止进入任务详情，点击上区工作卡打开安排详情/执行入口。

## 6 安排进度、改期与取消

首版用户可操作的安排状态：planned待执行、partial部分完成、done完成、cancelled取消。moved沿用已有数据的只读显示，不在没有改期来源/目标关系字段时伪造可追溯的改期链。

状态要区分“过了计划日期但尚未完成”和“任务超过截止”。前者提示待处理，不自动滚到今天/明天，不自动判任务逾期或失败。

### 尚未执行的安排

无关联Focus且state=planned，可以编辑说明/估时/日期；普通改期保留同一PlanItem ID，更新目标日期及稳定order，Task截止不变。改变所属Task不支持，需取消后另建。

取消要确认，保存为cancelled而非硬删除；不删除Task/Action/成果。有引用的PlanItem尤其不能直接删除。

### 已开始或已投入的安排

- 有任何未结束关联Focus时，先处理本次工作；不能在执行中改日期/取消/改说明，使正在写的上下文漂移。
- 有已结束Focus后，原日期/工作说明/预计分钟作为当日历史保留，不覆盖改期；提供“另安排一天”新建未来PlanItem。
- 新一天的说明/剩余分钟由用户确认，不能默认把原预计再减一次历史用时。原条目保留partial，或用户明确done/cancelled，实际成果不删除。
- 已投入的条目不能恢复成“从未执行”的planned；done/cancelled如果要继续做，明确创建新安排，不偷偷重开旧历史。

无专注记录也允许用户明确完成/部分完成安排，实际用时显示“未记录”，不能把预计分钟伪装为实际投入。完成安排不完成Action或Task。

## 7 从安排开始执行

开始执行必须绑定三件事：同空间Task、该任务的有效Action、当前PlanItem。action_text不同于Action身份，不自动取列表第一项或按同名猜测。

首版执行确认展示工作说明与任务当前行动：有合法当前行动时可确认执行；没有或想换行动，提供回任务详情选择/新增当前行动的入口，并携带plan与原周日上下文。选行动只是修改当前选择，未begin成功前不声称已经开始。

再次确认时事务内校验PlanItem仍active、状态planned/partial、Task/Action合法，目标空间未变化。done/cancelled/moved/已删引用的安排不能新开工作。计划日期不是实际开工锁：提前或延后执行可以明确确认，实际started_at按真实时间，原计划date不自动变化。

调用现有focus服务传入planItemId；服务目前只检查计划存在/任务一致，必须补本批新增的状态与引用校验，不只靠UI禁用。

已有同一PlanItem未结束Focus时“回到工作”而不是新建；同空间另一会话或跨空间运行冲突沿用既有规则，不把同Task不同PlanItem混成一项。回到暂停会话是导航，继续计时仍由用户点击。

Task详情直接开始且没有计划上下文，保留plan_item_id=null，不按日期/任务名自动吸附到某条安排。先独立开始的会话本批不支持事后改挂计划。

## 8 结束与实际投入：两个结果分别确认

从计划进入的执行页头部显示“计划日期、工作说明、总截止”，保持草稿为主。结束表单保留原有**行动结果**（完成/部分/阻塞）；另增加清楚的**本次安排进度**选择：

- “这项安排已完成”→PlanItem.done。
- “还需要继续”→PlanItem.partial，默认选此项且在确认前可见。

用户提交结束即明确确认这两个独立结果。Action完成不推断计划完成；安排完成不推断Task完成；blocked仅表示这次会话卡点，不私自增加PlanItem.blocked状态。partial后可继续同一安排的新段或另安排一天。

这次最终正文、计时、Focus结束、显式Action完成、安排进度与统计摘要须在**同一focus事务**中提交；失败整组回滚，UI表单与输入保留，重试沿用同一信封。不先end成功再用第二事务补PlanItem结果。

### 汇总规则

- 所有已结束会话从FocusSession.plan_item_id反查，按session ID去重；未结束段不混入已记录历史累计。
- `actual_minutes`契约是整数：先求所有已结束accumulated_ms之和，再向下取整为分钟，只取整一次。UI可按总毫秒显示分秒；不足1分钟显示“<1分钟”，不能当成没有记录。
- 没有已结束记录时actual_minutes=null；有结束记录但不足1分钟时为0。预计与实际分别标注。
- focus_session_id只指最近一次**已结束**会话；按结束时刻并用ID稳定处理同刻。不写入running会话，不用最后一段用时代替全部汇总。
- end重试/迟到回调不重复累加；以最新全量相关会话计算，不做无前提的`+=本段分钟`。
- 任务详情可汇总本Task全部投入，日卡只汇总本PlanItem；跨天新安排不继承原条目会话，以免同一投入算到两天。

## 9 删除、撤销、旧计划与备份

计划属于已有删除/恢复闭环，本轮必须同步验证，不能延期到4-3。

### 引用保护

现有删除规则会移除state=planned的PlanItem。新增真实执行后必须按**实际Focus引用**检查：

- 未执行planned且没有任何Focus引用，删Task时可随Task移除，并在撤销快照保留。
- 有未结束Focus，先按3B保护处理，取消/失败不删除。
- 有历史Focus引用的PlanItem必须保留，不能按state盲目移除造成Focus.plan_item_id悬空。
- 若旧/导入数据出现planned但已有结束Focus，不能静默删条目或自动改历史状态；引导用户先确认安排进度，再重新确认任务删除。新UI结束流程会显式落partial/done，避免新产生这种未确认状态。
- 已执行/取消等历史随Task删除断task_ref_state，保留计划与成果；撤销只回补本次引用，不覆盖后来工作。删除Action不能删除相关PlanItem。

源Task从另一页被直接完成/删除时，新建/执行事务读最新事实拒绝；已结束历史仍能看。不因页面已有对象就允许跨空间开始。

### 已有计划兼容

现存PlanItem原样可读；state等缺省按契约解释，不因本批UI接入批量重写。moved/cancelled等放历史区域；task_ref_state=deleted只读，不能作为待安排活任务。旧汇总与明细不一致时明确标记待核对，不自动用今天信息重写已备份的历史事实。

### 备份与恢复

不新增契约字段的情况下沿用已有适配路径；有必要新增本地字段先说明并补白名单与往返校验，不能静默遗漏。

至少实测：同任务多天安排、多次执行、部分完成/取消/历史引用、计划快捷会话及实际分钟 → 真实ZIP导出 → 新空间恢复 → 原库不变、引用重建、上下区展示正确；运行/暂停恢复仍待核对、不自动计时。

## 10 交互与视觉约束

保留当前米白底与暖色，主要精力用于统一日期轴与上下分工。去掉重复标题、套层卡片和常驻技术说明，不增加多套Tab、工具栏或第四主导航。

每张安排卡默认只展示工作说明/所属Task/预计与实际/必要风险，点击后看详情和操作；改期、取消放更多操作，日期格不塞一排删除按钮。开始/回到工作是明确入口，保存状态仍准确可见。

“待安排”面板列有未完成Task且没有未来有效安排或需要续安排的任务，包含无截止与远期截止；“全部任务”仍可到达全部Task，不只剩本周截止。已安排过也可继续安排下一天，不能从待安排消失后再找不到。

过去未完成安排提供“另安排一天 / 取消 / 保留待处理”，不自动新建下一日。空间、日期、搜索与展开状态不串到另一空间，异步成功不能清掉后来输入。
