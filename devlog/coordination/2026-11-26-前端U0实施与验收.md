# 前端 U0 实施与验收

日期：2026-11-26。状态：U0 已实施并通过本阶段验证；U1–U5 尚未实施。

依据：[前端体验整理实施方案](2026-11-26-前端体验整理实施方案.md)。本阶段仅处理可恢复基线与已证实的导航、移动布局缺陷。入口收敛、任务总览和说明文字整理将在后续阶段进行。

## 1. 实际修改

### 改排返回保留来源

任务详情进入助手时携带规范化的当前任务地址，包括合法的安排 ID 和原列表来源。改排入口、草案中的“原任务页”及采用后的“查看任务”共用受限返回解析。

新增 `resolveReplanReturn`：只有当前空间存在的当前任务可作为返回目标；继续复用既有路径白名单、安排归属与嵌套限制。其它任务或非法来源回退当前任务，当前任务不存在或跨空间时回日程。

实际复测：指定日期列表 → 带安排上下文的任务 → 改排 → 刷新入口 → 返回任务 → 返回日程，日期和视图保持。创建草案、刷新后重新打开、正式采用后也保留这条返回链。

### 修复创建草案后的入口地址残留

完整复测发现，`startReplan` 会先设置活动草案，使入口面板卸载；单独依赖该面板随后发出的 `started` 事件，可能不能完成入口地址清理。刷新时残留的 `replanTask` 又触发入口初始化。

现在由助手页面观察活动草案身份，在目标任务匹配时清理一次性入口参数并保留受限返回地址。草案业务状态、数据结构及采用规则不变。

### 修复助手草案的小屏横向溢出

修改前在 390px 视口，页面宽度为 531px。检查发现助手双栏网格只声明了桌面列数，小屏隐式列被内容的最小尺寸撑开。在浏览器仅将该网格约束为 `minmax(0,1fr)` 后，页面宽度即恢复为 390px。

正式修改为 `grid grid-cols-1 gap-4 md:grid-cols-2`。没有使用全局横向裁切隐藏内容。已检查编辑、预览、长任务标题、日期弹层与改排入口。
