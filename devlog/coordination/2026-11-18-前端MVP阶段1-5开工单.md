# 前端 MVP 阶段 1–5 开工单

## 任务归属

- 执行人：前端负责人。
- 后端状态：阶段 0 已冻结，阶段 6 等部署拓扑确认；本阶段不改后端源码、不新增后端接口。
- 联调方式：优先使用 `JXL_PROVIDER=fixture`，把后端 fixture 当稳定 mock。
- 交回方式：每个阶段完成后暂停，提交改动文件、测试结果、浏览器截图和未完成项，等待验收后再进入下一阶段。

## 当前基线

已有：

- 收集截图/文字并先保存原始资料。
- AI 分析、失败降级、原图保留。
- 字段核对、编辑、确认、原文引用。
- 从已确认截止时间创建任务。
- 刷新恢复、重复分析合并、删除便签时处理任务关联。
- Vue3 + Vite + Pinia + IndexedDB + hash 路由。
- 契约 `0.3.0` 已冻结，领域模型已包含 `Matter`、`Action`、`FocusSession`、`PlanDraft`、`PlanItem`。

## 阶段 1：数据层、工作区、北京时间输入

### 实施内容

- 复用现有 `workspace_id` 和 `is_demo`，至少支持 `personal` 与 `demo`。
- 所有 sources/docs 读取、写入、删除均按当前 workspace 过滤。
- 切换 workspace 后重载数据，不能残留上一个空间的选中项、图片 URL 或待保存结果。
- 如果需要新建 workspace 元数据，先评估 IndexedDB 版本迁移；不得清空已有数据。
- 日期输入改为日历控件，普通用户不需要手写 ISO 字符串。
- 空日期表单默认显示北京时间今天；只是表单初值，清空后保持空。
- 已有日期原样回填；用户保存/确认后才写入事实。
- 提供“今天/明天/7 天后”快捷按钮，必须由用户主动点击。
- 前端逾期、今天分组和日期显示统一按北京时间，不使用设备本地时区。

### 交回验收

- 切换 personal/demo 后数据完全隔离。
- 修改系统时区不会改变今天、逾期和日期分组结果。
- 刷新后日期不漂移，空日期不会被后端或前端静默补成事实。
- IndexedDB 迁移有测试，旧数据不丢失。

## 阶段 2：今天首页、收集箱、事项归组

### 今天首页 F08

- 显示北京时间今天。
- 展示今日到期、逾期、待核对、失败、今日计划和恢复入口。
- 支持待办/进行中/已完成筛选。
- 显示截止来源：便签、手动、无截止。
- 未确认字段不能作为已确认截止展示。
- 提供继续核对、重试 AI、手动整理、仅保存入口。

### 收集箱 F04

- 关键词搜索标题、原文摘要和来源名称。
- 按内容类型、分析状态、核对状态和日期筛选。
- 明确分组待核对、待确认、失败、已完成。
- 删除前列出受影响任务。
- 按用户追加定案：取消不修改；明确确认“删除便签及关联任务”后，同事务删除便签与 `note_ids` 或 `deadline.from_note_id` 引用的任务（按 ID 去重），列明共享任务将整体删除，原始资料默认保留。不再执行“截止被引用就禁止删除”的旧规则。
- 删除失败时界面和 IndexedDB 都回滚。

### 事项归组 F05

- 创建、重命名和删除事项。
- 便签和任务手动归入事项。
- 事项页展示资料、任务、截止时间和状态。
- 删除事项只解除关联，保留便签和任务。
- 先保持一条便签一个主要事项，不引入多对多关联表。

### 交回验收

- 一条资料可以从收集箱进入事项、任务和今天首页。
- 删除便签、解除关联、删除事项都有确认提示和失败回滚测试。
- 搜索和筛选刷新后仍然有效，不修改原始数据。

## 阶段 3：下一步行动与专注工作区

### 行动 F09

- 任务可以添加多个手动行动。
- 行动包含文本、预计分钟、完成状态和 `basis=user`。
- 可设置当前行动。
- 行动完成不自动完成任务；允许重新打开。
- 本阶段不做 AI 行动建议。

### 专注 F10

- 从任务或计划条目开始专注。
- 开始、暂停、恢复、结束。
- 使用 `started_at + accumulated_ms + running` 计算实际用时。
- 刷新后恢复正在进行的会话。
- 结束时选择完成、部分完成或被阻塞；阻塞必须填写卡点。
- 保存草稿内容、实际用时和结束结果。
- 专注不自动修改任务截止时间、确认状态或计划目标。

### 交回验收

- 关闭页面、刷新、断网后，专注记录仍可恢复。
- 行动、计划条目、专注和任务状态不互相误改。
- 计时以墙上时钟计算，不依赖前端计时器累计的次数。

## 阶段 4：基础备份恢复与演示空间

### 备份 F11

- 导出 ZIP，包含 manifest、sources、原图/文字、notes、matters、tasks、actions、focus_sessions、plan_drafts、plan_items。
- manifest 写入备份版本、契约版本、导出时间、workspace_id、数量和校验信息。
- 不导出 token、模型密钥和运行日志。
- 导入前完整校验结构、版本、图片和引用关系。
- 默认恢复到新 workspace，不覆盖当前空间。
- 任一步失败都不能产生半份数据。

### 演示 F12

- demo workspace 使用 `workspace_id=demo`、`is_demo=true`。
- 页面明确标注演示数据。
- 支持恢复演示初始数据。
- 清理 demo 不得触碰 personal。

### 交回验收

- 新浏览器空间导入后，原图、确认字段、任务引用、专注和计划完整。
- 导入损坏包不会改变当前空间。
- 退出 demo 后看不到 demo 数据，也不会污染 personal。

## 阶段 5：F13 离线规则规划

### 批量输入

- 至少支持 5 项任务。
- 标题必填；截止、预计剩余分钟、已完成分钟、最早开始日期可空。
- 支持是否允许拆分。
- 支持选择已有任务，避免重复创建。
- 缺少预计工时的任务进入待估计/未排程，不猜默认工时。

### 规则排程

- 固定未来 7 天。
- 用户设置每天可用分钟数。
- 默认保留 15% 缓冲。
- 使用确定性 EDD 规则优先安排截止较近的任务。
- 可拆分任务按天分配；不可拆分任务必须整体放入容量足够的日期。
- 无截止任务可保留未排程。
- 不能安排的任务进入 `unscheduled`，写明 `gap_minutes` 和原因。
- `gap_total` 必须准确，不能返回假完整计划。

### 预览与确认

- 草案和已确认计划分开保存。
- 可编辑日期、顺序、分钟数和行动说明。
- 实时显示每日已安排、可用、缓冲和缺口。
- 确认后写入 `PlanItem`，不回写 Task deadline/status。
- 计划条目完成不自动完成任务。
- 当天未完成只能由用户明确移到其他日期、保留待安排或重新规划。
- 计划条目可以进入专注工作区。

### 交回验收

- 刷新、断网、重新进入后，计划仍可读、可编辑、可执行。
- 排程结果在相同输入下确定性一致。
- 容量不足时明确显示缺口，不伪装成完成。

## 每阶段必须提交的证据

每阶段交回以下内容：

1. 改动文件清单。
2. 新增和更新的单元测试。
3. `npm run test`、`npm run check`、`npm run build` 结果。
4. 关键路径浏览器截图或录屏。
5. 失败、断网、刷新、重复点击和空状态结果。
6. 契约是否变化；没有变化也要明确写出。
7. 未完成项和下一阶段风险。

## 严禁提前做的事情

- 不新增规划、搜索、今天或专注后端接口。
- 不把 token 放入前端构建产物。
- 不擅自把日期改成设备本地时区。
- 不自动把 AI 推算值标为 confirmed。
- 不静默删除便签、任务或专注历史。
- 不插入 F06 变更检测、AI 归组、AI 行动建议、AI 排程和复杂依赖图。

## 开工任务

从阶段 1 开始，先提交：

- 当前 `frontend/` 基线测试和构建结果。

- IndexedDB 是否需要版本迁移的判断。
- 北京时间工具函数和测试方案。
- 阶段 1 完成后的浏览器验收路径。
