## F1 / P2：缺省 record_version 统一按 v0 解释

根因：领域规则 `recordVersion(s) = s.record_version === 1 ? 1 : 0`（缺省即 v0），但备份语义校验 `semFocusSession` 与关系校验 `layerC` 只在严格 `=== 0` 时走旧规则，缺字段落入 v1 路径，强制要求快照与引用状态，误拒合法旧历史。

修复（单一来源，不只改一处 if）：
- `services/backup/adapt.js` 新增导出 `focusRecordVersion(s) = (s.record_version === 1 ? 1 : 0)`，注释标明镜像 `domains/focus.js` 的 recordVersion。
- `services/backup/validate.js` 两处改用该 helper：`semFocusSession` 的 v0 分支判断、`layerC` focus_session 的 `const v0`。
- `services/backup/recovery.js` `buildRecoveryPlan` 也改用该 helper（原本 `=== 1` 已正确，统一口径防漂移）。
- **不改 `domains/focus.js` 产品域、不改契约**。校验只在投影/解释层按缺省 v0，绝不给原历史补快照、引用状态或升级 v1；旧记录缺省表示原样保留。

边界守住：
- 缺省/显式 0 的已结束与未结束记录均按 v0；旧引用缺失走已批准的非阻断预览说明（notes）+ 隔离历史映射，不伪造对象。
- 显式 `record_version=1` 缺快照仍必须拒绝（未把 v1 放宽）。
- 缺省版本但携带 v1 字段（如 task_ref_state）仍按 v0 混版拒绝（缺省不是无条件放行）。

## F2 / P2：matter 本地 updated_at 纳入适配

根因：契约 Matter schema 无 `updated_at`（additionalProperties:false），但 Matter 经通用 doc 机制可携带本地更新时间——`stores/app.js` 的 `mutateDoc` 通用盖 `draft.updated_at`，`domains/matter.js` 的 `migratePlan`/`setMatterPlan` 以 `...m` 保留既有字段。适配表 `LOCAL_ONLY_DOC_FIELDS.matter` 只投影掉 `kind`，漏识别 `updated_at`，合法事项被报未知字段。

真实写入路径审计（精确补表，不放开 additionalProperties）：
- Note / Task 的 `updated_at` 是契约业务字段（schema required），保留在业务核心，**不列入本地额外**。
- Action 域刻意不盖 updated_at（`domains/action.js:4` 注释「Action 契约没有 updated_at：编辑直接替换记录，不私塞未定义字段」），**无需补**。
- Matter 契约无 updated_at 而真实写入可携带 → 本地额外字段。

修复：
- `services/backup/adapt.js` `LOCAL_ONLY_DOC_FIELDS.matter` 改为 `['kind', 'updated_at']`：投影业务核心时去除，`docToBackup`/`docFromBackup` 克隆全量记录故备份与恢复往返保留。
- `services/backup/validate.js` 新增 `semLocalDocFields(d, ...)`，在 layerB 逐 doc 循环对**原记录**（core 已投影掉该字段）校验：matter 的 `updated_at` 存在时必须是真实 ISO 日期时间（`realDatetimeOk`，含日历/时刻/偏移合法性），非法仍拒。
- **不放开整个 additionalProperties、不删其它 schema 外字段**：业务核心仍按 schema 严格校验，matter 真正未知字段（如 foo）仍拒。
