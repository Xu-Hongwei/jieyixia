## 必须先修（公网或正式交接前）

### 1. 运行依赖与交接包不完整

`backend/app/validation.py` 已 `from PIL import Image`，但 `backend/pyproject.toml` 的运行依赖只有 fastapi、uvicorn、pydantic、httpx。已有 cleanenv 没有 Pillow，导入 `app.main` 即失败。修复方式二选一：把兼容版本的 Pillow 明确加入运行依赖并在干净环境重装验证，或移除 Pillow 依赖并采用经过完整损坏校验的替代实现；不能继续在文档中宣称“只装当前四个运行依赖即可启动”。

新增 `backend/app/time_rules.py` 当前不在 `handoff/截下来-前端交接-2026-11-17.zip` 中，交接包与工作树不完整。依赖修复后重新构建包，并逐文件核对。

### 2. 默认北京时间没有成为唯一执行规则

`time_rules.py` 已定义严格偏移校验和 UTC+08:00 解释，但 `backend/app/model/core.py` 仍直接调用 `datetime.fromisoformat`，未使用该模块。因此模型输出的 `+08:75` 当前会通过；naive datetime 仍只产生“由前端按用户时区解析”的旧提示。需要让请求校验、模型节点、deadline 选主和后续比较共用同一时间规则，并同步 README、HANDOFF、测试和交接包。

默认北京时间的边界必须保持：缺时区按业务默认 Asia/Shanghai 解释，但不伪装成原文明确写了 +08:00；原文明示其他时区保留实际时刻；date-only 不补 23:59。

### 3. 分析总预算要覆盖真实响应读取

当前适配器已改为流式读取并检查 deadline，但 HTTPX 的 read timeout 仍只限制两次收到数据之间的间隔。细分数据流可能让每个间隔都合法而总请求超过预算。需要用真实本地 HTTP 服务覆盖分段慢响应、无响应、错误响应和连接释放，并确保超时后响应与连接关闭。仅在读取完成后判断 elapsed 不算完成。

### 4. 图片校验与依赖形成闭环

Pillow 完整校验方向是正确的，但必须先解决运行依赖。测试应覆盖 PNG/JPEG/WebP 的正常图、截断图、只有文件头、损坏块、超像素图和畸形 data URL，并证明非法图在进入模型前调用次数为零。响应体也要设字节上限，不能把未限制的厂家响应全部拼接到内存后才检查模型输出字符数。

## 公网接入前需要补齐

### 5. 并发、频次和费用边界

当前没有 API 鉴权、访客频次、并发上限、共享额度或熔断。公网页面一旦连接真实模型，任何人都可以重复提交图片消耗额度。至少需要网关/API key/匿名演示配额中的一种组合，限制单 IP/会话频次和同时分析数，达到上限时返回现有降级错误并保留仅保存/fixture 体验。单进程信号量不能替代多 worker 或多实例的整体限制。

### 6. 同步模型调用的资源隔离

当前 API 是同步函数，模型适配器每次新建 `httpx.Client`，重试与退避使用 `time.sleep`。高延迟模型会占用线程池。应在公开部署前决定有界线程/信号量、客户端复用和优雅关闭策略，并验证取消请求时上游连接会释放。

### 7. 健康检查语义和发布配置

`model_ready` 只代表 profile 能装载，不代表厂家网络可用；文档已有说明，但部署上最好区分 liveness、配置 readiness 和最近调用状态。CORS 当前允许方法和请求头 `*`，公开域名必须用明确来源列表；生产环境还应确认 `/docs`、日志、代理和 HTTPS 策略是否符合发布要求。

### 8. 配置解析仍有宽松路径

当前 `_int_env` 对 `JXL_MAX_BODY_BYTES=-1` 和非数字会静默接受/回退；浮点配置需要拒绝 NaN/Infinity；profile 的 `base_url=123` 等类型也应在装载期拒绝。配置问题不能等用户第一次分析才暴露。为这些反例补配置测试，并记录实际启动失败信息。

## 质量与可维护性建议

### 9. 统一版本和发布标识

schema/API 目标是 0.3.0，但 `backend/pyproject.toml` 仍是 0.1.0。统一包版本、健康响应、README、交接包和比赛留档，避免前端收到 0.3.0 而部署元数据显示 0.1.0。

### 10. 增加请求关联和安全日志字段

当前日志记录 `source_id`，它来自客户端且没有长度/字符边界；没有 request_id、尝试编号和总预算结果。增加服务端生成的 request_id，限制 source_id 长度并避免把用户可控标识直接作为高基数字段。继续禁止原文、图片、密钥和上游完整错误进入日志。

### 11. 明确重试和模型输出策略

模型输出不合契约目前也可能触发 profile retries 和下一个厂家调用，可能重复计费。建议按错误类型区分：网络/429/5xx 可有限重试，认证错误不重试，结构化输出错误最多一次修复或切换，并把每次尝试成本和最终原因留元数据。

### 12. 契约与模型质量分开验收

209 项主要证明代码和结构约束；13/13 golden 主要证明离线解析回归。还需要一组脱敏语义样例评估：活动开始与提交截止混淆、无年份、跨年、混合时区、错误引用、应留空却给出具体日期。真实模型实测与离线重放分开记录，不把 fixture 通过等同模型质量。
