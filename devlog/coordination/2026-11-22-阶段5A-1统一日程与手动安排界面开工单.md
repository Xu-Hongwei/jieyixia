# 阶段5A-1：统一日程与手动安排界面开工单

日期：2026-11-22。状态：待实施方案，本轮只做设计，不表示页面已经实现。

前置：[5A-0最终人工验收](./2026-11-22-阶段5A-0最终人工验收.md)已通过。上位规则：[5A统一日程与手动安排](./2026-11-22-阶段5A统一日程与手动安排开工单.md)。本单细化界面接入，不重新定义5A-0数据规则。

## 1 本批交付与边界

用户能从已有任务安排某天做什么，在同一张七日日程表看见“每天准备做什么”和“哪天必须交付”，编辑、改期、取消或人工核对安排进度，刷新后仍然存在。

本批包含：统一周表及按天列表、安排表单/详情、任务详情入口、待安排与全部任务、手机适配、删除影响确认、返回定位及真实浏览器验收。

不做：从安排开始专注、自动绑定实际Action、结束专注时双结果提交、自动排程、拖拽、重复任务、小时槽、多截止里程碑、全站换肤、部署。现有任务直接开始工作及ContinueBar保留原行为；不把它们伪装成已关联某条安排。

本批人工“更新安排进度”仅复用已验收confirmProgress命令，独立于专注结果；5A-2仍负责开始/结束执行联动及其原子事务。不要因为有“安排完成”按钮就宣称整个5A完成。

继续使用Vue/Pinia/reka-ui和现有样式系统，不加UI依赖、不新增后端API、不改契约0.4.0或IndexedDB v3。允许薄UI适配和必要的接入修正；领域规则若真有缺口，单独说明反例及最小修复，不在页面另写第二套规则。

## 2 页面分工

| 位置 | 职责 | 主操作 |
| --- | --- | --- |
| 日程 /today | 看每日工作与截止、安排工作 | ＋安排工作 |
| 安排详情面板 | 看这一天具体做什么、投入与状态 | 编辑/改期/人工更新进度，按资格展示 |
| 任务详情 /tasks/:id | 看总目标、总截止、行动、全部安排与成果 | 安排工作；原有任务操作保留 |
| 待安排/全部任务面板 | 找没有本周截止的长期任务、远期任务和待续任务 | 安排到某天 / 查看任务 |
| 工作记录 | 回看真实会话成果 | 沿用现有入口 |

保留三项主导航，不增加“计划中心”或第四主导航。任务详情仍是总任务权威编辑入口，安排表单不编辑总截止，也不创建Task/Action。

## 3 构图与视觉规则

视觉主张：一张清楚的暖色周历，上半部摆每日工作，下半部标交付节点；层级靠字体、间距和分隔线建立。

内容顺序：紧凑工具栏 → 有内容时出现的继续/异常提醒 → 统一日程 → 待安排/过去未完成/全部任务入口 → 默认折叠的恢复入口。工作记录作为次入口，不与“安排工作”竞争。

交互主张：选日后定位当日；点安排打开详情面板；保存后定位落库结果。只使用短促的选中/展开/面板过渡，支持减少动态效果，不用动画阻塞保存或隐藏错误。

沿用当前米白底、暖色品牌及正文/日期字体，不叠加纹理、图片、渐变大背景、独立配色卡组或大面积阴影。安排卡作为真实点击对象允许保留；外层区域用同一工作面和细分隔，减少卡片套卡片。正文、日期、数字清楚可读，状态不能只靠颜色。

### 3.1 桌面示意

```text
日程                       工作记录  新建任务（次）  ＋安排工作（主）
11.23—11.29 · 北京时间                         上周  本周  下周

              周一          周二          周三        …… 周五
每日任务      搜集资料      写报告初稿    修改图表
              课程报告      课程报告      课程报告
              预计30分      预计60分      预计30分
              总截止11/27   总截止11/27   总截止11/27
              ＋安排        ＋安排        ＋安排
───────────────────────────────────────────────────────────
每日截止      暂无截止      申请18:00     暂无截止        课程报告
                                                         当日截止

本周 3项安排 · 2项截止
待安排  过去未完成  全部任务                         展开所需清单
```

这是信息结构示意，不要求照搬占位文案或制作小时网格。安排没有开始钟点，不显示假的09:00，也不把预计60分钟画成实际占用时间。

### 3.2 共用日期轴

- 只出现一次周范围和七日表头，上下区域严格对齐同一组7列。
- 采用共用列宽和统一行边界；不能在七个独立列内部各自堆叠后，让下方截止线随任务数量高低错落。
- 今日与选中日可同时识别。今日用品牌标记，选中日用边框/底色，不能两者混为同一日期。
- 上区默认每日至多3条，更多以“还有N项”展开，展开区限高滚动；下区保持可达，不随上方数据无限向下漂移。
- 下区默认每日至多2条紧凑截止项，更多单独展开/滚动，不吞掉其它截止。上/下计数分别展示。
- 无工作写“未安排工作”；无截止写“暂无截止”。日期型截止写“当日截止”，不能写“时间未定”或补23:59。
- 以1440×900和1024×768验证正常数据下上下区都能看见；密集数据有明确滚动入口。

### 3.3 手机与窄容器

七日日期条 → 当前选日 → 每日任务 → 每日截止，两个区域始终顺序呈现，不能改成互斥Tab。可用宽度不足以容纳7列可读内容时切为所选日布局；不得只按屏幕宽度硬塞被侧栏挤窄的七列。

360px宽无整页横向溢出，任务长标题可读，操作不能挤成单字竖排。详情/表单在窄屏可占大部分屏幕，内部滚动且提交区可见；不得压住输入框或超出可视高度。

## 4 读模型与卡片

使用usePlanStore.schedule/classify/summary/riskFor及app.docs/tasks；只维护表单草稿与展示状态，不复制一份计划业务库，不按DOM内容推算状态。

| 上方安排卡 | 下方截止项 |
| --- | --- |
| 工作说明为主，所属Task名为次 | Task标题为主 |
| 标“预计X分”，有真实记录时另标实际投入 | 标北京钟点或“当日截止” |
| 简短总截止标签及必要风险/安排状态 | 已逾期红色文字/边线；已完成淡化 |
| 点击打开该PlanItem详情 | 点击打开Task详情 |

工作说明默认至多两行，完整文本在详情可读；无hover设备也可查看。状态/截止/时间文字避免重复堆满卡片。不要在每张卡常驻一排编辑、改期、取消和完成按钮，操作放详情内。

actual_minutes=null显示“未记录”；存在结束会话但不足一分钟显示“<1分钟”，可在详情看分秒；不能把0误当无记录。计算有异常则展示待核对并阻止生成权威结果，不用有效子集冒充全部投入。cacheMismatch显示明确的核对提示，读取不自动改库。

done/cancelled/moved、Task完成后旧安排、断引用历史按日折叠在“安排历史N项”，保留状态与只读原因。Task已删除时用“原任务已删除”或真实现有快照，不虚构任务标题，不留下无效可点击入口。首版不创建moved状态。

## 5 安排表单与详情

建议一个共享PlanEditor，模式为新建/编辑/改期/另安排一天；一个PlanDetail面板展示记录与可用操作。日程、任务详情、待安排入口均复用，不能各写一套提交逻辑。

### 5.1 新建入口与初值

| 入口 | 初值 |
| --- | --- |
| 日程主按钮“安排工作” | 实时北京今天，Task可搜索选择 |
| 某日“＋安排” | 默认该列日期，Task可搜索选择 |
| 任务详情“安排工作” | 固定该Task，默认实时北京今天 |
| 待安排Task的“安排” | 固定该Task；若用户明确选“安排到当前选日”则带入该日，否则今天 |
| 详情“另安排一天” | 固定该Task，默认原安排次日与北京今天的较晚者，用户可以改；说明/分钟重新确认 |

表单包括：所属任务、按天日期、工作说明、预计分钟，以及只读总截止。任务选择优先未完成Task，支持搜索，blocked可选但标受阻；已完成Task不能新建安排。

可选择“从已有行动带入”作为文字/估时初值，不形成行动ID绑定，不自动修改当前行动。没有行动也能手工写工作说明。预计分钟可初填30，必须由用户提交确认；清空不自动变30，拒绝小数/0/负数/非法值。

复用DateInput日历选择，安排表单只选日期，不提供时间输入；不能把DateInput的空值显示今天当成已有事实。新建打开时显式初始化合法date，清空后展示必填错误；新开表单重读今天，午夜不能改掉已编辑日期。

无Task时给“先创建任务”入口，必要时先确认放弃草稿；不要在同一表单里隐式新建Task或Action。任务总截止只读，可回详情修改，安排保存不回写截止。

### 5.2 可用操作

| 当前事实 | 界面行为 |
| --- | --- |
| planned、活Task、无任何Focus | 允许编辑说明/估时、改日期、取消、明确人工确认进度 |
| partial且无未结束Focus | 可确认进度、取消、另安排一天；不覆盖原说明/日期/估时 |
| 有未结束Focus（含暂停） | 主要引导查看已有工作；禁止改期/编辑/取消/手工确认；导航不自动继续计时 |
| 已有结束Focus | 原日期/说明/估时保留；可核对进度、取消或另安排一天，不迁移原成果 |
| done/cancelled/moved | 历史只读，可为仍有效Task另建安排，不提供“恢复待执行” |
| Task完成/删除或断引用 | 历史只读，动作按领域资格限制；不承诺另建一定可用 |

取消安排必须确认，明确说明“只取消这项安排，任务和成果保留；后续继续请另建安排”，保存cancelled，不硬删PlanItem，不提供未实现的撤销取消按钮。

人工更新进度放详情次操作，用户明确选“部分完成/已完成”后确认；文案必须写“这项安排”，不写泛化“完成任务”。有历史时展示真实摘要并回传确认；异常历史先核对，不用人工确认绕过。整个Task完成仍走Task原独立入口。

新增/改期成功定位目标日和该卡；人工完成/取消后，该条进入当天历史，应保持可定位并说明去向，不能保存成功后像丢失一样突然消失。

## 6 截止、重复内容与确认流程

复用5A-0风险计算；总截止只来自Task。无截止照常安排，同日钟点提醒核对，晚于截止明确二次确认。过去未完成不等于Task逾期，不自动滚到明天。

同内容重复先展示已存在条目的日期/说明与数量；用户明确“仍要添加”才按新意图提交。匹配集合、截止或历史变化后重新展示，不自动补确认参数直至成功。

UI适配必须注意实际字段形状：

- 风险返回deadlineValue/deadlinePrecision/planDate；deadlineConfirm需要`{value, precision, planDate}`，明确映射，不能原样塞risk对象。
- 历史确认通过既有historySignature构造，显示摘要对应提交的真实字段，不从中文分钟字符串反算毫秒。
- edit/move/cancel/confirmProgress提交完整相关字段expected：task_id/date/state/action_text/planned_minutes/task_ref_state（缺省active规范化）；不传空快照。

对话框生命周期必须稳定：不要AlertDialog自动关闭时先清target，再让confirm读取空对象。操作目标、快照和本次输入在确认之前固定；异步失败时可重新打开相同事实或明确要求重新核对。

## 7 保存、重试、陈旧页面与切空间

每次明确提交：表单校验 → 固定本次输入 → 签发一次信封 → 调用服务。不能在每次render/watch里签发，也不能双击产生两个新意图。键盘Enter与按钮共用提交入口；saving期间重复提交不新建操作。

- 同一失败重试沿用requestId、issuedAtMs、planItemId和不可变输入；用户修改字段/新增确认事实后属于新意图，重新签发。
- 信封使用store.issueRequest返回的规范化input；不要只取requestId又漏掉固定date/planItemId。
- 保存状态显示未保存/保存中/已保存或明确错误；拿到提交结果与最新事实后再报成功，不用动画代替落库。
- 表单持有workspace/目标ID/draftEpoch；晚到结果不关闭新表单、不清后来输入、不跳到另一空间或日期。
- STALE_PLAN保留用户草稿，展示当前值供核对，用户确认后再基于新快照提交，不能无提示覆盖。
- TASK_DONE/RELATION_INVALID/PLAN_HAS_HISTORY/UNFINISHED_FOCUS等按实际事实解释，保留输入；去已有会话仅导航，不自动计时。
- 保存可能已提交但结果/刷新失败时，保留原信封并显示“保存结果待核实”，先按稳定ID核实或原信封重试，不能重新生成ID。

对已提交但结果待核实的操作，可用工作区隔离的sessionStorage暂存完整请求信封与不可变输入；恢复页面只提供核实/原请求重试，不自动重放。它不是业务记录，不写进备份，不给未提交草稿创建假事实。清理只清本次对应请求，不误清后来的提交。存储不可用时诚实提示先查看列表核对，不宣称刷新后自动恢复。

未保存表单关闭/跳页应明确放弃或继续编辑；浏览器刷新提供适用的未保存提示。切空间按现有全局规则处理：表单数据不得带入另一空间，已提交请求只属于原空间；不得因watch触发而将旧输入保存进新空间。

## 8 URL、返回与旧入口

沿用hash路由及/date/view/undated语义。可用`/today?...&plan=<id>`定位安排详情，不另加一级主页面。仅在app.ready后验证对象，并检查当前空间；无效/跨空间ID提示后移除非法参数，不自动创建记录。

| 操作 | 结果 |
| --- | --- |
| 周内选日/跨周 | URL与实际周/选日一致；显式切日时清理不再适用的安排详情参数 |
| 点安排 | 打开该安排详情，保留原周/选日/布局/筛选 |
| 查看所属Task | 跳任务详情，return指向原日程上下文（可含plan以返回详情） |
| 从任务详情安排工作 | 复用表单；保存后提供“在日程查看”，不要强行踢走任务详情 |
| 返回/刷新/同路由参数变化 | 定位一致，不串旧详情/表单；关闭详情不回错周 |
| 无截止旧链接undated=1 | 仍能打开全部任务中的无截止筛选，不丢既有收藏链接 |

返回地址只允许已知站内路径和受控查询，不接受外站跳转或递归套return。关闭通过浏览器历史打开的面板可回上一列表状态；直接深链关闭应有明确列表回退，不能一律router.back把人送离产品。

### 列表布局

保留view=list链接和“周表/按天列表”布局切换；列表也按当前七日显示同一套每日任务+每日截止，不能继续把截止Task叫“今日任务”。两种布局内容口径相同，视图切换保留周与选日。

若存在外部入口依赖旧列表，不删入口：全部任务面板提供原任务全集及逾期/无截止/已完成筛选。整Task的完成/改名/删除仍走现有独立入口，不把它们混进安排卡的单次进度。

## 9 待安排、过去未完成与全部任务

三个紧凑入口共享一个按需展开区域，不额外占一套常驻七列表。

- 待安排：使用classify的尚未安排/待续安排，显示原因；已有后续安排仍可从全部任务继续排新一天。
- 过去未完成：读取pastUnfinished，即使Task另有未来安排也保留待处理项；操作为查看、另安排一天、明确取消或人工确认进度，不自动改原日期。
- 全部任务：任务全集，可搜索并筛选未完成/已完成/无截止；远期截止、周外安排、无截止长期任务始终可到达。

既有Task CRUD入口可复用，但不让旧TaskRow的大量按钮再次塞满周表；清单优先任务名、总截止、安排概况及单一“安排/查看”入口，更多操作回Task详情。

## 10 删除影响确认：本批必须把界面接上

同时覆盖TaskDetailPage、TaskRow和NotesPage便签联删入口，不能只修新周表。

1. 打开确认框时读取当前事实，冻结用户将看到的Task/Action及planDeleteScope结果；展示待移除安排数量、保留为历史数量、涉及日期，必要时展开逐条看说明。不得展示时一份、点击确认后重新取另一份冒充已确认。
2. 提交原taskIds/actionIds/planItemIds/planFacts快照；不能依赖withPlanScope事后代填。
3. SCOPE_CHANGED则不删、刷新影响、明确告知变化并重新确认；UNFINISHED_FOCUS/PLAN_PROGRESS_REQUIRED则引导处理会话/安排进度。
4. 已结束历史与原成果保留；删Task/便签的撤销仍按既有最小恢复规则，不能覆盖后续新增事实。
5. 对阻断删除的旧planned+历史Focus，提供可用的安排详情/进度核对入口，不只抛无法操作的提示。人工确认进度后重新展示最新删除影响并确认，不能自动继续原删除。

取消安排与删除Task是不同操作：取消不调用Task删除，Task删除也不被安排的“取消”按钮暗中触发。
