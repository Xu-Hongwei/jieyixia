# 2026-11-18：产品前端 UI 库与技能建议

状态：选型建议，尚未安装或迁移，不代表前端负责人已签收。依据当前 lab/package.json 及本轮官方文档查询。

## 推荐组合

Vue 3 + Vite + Tailwind CSS 4 + shadcn-vue（Reka UI）+ lucide-vue-next。

现有 lab 已包含 Vue、Vite、Tailwind 4、Reka UI、Lucide 及少量手写 UI 组件。这些是继续选 shadcn-vue 的适配基础，但不等于项目已经由官方 CLI 初始化；迁移前应核对 components.json、别名、JavaScript 配置及组件差异。

## 库的比较

| 方案 | 适用情况 | 本项目判断 |
| --- | --- | --- |
| shadcn-vue | 希望掌握组件源码、按产品需求组合与定制 | 首选，延续现有栈，适合字段核对、原图侧栏和任务工作区 |
| Nuxt UI | 希望用主题统一、较完整的成品组件更快交付 | 备选，官方支持普通 Vue/Vite，不必迁移成 Nuxt；需评估替换现有组件的成本 |
| PrimeVue | 表格、复杂表单等数据密集界面占主导 | 备选；当前产品主要是收集、核对与专注，不作为首选 |

一个产品选一个主组件体系，避免重复引入整套组件库造成样式和交互不一致。

## 技能建议与分工

1. **UI UX Pro Max**：先整理产品布局、配色、字体、响应式和交互规范。维护者提供 Qoder 安装目标；选定具体风格后仍需结合本项目工作流评审，技能不是审美质量保证。
2. **shadcn-vue 官方 skill**：负责查组件、遵守实际 API、组合与定制；官方提供基于 components.json 的项目识别。放入 Qoder 后需要实际验证识别与触发，不能把其他应用已安装的技能当作 Qoder 已可用。
3. **Anthropic frontend-design（可选）**：用于视觉方向、排版、布局和整体一致性检查；移植时固定 Vue 栈及产品工作区目标，避免生成不适用的落地页或改换框架。

设计阶段主要使用一个视觉指导技能；实现阶段使用组件技能；完成后用浏览器功能与截图验证。不要让多个视觉技能同时提出互相冲突的方案。

本轮在检查的 Qoder 用户 skills 目录中看到 fastapi、pytest-test-scaffolder，未发现上述 UI 技能；这不是对所有内置能力或其他安装路径的完整盘点。

## 第一轮产物与验收

- 先给两种有差异的布局/风格草案，再选一种落地。
- 工作区结构覆盖“今天、收集箱、专注”；首先实现“收集 → 核对 → 建任务 → 刷新恢复”。
- 桌面核对页可采用资料列表、结构化字段、原图上下文的布局；小屏将原图作为可展开面板。
- 统一字号、间距、颜色、组件状态及操作名称；保存中、保存失败、空状态、待确认状态都要有明确表现。
- 前端显示产品语言，避免把 role、basis、reference_source 等内部枚举直接当作普通用户文案。
- 采用真实可运行页面及固定虚构样例验证，不仅交静态效果图；浏览器检查编辑、确认、失败恢复与键盘操作。
- 当前阻塞缺陷继续按二次验收报告修复，不用 UI 工作替代可靠性验收。
