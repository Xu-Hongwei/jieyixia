# 前端 U1 实施与验收

日期：2026-11-26。状态：U1 已实施并通过本阶段验证；下一阶段 U2。

依据：[前端体验整理实施方案](2026-11-26-前端体验整理实施方案.md)。本阶段完成任务总览、导航归属、返回目的地与任务列表筛选恢复，并精简相关重复说明。没有改后端、契约、存储格式或规划算法。

## 1. 现在的页面行为

- 主导航为日程、任务、资料、助手。桌面侧栏在滚动时保持可访问，手机改为四项底部导航并预留内容底部空间。
- 新增 `/tasks` 任务总览，直接访问全部任务、待安排、过去未完成；支持搜索、状态、事项、仅无截止筛选。
- 任务页可以就地创建任务和每日安排，提交使用原有服务；不需要先跳到日程创建任务。已有日程新建入口暂保留，待 U2 做统一收敛。
- 列表来源中的筛选参数可在任务详情返回、刷新、改排往返后恢复；实测滚动返回前后均为 583px。
- 任务详情属于任务分区，资料核对属于资料分区，工作记录属于日程分区。
- 任务详情按钮按真实来源显示“返回任务列表”“返回日程”“返回资料库”等；直接打开或来源无效的任务详情默认回任务总览。
- 安排上下文的“在日程中查看”与返回原位置明确区分；删除异常提示区内重复的返回按钮。
- 待核对保留为资料分区的二级入口，仍显示待处理数量，手机同样可直接进入。`/notes`、`/notes/:id` 均保留；资料列表与核对的完整合并仍属于 U3。

## 2. 组件与状态处理

任务页和日程旧清单共用 `TaskListRows` 与 `filterTaskList`，继续使用现有 planStore 的分类结果，不复制“待安排/过去未完成”的业务定义。

任务列表 URL 只保留清单、搜索、状态、事项、无截止等受限偏好；一次性创建参数与嵌套 return 不会混入任务列表来源。任务详情和改排的返回验证仍检查真实对象和当前空间。

新增 `TaskCreateForm` 保持字段标签可见，保存失败保留输入，保存中禁止重复提交与离开；取消、导航、切空间均通过未保存确认。任务页复用现有离开协调器保护任务表单和安排编辑器，并在空间切换后清理一次性批准状态，避免新空间的下一次离开绕过确认。

## 3. 已精简的内容

- 移除“同一展开区 · 搜索与筛选对当前清单生效”。
- 列表使用分隔线展示任务，减少每行独立卡片边框。
- 任务总览不添加功能介绍段落，直接展示分类、筛选、任务和操作。
- 本地存储说明缩为“数据保存在本浏览器”。
- 任务创建只显示名称、可选截止、事项与提交/取消。
- 同屏返回入口去重，保留目的不同的“返回来源”与“在日程中查看”。

助手、资料详情、日期控件中的其它说明文字尚未在本阶段统一精简，继续按 U2–U5 推进；未为了删字隐藏未保存、失败、删除影响或其它必要信息。

U1 浏览器覆盖了：组合筛选及刷新/返回、滚动恢复、任务创建落库一次、模拟存储失败保留输入、取消离开、取消/确认空间切换、批准状态不串到下一空间、安排实际保存、安排详情返回来源、任务列表改排往返、旧无截止/创建链接、核对与记录分区、手机二级入口。

U0 回归继续覆盖：指定日期/列表/安排上下文在创建草案、刷新重新打开和采用后返回时保持；非法来源拒绝；普通/改排草案不同尺寸下编辑、预览、日期选择正常。

两套浏览器测试使用不同隔离上下文与虚构 IndexedDB 数据；合计 64 项包含重复验证，不表示 64 个互不重复的业务场景。没有调用 analyze/propose，没有访问用户 8000/8020 服务，没有真实模型费用，也未发布。

过程记录：U1 首轮一项断言把浏览器编码后的中文 URL 与未编码文本直接比较，已改为对解码结果与实际页面作校验；U0 回归首次因两个同名“返回日程”按钮失败，随后据真实不同目的地整理文案并移除重复入口。未覆盖或删除这些过程证据。

## 6. 范围与下一步

本阶段保留旧日程任务清单、日程新建和完整核对页面，避免承接流程尚未完成时丢失能力；最终入口去重仍需 U2/U3。任务页的安排详情暂在页内展开，统一侧面板与“创建任务后继续原安排”属于 U2。

手机验证使用浏览器视口，未在实体手机上验证软键盘和安全区；这些继续作为最终设备验收项。本轮不是全量旧浏览器脚本、后端或公网部署验收。
