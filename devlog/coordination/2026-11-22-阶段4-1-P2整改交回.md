## 修改内容（对应 5 条规则）

`export.js`：新增 `import { validateBackup } from './validate'`；在 `entries.unshift(manifest)` 之后、`packArchive(entries)` 之前插入：

```js
const check = await validateBackup({ entries })
if (!check.ok) {
  const detail = check.errors.slice(0, 3).map((e) => `[${e.layer}] ${e.message}`).join('；')
  const more = check.errors.length > 3 ? `（共 ${check.errors.length} 项问题）` : ''
  throw Object.assign(new Error(`备份未通过完整性校验，已禁止下载：${detail}${more}`),
    { code: 'BACKUP_VALIDATION_FAILED', errors: check.errors })
}
```

- 规则1（接入结构/语义/关系/限额校验，失败抛错不下载不成功）：validateBackup 的 A（归档/限额/哈希/声明一致）+B（契约 schema+models 语义+禁运字段+计数）+C（关系闭包+≤1 未结束会话）全部在生产链执行；!ok 抛 `BACKUP_VALIDATION_FAILED` 带完整 errors。DataPage 的 doExport 只在 buildBackup resolve 后才 triggerDownload，throw→catch→exportError+lastExport=null，故零下载、无成功提示（无需改 UI）。
- 规则2（压缩前查条目数/JSON/图片/总展开字节，保留压缩后 ZIP 检查）：validateBackup({entries}) 在 packArchive 之前按**最终实际字节**查 MAX_ENTRIES/JSON_MAX_BYTES/IMAGE_MAX_BYTES/UNCOMPRESSED_MAX_BYTES；packArchive 仍保留压缩后 ZIP_MAX_BYTES 兜底。超限载荷在压缩前即被拒，不会先压出小 ZIP 再发现不可恢复。
- 规则3（manifest 后对最终 entries 调已有校验器，不强制重复解压 ZIP，不只查 kind/哈希）：正是对 unshift manifest 后的 entries 调 validateBackup；不重复解压 ZIP（entries 即归档原始字节），依据实际字节而非仅 kind/哈希。
- 规则4（不截断/不丢字段/不篡改原库/不放宽恢复器）：校验只读 entries，失败即抛错；不修改 snapshot/原库，不放宽 LIMITS 或 schema；合法本地额外字段仍按 4-0 适配保留。
- 规则5（UI 失败可重试+真实归属+零 download+不把上次成功当本次）：DataPage 原有 catch 分支已满足；浏览器实测失败阶段 download 计数不变、成功提示消失、按钮恢复可点，重试合法后再次下载+成功。
