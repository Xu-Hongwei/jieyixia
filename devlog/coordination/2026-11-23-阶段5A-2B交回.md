## 3. 路由与参数（hash 路由）

## 4. 实际命令输入（页面→store→2A 服务，字段名与源码一致）

- **begin**（usePlanWorkStart.buildInput）：`{ taskId, actionId, planItemId?, expected?(planSnapshot 六字段), facts?(beginFactsOf 八字段), confirmBlocked? }`。首次提交签发信封（requestId/issuedAtMs），同输入失败重试原样复用；差异确认后以重冻结的 expected/facts/confirmDate 构建新意图新信封。
- **end**（WorkPage.submitEnd→doEndAttempt）：`{ sessionId, outcome, blocker, draftMd, expectedRevision, requestId, issuedAtMs, planProgress?, expected?, historyConfirm? }`。提交顺序=结算草稿→重查资格→冻结不可变 endAttempt（结果/卡点/正文/进度/expectedRevision/expected/historyConfirm 任一变化=新意图新信封；完全相同重试复用原信封原内容）→成功后核实持久记录再导航；调用抛错=结果未知，保留原提交待核实。historyConfirm 只含已结束会话（historySignature，不含当前段）。
- **legacyEnd**（v0）：`{ sessionId, outcome, blocker, draftMd, requestId, issuedAtMs, planProgress?, expected?, historyConfirm? }`——仅活关联+冻结快照齐备才带安排三元组；不补造过去快照/Action 完成。

### 11.1 R1（P2）：日期重确认未更新 planDate → 确认版本统一派生

- 根因：`planDate` 是独立字段，confirmDiffs 只换 expected/facts，不换 planDate 与任务展示快照，导致重确认后显示/勾选/提交非同版。
- 修复（`src/composables/usePlanWorkStart.js` + `StartPlanWorkDialog.vue`）：
  - `planDate` 改为 `computed(() => state.expected.date)`，无独立字段可失同步。
  - openFor 冻结集合扩为 expected（6 字段）+ facts（8 字段）+ taskTitle/taskStatus/taskDeadline + confirmDate；面板显示、日期关系徽标、风险提示、提交输入全部只读该冻结集合，不读 live 对象。
  - confirmDiffs/refreeze 从差异冻结快照**整体**复制全部字段，并重置 blockedChecked/dateChecked/输入/信封——blocked 与非当日确认按新事实重新取得，不勾选不提交。
- 反例验证：单测「今天→明天→再次改期」两段重确认（`usePlanWorkStart.test.js`）；真实浏览器 RF1 八断言（ui-rfix.mjs：diffs 期间冻结旧日期展示 → 重确认后徽标/勾选/提交同源换新 → 再次改期重复一轮 → 全程单会话）。

### 11.2 R2（P2）：开始后补充读取失败卡 busy → 待核实只读重试

- 根因：navigateVerified 的 loadWorkspace 无 try/catch，抛错后 busy 永挂。
- 修复（`usePlanWorkStart.js` + `StartPlanWorkDialog.vue`）：
  - 读取前先记 `pendingSid`（会话可能已创建，稳定 session_id 优先保留）；try/catch/finally，finally 释放 busy + 作用域检查。
  - 失败进入 verify 相位，文案「已收到开始结果，读取待核实：会话可能已创建。可重试读取，不会重新创建。」；pendingSid 分支的 verify 只重读、绝不重新 begin；面板此时只显示「重试读取」，隐藏「原信封重试」（`v-if="state.envelope && !state.pendingSid"`）。
  - showDiffs/verify/refreeze 的全部读取同样 try/catch/finally + 空间归属检查，晚到的原空间结果不污染新空间。
