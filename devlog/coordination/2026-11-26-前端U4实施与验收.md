依据：[前端体验整理实施方案](2026-11-26-前端体验整理实施方案.md) U4，以及减少重复入口、跳转和无关说明文字的要求。

## 1. 本轮结果

助手由桌面双列堆叠改为同页四步：**提供资料 → 核对建议 → 预览安排 → 确认加入**。桌面与手机共用顺序。

- 入口分为“制定新计划 / 调整已有计划”；七日可用时间显示摘要，编辑时展开。示例与历史草案默认折叠。
- 核对步骤保留原文、任务、行动、剩余工作量与截止确认；改排仍明确列出允许替换、保留和受保护的安排。
- “保存并预览”按顺序调用原有保存、排程逻辑。保存失败停止后续步骤；无效预算和未保存改排内容不能继续。不会通过“下一步”代替事实、范围、缺口或过载确认。
- 待确认事项在核对/预览当前步骤显示，避免重新排程导致确认失效后找不到操作。步骤切换回到工作区顶部，并把键盘焦点移到当前步骤。
- 最终加入仍有明确确认。成功后只保留一组“查看日程 / 查看任务”，不自动跳页；已采用草案只读。未知结果的核实入口保留，未把它当作成功或重新采用。
- 标题、预算、进展清单、原文输入和未提交的澄清回答都有离开保护；取消离开保留输入。已有澄清已归档且没有未提交回答时，允许离开，不锁住页面。
- 删除重复成功横幅和部分机制说明；任务/行动编辑区不再把内部 key 当主要标签。仍保留会影响决定的失败、总截止不变、替换范围和未排入提醒。

后端、HTTP API、数据契约和排程算法未修改。日程的每日安排/截止分区、资料库核对和任务页就地操作继续沿用 U0–U3。

## 2. 本轮发现并修复的边界问题

### 确认事项不能藏在另一页签

排程更新版本后，任务截止或改排范围可能需要再次明确确认。只把这些按钮放在编辑区，会让预览页出现“不能继续”却找不到原因。本轮把相关事项作为共享核对区，在当前步骤展示；按钮仍调用原确认服务，不自动确认。

### 浏览器存储额度不足被误当作领域错误

故障注入发现 `DOMException.code` 是数字（`QuotaExceededError` 为 22），原前端草案服务把它原样返回。生成状态机只对 `SAVE_FAILED` 保留结果，因而额度不足会落入“需要重新生成”分支。

现仅保留显式的字符串领域错误码；浏览器数字错误码归为 `SAVE_FAILED`，消息保留原原因。真正的冲突等字符串错误仍按原规则处理。补充单测验证线程/草案整体回滚、恢复后保存同一结果；浏览器验证失败时不能采用，重试保存后模型请求计数仍为 1。

这是前端本地存储的错误识别修正，不涉及后端错误契约。测试采用异常注入，没有实际填满磁盘或删除用户数据。

建议人工体验三条路径：

1. 助手 → 输入文字并保存 → 填要求 → 生成 → 核对截止 → 保存并预览 → 处理待确认项 → 确认加入。
2. 任务详情 → 调整后续安排 → 选择替换范围与剩余工作 → 保存并预览 → 采用 → 查看任务 → 返回原日程。
3. 修改预算或任务标题 → 尝试离开 → 取消 → 确认输入保留；再保存预览，检查正式采用前仍需确认。

限制：本轮未验证真实模型质量、线上部署、实体手机软键盘或 Safari。主包约 1111 kB、gzip 约 332 kB 的构建体积告警仍在，留到 U5 评估路由拆包；不调高告警阈值掩盖问题。
