## 给 Qoder 的实施说明

1. 先以「核对工作台」落地收集箱：稳定左侧导航、待核对资料队列、结构化字段、原文对照。原文区允许展开/收起，窄屏需调整分栏。
2. 「今日执行」作为首页、「事项文档」作为事项详情，是现有草案建议；本次选择仅明确核对工作台的参考方向，不将全部展示细节视为已批准的产品决策。
3. 在项目现有 Vue 体系内拆分页面与组件。视觉、间距、层级和交互可借鉴，草案脚本里的临时状态不能替代正式业务状态与存储。
4. 第一阶段完成真实闭环：收集资料 → 识别 → 人工核对 → 建立任务 → 刷新后恢复。页面只在持久化成功后呈现保存成功，失败时保留用户输入。
5. 按已定字段来源、确认状态和截止时间规则实现；模型推断不等于人工确认，完成今日计划条目不等于完成整个任务。
6. 草案数据均为虚构，计时与创建任务均为演示。不要将静态示例、演示成功提示或页面中的功能入口作为正式功能已完成的证据。
