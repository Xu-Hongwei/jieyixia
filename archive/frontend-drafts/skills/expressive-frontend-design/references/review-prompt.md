# 三位评审的共同提示词 · v2.1

## 使用与证据包

执行独立评审时，让每位评审完整读取本文和 [细项评分规则](scoring-rubric.md)。三位收到相同版本的两个文件、同一证据清单和相同任务说明，不分别赋予视觉/技术/产品角色。主聊天、技能或用户允许委派时才使用子智能体；环境不允许则只作明确标记的单人自查，不能模拟独立结果。

证据包至少说明：批次与版本、产品用途、用户范围、方案标识、固定示例内容与状态、视口、实际截图、可用的交互/录屏、素材接入和未实现事项。先冻结批次证据再发给评审，不边改画面边混用版本。静态与动态分开注明；每人先评全部方案，再汇总其本人的跨方案差异。不要提供设计者偏好、其他评审结果或期待分数。

只修改技能或整理规则时不启动实际设计评审。以下共同提示词原样发给每位评审，替换具体证据清单即可；不要给不同评审增加不同的审美暗示。

## 共同提示词

请评审本次提供的前端设计草案。当前处于创意探索阶段，开放地评价个性与完成质量，不按正式产品的后端完成度苛责草案。

共同审美要求：

- 整体协调，有鲜明气质，构图、配色、字体、图像、材质与运动共同表达产品用途。
- 鼓励大胆、多色、密集、非对称、重叠、平面、3D 或着色器等多样表达；不按个人偏爱的风格加减分。
- 主要信息清楚、主要操作容易找到，丰富装饰与空间隐喻应当支持使用。
- 只评价证据支持的效果，分别辨认生成资产、CSS空间效果、视频、着色器与真实3D；未展示的动态品质不可推测。

使用附带的 scoring-rubric.md v2.1：五大项100分拆为14个子项，先判每项0–4整数等级，再按权重计算，不能先定总分再凑分。每项给出具体证据、理由、反证或局限和置信度；相同观察用于多个子项时解释各自不同的收益。首次使用或等级含混时阅读附带的calibration.md，校准仅用于理解指定子项，不将样例风格当作评分偏好。缺证据记NE，按实际可评满分报告；所有方案在共同可评集合上比较，不默认采用95分或任何其他删项后的固定满分。

宽容意味着尊重创意探索的范围，不意味着默认给良好等级；同样也不为制造区分度而强行拉开分数。等级4需要明确的突出证据，等级0需要实际失效证据。缺少真实后端、个人不喜欢的配色、未使用昂贵技术，均不能独立构成扣分理由。用户明确要求但未交付的素材/效果单列为范围问题。

请输出：

1. 证据覆盖：看过的版本、页面、状态和视口；哪些能力待验证。
2. 每套一句话整体印象，随后给14行评分表：ID、权重、等级或NE、得分、证据位置、判级理由/局限、置信度。
3. 每套分开报告质量（已评得分/满分）、证据覆盖（未评项与缺少场景）、交付完成情况（已完成/受限/未交付），并列关键问题。关键问题不能被高总分抵消；缺少核心体验证据时不宣布整体最佳。
4. 每套最值得保留的三个亮点、两到三个优先优化项；区分明确问题与偏好。
5. 每套最优先解决的一件事：指向层级、位置、修改假设与可复验的通过依据。不要只写“更精致”“增加高级感”。
6. 本人的跨方案校准：列出最能解释分差的子项与证据；若同分，说明真实接近还是证据不足，禁止人为规定分数分布。

目标是帮助下一轮作出具体修改并保留个性。不要读取其他评审的结论，也不要宣称静态截图已证明动画、可打断性或性能。

## 三份结果的汇总与返工

三位独立提交后才汇总：

- 在共同可评集合上展示三份分数、平均分和最小–最大值；覆盖不同时先取交集重算，保留各自完整表。
- 列出共同认可的优点、主要问题与分歧。出现子项相差两级及以上时核对证据与判断，不强迫统一，也不按均分机械选赢家。
- 将采纳的优化项写入 [优化流程](optimization-loop.md) 的问题记录，注明当前层级、假设和复验依据。未采纳项解释是偏好、证据不足还是与用户范围冲突。
- 实际修改后比较同条件前后证据，再决定关闭、保留或回退；重要变化才重新发起相同范围评审，不能只交付评分报告而不完成已承诺的修改。
- 同一子项有可比证据才报告提升；新增证据覆盖、改权重或改评分版本须单独说明，不当作质量分上涨。

最终审美选择属于用户。一次评分不等于用户测试、真实业务验证或上线验收。
