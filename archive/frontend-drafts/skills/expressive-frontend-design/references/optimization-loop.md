# 逐层优化与继续执行

## 1. 恢复任务状态

确认用户要文字、静态画面、交互原型还是正式实现。只分析或修改技能时，不自动改页面、生成素材或启动评审。

实现阶段将简短进度记录放在用户允许的设计目录内，例如已有设计说明中的“优化状态”段落；已有记录就复用，不复制出多份清单。记录当前方案/页面/层级、稳定的设计决定、待解决问题、证据路径和下一步。不要写进长期记忆。用户说“继续”时从该状态恢复。

固定比较基线：同一输入内容、业务状态与视口，记录字体、素材和实现版本。字体、素材或布局本身是修改对象时允许改变，并写明本轮有意改变的变量；其余条件尽量保持稳定。“同条件”不意味着冻结所有设计元素。多方案先比较共同核心页面，选型未定时可平行打磨，不自动扩展全部页面。

图像主导、拟物或立体方向在L1定型前，先试放一份关键资产或验证一个低成本空间原型：比例、裁切、视角、文字安全区和交互区域是否成立。现有素材、生成试样或诚实标注的临时几何均可用于早期验证；明确要求的最终生成资产不能用临时原型代替。涉及持续运动时在此检查基础表达可行性，L4再精修与复验完整状态。每次只做足以验证方向的试验，避免未定构图就全量生产资产。

## 2. 每层使用同一个闭环

1. 看实际证据，写出当前层最值得处理的具体问题；没有问题要给出依据，不凭空制造。
2. 选少量高价值问题，说明位置、影响和修改假设。基础层的问题优先于装饰层。
3. 做能验证假设的修改，保留已成立的设计关系，不顺手重构无关页面。
4. 在相同条件下检查修改前后；涉及动态行为时重新操作。
5. 判断解决、部分解决、无改善或退步；退步时回退相关修改或更换假设。
6. 当前层选定的优先问题已解决，其他问题有明确处理决定且满足本次范围后，才进入下一层。关键问题不能延期为“已通过”；主要问题若延期，须记录原因、影响、何时返回处理，以及为何不破坏后层的基础。与本层核心设计主张有关的未解决问题不得只改名为局部问题来绕过。高总分不能代替问题关闭。

不要求机械循环固定次数。若连续修改无改善，重新检查问题与假设，必要时回到更早的层；不要只加纹理、特效或更多页面。用户未要求的扩大实现不作为优化成果。

## 3. 层级与通过依据

| 层 | 检查重点 | 通过依据 | 需要返回的情况 |
| --- | --- | --- | --- |
| L0 内容与操作 | 核心任务、必要信息、主操作、示例/真实边界 | 固定示例和状态；用户能辨认要看什么、下一步做什么 | 装饰或改版使关键内容丢失或语义改变 |
| L1 空间构图 | 导航、主工作面、上下文、阅读顺序、密度、方案差异 | 同尺寸缩略图与灰度图；指出主次、留白和阅读路径；关键操作不被遮挡 | 大字、素材或新面板改变视觉重心，或仍沿用同一骨架换皮 |
| L2 排版 | 中文字形、字体关系、长任务名、日期数字混排、行距、对齐 | 实际字体的原尺寸与关键局部；长内容、桌面/窄屏主要信息可读、换行合理 | 字体回退、素材裁切、展开或状态变化造成挤压与孤字 |
| L3 色彩与材质 | 色彩面积、语义色、对比、图像语言、光线与纹理尺度 | 素材已在页面接入；原尺寸和缩小后不抢正文；同一系列协调；灰度层级仍成立 | 新材质导致对比下降、文字被图像争抢或构图失衡 |
| L4 状态、运动与空间 | 对象来源和去向、展开/确认/归组、连续操作、焦点、空间反馈 | 主要动作实际运行；输入不被动画阻塞；可打断；窄屏与减少动态效果下可用 | 全区重绘导致焦点丢失、展开跳动、反复入场或效果误导真实状态 |
| L5 整体复验 | 核心流程、代表页面、关键异常状态、资源与退化 | 复查受影响的前层和相关页面；已采纳问题有关闭证据，剩余限制明确 | 局部改善损坏整体风格、其他视口或操作链路 |

文字阶段只执行能由文字支持的层，不能宣称已通过字体渲染、素材接入或动态体验检查。风格可影响检查重点；不把所有任务限定成同一种布局或极简审美。

## 4. 问题条目必须可关闭

最小格式：

```text
问题ID / 所属层 / 影响程度
方案、页面、状态与视口：
观察与证据：
修改假设：
这次实际修改：
复查证据与结果：解决 / 部分解决 / 无改善 / 退步
保留或回退决定：
若延期：原因 / 影响 / 返回条件 / 当前层是否仍可通过
下一步：
```

程度分为：关键（阻断核心任务或主信息阅读）、主要（明显破坏主次/风格/连续操作）、局部（有限细节）、偏好（无可验证缺陷）。明确问题与偏好分开；评审多数票不自动将偏好变成缺陷。

## 5. 证据与收敛

- 功能证据：实际检查了哪些操作、异常和输入。布局无溢出只证明这一项。
- 视觉证据：对照同条件画面，说明视觉重心、排版或材质的具体改善，不以截图数量代替结论。
- 动态证据：实际操作记录或短录屏，包括触发、过程、结束及再触发。只读源码只能证明存在实现，不能证明效果和流畅度。
- 资源证据：接入文件、格式/大小、裁切和退化表现；未测量性能时不宣称“性能优秀”。

独立评审用于发现盲点。汇总后选择具体意见处理，更新问题条目，再对相关证据复验。无需为了追分重做所有层，也不在每次微调后重复全套评审。

收尾依据：本次范围的关键问题和选定优先问题已解决，其他问题有明确处理决定，有相应实际证据，已交付可用入口与剩余事项。若仍有影响本次核心主张的主要问题，不宣称完整优化通过。工具限制导致某层不能检查时，标明未验证；可完成的工作继续做。不要等待用户再次说“继续”才完成已承诺的本轮复验。
