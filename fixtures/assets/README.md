## 为什么不用图像生成模型直接画

fixture 里每个字段都带 `quote.text`，前端要把它当作「原文引用」展示，并支持点回原图核对。如果截图由图像模型生成，中文文字大概率渲染错乱或缺字，`quote` 与图片就对不上——这会直接破坏 PRD 规则 4「来源可追溯」的演示效果，评委一点开原图就露馅。

## 生成方式：两条路线，任选其一

**路线 A：PIL 直接渲染**（01 已用此路线）。用 `PIL.ImageDraw` + 系统中文字体（如 `C:/Windows/Fonts/msyh.ttc`）把通知文字画到白底图上。文字由代码写入，天然与 fixture 逐字一致，且可重复生成。适合排版简单的通知页。

**路线 B：先写 HTML，再截图**。适合需要仿真平台 UI（导航栏、按钮、表格）的场合：

1. 为每张通知写一个静态 HTML，模拟课程平台的通知页样式，**正文文字逐字取自对应 fixture 的 `quote.text` 与 `raw`**。
2. 用 `browser-use` MCP 打开该 HTML，`take_screenshot` 存成对应 PNG。
3. 人工核对一遍：图片里的每个关键句与 fixture 的 `raw` 完全一致，尤其是数字（`3000字` 不能变成 `300字`——那正是 fixture 01 里刻意安排的 AI 识别错误，原图必须是正确的 3000）。

两条路线都禁止用图像生成模型画文字（理由见下）。

## 脱敏要求

- 不出现真实姓名、学号、学校名、教师名、真实平台域名与 logo。
- 课程名用虚构但合理的名称（如「机器学习」这类通用课程名可以，具体校名不行）。
- 日期用 fixture 里的 2026-11-17 / 11-19 / 11-21 / 11-25，保持整套数据自洽。
- 生成后在当日 devlog 中标注为**生成素材**，与真实上传截图区分（PRD 第 385-387 行）。

## 注意 fixture 01 的刻意错误

`expected_analysis` 里 `constraints.value` 是「报告不少于 300 字」，而 `raw` 与原图是「3000字」。这是黄金路径第 3 步「用户修改一项识别错误」的演示素材，**不是 fixture 写错了**。生成原图时务必写 3000。
