# 有个性的前端设计探索

目标：让不同方案拥有独立的空间结构、阅读节奏与操作感，让图像、字体、配色、材质和运动共同表达产品用途。鼓励大胆尝试，以整体协调和使用体验判断取舍。

## 执行入口：逐层闭环

开始实现或收到“继续优化”时，先读 [逐层优化流程](references/optimization-loop.md)。恢复现有问题和证据，从当前未通过的层继续；没有记录时先诊断现状，不默认重新换风格或增加页面。

下面各节提供设计依据，不是“每章做一次就完成”的清单。每层执行：检查证据 → 选高价值问题 → 修改 → 同条件复查 → 记录通过或回退。检查过、生成过、测试通过均不能自动等同于视觉改善。

先固定一张核心页面及其关键状态，在结构和排版稳定后扩展同方向其他页面。图像主导或空间型方案应先试放关键资产或做低成本空间原型，再定型布局；层级用于组织复验，不要求把素材和运动全部推迟到排版之后。多方案任务保留用户要求的方案数量；优先在共同核心页面比较，避免同时铺开所有方案的所有页面再匆忙精修。

## 工作范围与阶段

- 先识别用户要的是文字构想、静态画面、交互原型，还是正式实现。要求“先文字描述”时只交付设计说明，不自动生成图片、写页面或启动评审。
- 沿用用户指定的目录、技术栈与改动边界。独立草案放进专用文件夹，不改其他成员的源码、存储、配置或现有工作。
- 草案用虚构内容并说明演示边界；真实保存、模型识别和状态确认必须有对应实现，不能用动画或成功提示冒充。
- 六种参考方向是灵感库，不固定要求六套，不将截图产品的特定信息架构推广成所有项目的规则。

## 1. 定义共同内容，拉开设计差异

从实际产品中选择一个核心流程，固定示例内容、文字长度、主要操作、关键状态与比较尺寸。各方案展示相同内容和流程，避免用不同页面或不同信息量制造差异。

为每套方案写清：

1. 视觉主张：情绪、材料、能量，以及与产品用途的联系。
2. 页面框架：导航位置、主要工作面、次要上下文、信息展开方式、主操作所在位置。
3. 排版与色彩：中英文字体分工、字号比例、行距、对齐、色彩面积关系与状态色。
4. 图像与空间：需要生成的资产、材质、光源、视角，平面与立体区域的关系。
5. 交互主张：两个或三个有意义的动作，解释信息如何从一个状态进入另一个状态。

多方案间至少在页面结构、字体关系、配色面积、图像语言、操作方式中三个维度形成明显差异。可以共享业务逻辑，但不要仅在同一页面骨架上换主题色。

如用户鼓励随机探索，为各方向生成并记录不同字符串种子，将其用于打破构图、材料、字体或配色惯性。明确种子只是启发；最终组合经过判断，不宣称随机结果天然更好。种子不能替代具体的设计决定。

需要方向示例时阅读 [references/design-directions.md](references/design-directions.md)。

## 2. 先建立构图，再精修视觉

- 用缩略图检查视觉重心，用灰度检查层级，用局部放大检查字距、边缘、间距和材质。不要让特效掩盖基础构图问题。
- 设计中文字体关系：用真实长任务名、日期、数字和中英文混排验证换行与密度；手写体与特殊字形优先用于短标题或便签，正文保持清楚。
- 不固定极简、黑白、少色、无卡片等单一审美。多色、密集排版、重叠、非对称和立体元素都可以使用，只要整体协调、信息可读、操作明确。
- 静态画面和交互过程分别成立：某张截图漂亮，不代表展开、滚动和切换后仍然协调。

## 3. 用生成图像建立专属资产体系

主动判断生成素材的职责，并实际完成“生成 → 项目内保存 → 加工 → 组件拼装 → 页面验证”。用户要求大胆、丰富、高级材质、图片/视频或空间效果时，在工具可用且属于授权范围的前提下，优先为最有表现价值的工作面、物件、封面或场景接入真实生成素材；不能默认用几何 SVG、渐变、emoji 或纯 CSS 方块替代所有视觉资产。

素材如何主动选择、图片与视频如何生成利用、工具不可用时如何降级，按 [资产与效果落地](references/assets-and-motion.md) 执行。生成工具返回文件只是中间结果，素材必须在实际页面中发挥作用。仅修改技能、文字构想或简单功能界面时不自动生成素材。

先确定资产规范，再生成：统一光线、视角、色域、材质尺度与细节密度；预留文字区域；需要独立摆放的物件使用透明背景。真实文字、按钮和动态业务内容由界面渲染，不烘焙进图片。

需要资产清单与提示词结构时阅读 [references/assets-and-motion.md](references/assets-and-motion.md)。不要把待生成资产描述为已完成素材。

## 4. 让动画、着色器和 3D 具有职责

- 把进入、展开、核对、归组、建立行动、专注等状态变化设计成连续动作；清楚交代对象从哪里来、到哪里去。
- 每套优先精修一个标志性效果，并让其他动作遵循同一节奏。光泽、显影、折叠、折射、纸张厚度和空间分层按方案选择，不要求全部叠加。
- 实现前写出触发、对象、前后状态、执行技术与退化方案，然后实际运行检查。用户明确要求的适用效果不能只停在描述或参考图；发现所需工具、素材或运行能力缺失时记录限制与实际替代。图片动画、视频、CSS 空间变换、着色器和真实 3D 分别标注，不相互冒充。
- 文字与输入区保持稳定可读；旋转、视差和反光可以作用于物件外层。交互动画支持打断，不让等待动画阻塞任务。
- 正确表达候选、人工确认、正在保存与已保存等语义；“完成一个计划条目”不自动暗示整个任务完成。
- 移动端、低性能设备和减少动态效果偏好提供合适的简化或静态表现。检查实际资源体积与操作流畅度后再报告性能结论。

## 5. 用真实材料验证与收敛

文字方案按文字阶段交付。进入实现阶段后，使用可用浏览器工具检查至少一个窄屏和桌面尺寸，以及长文字、空状态、待确认和失败状态。记录核心流程，检查跳动、等待、操作来回和动效衔接。

保留实际截图、可用的演示入口和验证记录；说明已实现、已验证和待验证内容。工具受限时如实报告，不把代码检查等同于视觉验收。仅在有实际问题或新改动时追加检查。

分别记录功能验证、视觉复验和动态体验证据。无溢出、可点击、没有运行错误只能证明对应检查通过。视觉改善需指出具体画面变化；连续动作需实际操作或录屏，静态图不能证明。

先比较各方向的同一关键页面，再把最有潜力的方向推进到完整流程、生成资产与标志性动画。用户仍保留最终审美选择权。

## 5.1 硬性设计闸门

以下检查不是建议项。每次进入“继续优化”或提交一轮视觉改动前，都要逐项给出通过、未通过或不适用；未通过时先解决最高影响项，不用新增特效掩盖问题。

### A. 反同质化闸门

- 如果两个页面同时使用居中标题、顶部居中导航、均匀卡片网格、大面积柔和背景和相同圆角阴影中的三项，必须重新构图。
- 页面之间至少要在结构、字体关系、配色面积、图像语言、操作方式五项中改变三项；只换主题色不算改变。
- 核心页面必须先写出一句可复述的空间主张，例如“编辑工作台”“档案柜”“时间轴墙”；如果只能描述为“更高级、更柔和”，视为未通过。

### B. 缩略图与视觉重心闸门

- 将核心页面缩小到约 25% 检查：必须能看出一个主角、一个次级信息区和一个主要操作入口。
- 用灰度检查：标题、工作面、任务内容、状态和背景必须有清楚的明度层级；如果背景纹理比任务内容更抢眼，视为未通过。
- 首屏不能同时出现三个同等重量的主角。任务墙、日程表或仪表盘必须明确哪个对象代表“现在”。
- 大面积留白必须服务于节奏、方向或操作聚焦；无法说明用途的空白需要收紧。

### C. 色彩与文字层级闸门

- 先记录色彩面积预算：背景、工作面、主强调色、状态色、文字墨色分别承担什么职责；所有颜色都低饱和或都接近同一色相时视为层级不足。
- 关键文字不依赖透明度表达层级。正文、截止时间、按钮和状态必须在真实截图中清楚可辨。
- 中英文、标题、数字、时间和辅助信息至少形成两组明确的字体关系；同一字体只靠字号变化来分层时，需要重新评估。
- 使用真实长标题、日期、数字和中英文混排检查换行；不能只用短占位词判断排版通过。

### D. 组件语义与密度闸门

- 每个视觉组件必须回答它表达的业务含义：任务、时间、优先级、来源、状态或操作。只负责装饰的层应减少或移除。
- 多任务页面必须同时检查稀疏、正常和密集状态；不能用三张示例卡证明日程系统已经成立。
- 周视图要能让人读出星期、时间顺序、当前时间和任务密度；月视图要能让人读出日期、任务数量和重点日期。
- 空状态、无截止时间、长文本、已完成、失败或待确认状态必须保持同一设计语言，而不是临时添加普通提示框。

### E. 动效、3D 与着色器职责闸门

- 每个显眼效果都要记录触发对象、前后状态、用户获得的信息、实现技术和静态退化方案；无法回答其中一项就不加入。
- 每套方案最多设置一个主导效果，其他动画服从相同的时长、缓动和空间方向。不要把悬浮、粒子、视差、反光和 3D 同时当作主角。
- 动效必须改善进入、展开、核对、归组或专注中的一种体验；只在截图上增加“高级感”的效果视为未通过。
- 运动不能降低文字可读性、改变按钮命中区域或阻止任务操作；减少动态效果、触摸设备和 WebGL 不可用时必须有可用的静态表现。

### F. 证据闸门

- 至少保留同一视口下的核心页面、关键交互前后、窄屏和灰度截图；动效需要实际操作证据，静态截图不能代替连续过程。
- 视觉结论必须说明具体变化，例如“标题与工作面明度差增加”“当前任务从三张卡中脱离”；“更漂亮”“更高级”不能作为验收结论。
- 功能通过、视觉改善和动效体验分开记录。无报错、无横向溢出和可点击只能证明对应检查通过，不能自动证明审美改善。
- 如果某一轮只改变素材、特效或文案，应说明它是否改变了构图、阅读层级或操作理解；没有实际贡献的改动应回退。

## 6. 三位子智能体的共同审美评审

执行评审时，先确认当前环境允许并行智能体，且在用户授权范围内。每个方案由三个不同的子智能体独立打分；三位收到完全相同的审美要求、评分权重、提示词与证据包，不分别设置偏向视觉、产品或技术的评分角色。

统一使用 [共同评审提示词](references/review-prompt.md) 及其引用的 [细项评分规则](references/scoring-rubric.md)。每位评审收到相同文件版本和证据清单；不提前透露设计者偏好、其他评审结论或期待分数。评分用于定位具体问题，既不凑平均分，也不人为规定分差。

展示三份独立分数、平均分、分数范围、共同优点与主要分歧。分歧优先回到画面与操作证据，不机械用平均值消除不同判断。按草案阶段开放评价，优先提出少量高价值改进，保留方案个性。

将采纳的意见转为问题条目，修改后用同一条件复查。评分版本或证据覆盖发生变化时分开报告，不把不同满分、不同阶段或不同评审人的结果直接当作提升量。用户仅要求修改本技能时，不启动实际设计评审。

若环境禁止或不提供子智能体，则只交付评审材料或明确标注单人自查，不模拟三位真实独立评审。本技能的创建、整理或调用本身不意味着评审已经执行。
