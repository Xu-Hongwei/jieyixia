### 删除便签与原始资料的补充决定

**2026-11-18 用户追加决定，替代原“有截止引用就阻止删除”规则：** 删除便签时先展示影响确认框，列出当前工作空间中关联任务的数量与标题；用户点击“删除便签及关联任务”后，同步删除该便签与列明的关联任务。关联包含 note_ids 引用或 deadline.from_note_id 引用，按任务 ID 去重；没有关联任务时只确认删除便签。取消不修改数据，失败整体回滚，提交成功后才更新界面。多便签共享的任务也必须明确列出并说明该任务将整体删除；不沿任务引用继续删除其他便签或事项。原始截图/文字默认保留，专注历史不在本次授权删除范围内。当前产品前端的便签/任务闭环先落实联删；后续接入行动、计划和专注时必须补齐引用清理/历史保留策略，不允许留下悬空引用。实施与验收要求见 [时间输入与便签联删](../devlog/coordination/2026-11-18-时间输入与便签联删.md)。此为新决定，不倒改此前历史验收结论。

### 时间输入体验补充决定

用户追加：无已有日期的时间输入默认动态读取北京时间的今天，允许用户再编辑日期/时刻；已有值和用户改值优先保留。默认仅是表单初值，用户保存/确认后生效，不在后端把模型缺失的截止或参照静默填成今天；用户主动采用默认值记为用户选择。清空/暂不设置继续有效。详见默认北京时间规则中的“空日期输入默认今天”。

日期、参照日期、消息日期均提供日历选择；截止和时间节点默认按日期输入，可按需开启具体时刻、选择时间，也允许清空。可提供“今天/明天/一周后”快捷操作，由用户明确点击后生效。普通用户不必手写 YYYY-MM-DD 或 ISO 字符串，也不直接编辑 basis/reference_source 等内部枚举。已识别的时间先回填并提供确认入口；仅日期不补 23:59。按用户追加决定，业务默认时区为北京时间 UTC+08:00（Asia/Shanghai），缺时区按产品默认解释但不伪装成原文明示；已有明确偏移的值不因打开编辑器而改变实际时刻。用户修改或清空关键时间后需重新确认；直接确认未改值仍保留模型来源与推算标记。具体实现沿用当前契约序列化格式，详见 [默认北京时间规则](../devlog/coordination/2026-11-18-默认北京时间规则.md)。

优先顺序：F06 跨便签截止变更建议 → F13 自然语言解析/拆解/重排 → F05 AI 归组 → F09 AI 行动建议。应用内裁剪、完整备份迁移/合并也在 P1，不能挤占可靠性和演示闭环。

V3-2 对**同一输入**中旧时间的 superseded 标记属于 P0 识别正确性，不代表 F06 **跨便签、跨通知**变更检测已经实现。黄金演示路径第 6 步在 P0 采用人工查看新旧证据、确认并修改任务；不得演示成自动变更检测。

## 4. V3-5 产品决定

| 项目 | 定案 |
| --- | --- |
| 图片裁剪 | P0 提供上传预览和“仅上传正文、避开侧栏/成员信息”的提示，允许用户在外部先裁剪；应用内裁剪为 P1。未来裁剪保留原图、另存分析副本。当前不新增 source_region/OCR 坐标依赖。 |
| 隐私与 PII | P0 明示资料仅存当前浏览器，以及点“AI 整理”后选定内容会送模型处理；仅保存不发模型。示例使用虚构/已脱敏内容，公开截图逐份检查，日志不记录内容或密钥。V1 不承诺自动检测/匿名化所有姓名、学校、链接，不增加未经验证的自动 redaction。 |
| 活动时间 | V1 不增加独立 event_time 顶层键；活动开始、结束、窗口等保存在 time_nodes，按角色展示，不都叫“截止时间”。deadline 保留为提交/完成截止语义，活动开始不自动变成任务截止。 |
| 多时间选主 | 先按明确语义筛选有效提交/完成截止，再在可比较的候选中取最早；superseded、背景日期、补班日、活动开始等不参与截止选主。无有效截止或无法确定角色/比较关系时，deadline 缺席或为空并保留节点，交用户选择。不得靠 label 关键词或任意日期最小值猜业务角色。 |
| 选择节点建任务 | 用户可从节点列表选择一项，明确确认其用于当前任务的截止；一次任务仍只保存一个截止，可从同一资料手动建立多个任务，不自动批量创建。界面必须说明把活动开始用于任务截止是用户选择。 |
| 节点角色表达 | 后续契约显式补节点 role（submission_deadline / event_start / event_end / other / unknown）；模型只输出候选角色，缺失按 unknown，后端不以自由标签替代角色。旧响应无 role 时不能直接推断活动截止；前端保留人工选择入口。 |
| 旧截图相对日期 | captured_at 只表示收集时间，不等于消息发布时间。新增可选 reference_at 及参照来源记录，使用消息中明确的绝对日期依据或用户指定参照；不能静默拿旧截图保存日当可靠消息日期。无可靠参照时相对节点 value=null、unresolved，展示原文；不能补造确定日期。 |
| 相对时间换算 | 追认模型抽取和换算方向；relative/inferred 结果仍待确认，后端校验格式/日历/来源边界。换算不出允许空，不要求为“月底/国庆前”等所有表述硬算出一个值。 |
| 时间精度与时区 | 用户追加定案：产品默认北京时间 UTC+08:00（Asia/Shanghai），不依赖设备时区。date 保留日期，不补 23:59，自北京时间次日开始判逾期；缺时区 datetime 在业务计算中按默认北京时间解释并明示采用默认，原始模型值/时区未知信息保留，不从 captured_at 补偏移。明确其他时区的时刻保留其实际含义，按时间点比较；不同精度不补造时刻。详见默认北京时间规则。 |

只要输出仍依赖模型抽出的节点集合，“同图双跑一致”不能证明整个链路确定性；确定性只保证对**相同结构化输入和比较规则**得到相同选择。

## 6. 版本、公开演示与工程边界

### 版本发布

本轮目标契约统一发布为 **0.3.0**，API 路径版本保留 v1。当前 models.py、schema.json、typedefs.d.ts 仍标 0.2.0，视为待修复的工作树状态，不作为新冻结包发给前端。

由 Qoder 在完成已定规则后统一：更新源版本 → 生成 schema/typedefs → 同步 fixtures 与负向/语义测试 → 核对 healthz/analyze → 更新 HANDOFF → 重建交接包。前端对新版本做真实接收确认。原有本地用户记录需定义兼容读取/显式迁移，不清空数据，不把旧记录静默当作新语义。

### 公网与远端

- **公网演示必须有**：依用户提供的比赛规则截图，作品入口使用 Qoder Sites 的可公开访问地址；不以本地 localhost 或 zip 代替。
- Qoder 承担开发与部署操作。先做实际托管验证，不能假设 Qoder Sites 可直接运行 FastAPI；如不能，前端仍用 Qoder Sites，后端通过 Qoder 部署至可访问的兼容环境，作品站点内连接。
- 新访客无需登录、可用固定演示数据完成核心体验；模型不可用不阻断演示。真实上传与固定示例明确区分。
- 真实模型密钥仅在后端，公开调用需设置体积/并发及费用边界，达到限制时保留仅保存/示例体验。公网正式发布前复核公开文件、数据与调用路径。
- **GitHub 已定**：本次只读验证 origin 为 https://github.com/Xu-Hongwei/jieyixia.git，不再列为待选平台。已有远端不等于当前工作树都已推送；本轮不提交、不推送、不发布。
